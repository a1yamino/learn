协议：Op、Event 与 ResponseItem

pi 用一套自己的消息类型（user/assistant/toolResult）抽象各家 API。Codex 则直接以 OpenAI Responses API 的条目为历史的基本单位：ResponseItem。在它之上，codex-protocol 还定义了前端与内核之间的 Op（31 种操作）和 EventMsg（85 种事件）。本课逐一认识这三类类型，并在线上请求中看到它们的真实 JSON。约 40 分钟。

小结
记住这几点


  1. ResponseItem（protocol/src/models.rs）：#[serde(tag="type", rename_all="snake_case")] 的枚举——Message、Reasoning、FunctionCall/FunctionCallOutput、CustomToolCall/CustomToolCallOutput（自由格式工具，如 apply_patch）、WebSearchCall、Compaction 等。会话历史就是 ResponseItem 列表，原样发回模型。
  2. arguments 是字符串：Responses API 把函数参数作为“包含 JSON 的字符串”返回，Codex 原样保存，到处理工具时才解析。
  3. ContentItem：消息内容——InputText、InputImage、InputAudio、OutputText。
  4. Op（protocol.rs）：Interrupt、TurnInput、ExecApproval、PatchApproval、Compact、Review、Shutdown……前端的一切操作。
  5. Event / EventMsg：Event{id, msg}，id 关联到提交；EventMsg 涵盖错误、警告、turn 开始/结束、消息增量、命令执行开始/输出/结束、审批请求、计划更新、token 计数等。
  6. 对比 pi：pi 的统一消息模型要在各家 API 之间转换（第 5 课）；Codex 以 Responses 为“母语”，Chat Completions 等其他协议则通过适配实现。
