Codex CLI · 第 9 课

shell 与 unified exec

pi 的 bash 工具执行一条命令、等它结束、截断输出尾部。Codex 的 unified exec 更像一个终端复用器：exec_command 在 PTY 中启动进程，最多等待 yield_time_ms；进程还没结束就返回一个 session ID，模型之后可以用 write_stdin 继续输入、读取新输出。于是交互式程序（REPL、提示输入、长时间构建）也能被 agent 驱动。本课在真实 codex 中走一遍：提示输入 → 写入 stdin → 一条十万行的输出被截断。约 45 分钟。

//! Unified Exec: interactive process execution orchestrated with approvals + sandboxing.
//!
//! Responsibilities
//! - Manages interactive processes (create, reuse, buffer output with caps).
//! - Supports completion-only calls that terminate on timeout or cancellation.
//! - Uses the shared ToolOrchestrator to handle approval, sandbox selection, and
//!   retry semantics in a single, descriptive flow.
//! - Spawns the PTY from a sandbox-transformed `ExecRequest`; on sandbox denial,
//!   retries without sandbox when policy allows (no re‑prompt thanks to caching).
//! - Uses the shared `is_likely_sandbox_denied` heuristic to keep denial messages
//!   consistent with other exec paths.
//!
//! Flow at a glance (open process)
//! 1) Build a small request `{ command, cwd }`.
//! 2) Orchestrator: approval (bypass/cache/prompt) → select sandbox → run.
//! 3) Runtime: transform `SandboxTransformRequest` -> `ExecRequest` -> spawn PTY.
//! 4) If denial, orchestrator retries with `SandboxType::None`.
//! 5) Process handle is returned with streaming output + metadata.
//!
//! This keeps policy logic and user interaction centralized while the PTY/process
//! concerns remain isolated here. The implementation is split between:
//! - `process.rs`: PTY process lifecycle + output buffering.
//! - `process_state.rs`: shared exit/failure state for local and remote processes.
//! - `process_manager.rs`: orchestration (approvals, sandboxing, reuse) and request handling.

fn response_header(&self) -> String {
    let mut sections = Vec::new();

    if !self.chunk_id.is_empty() {
        sections.push(format!("Chunk ID: {}", self.chunk_id));
    }

    let wall_time_seconds = self.wall_time.as_secs_f64();
    sections.push(format!("Wall time: {wall_time_seconds:.4} seconds"));

    if let Some(exit_code) = self.exit_code {
        sections.push(format!("Process exited with code {exit_code}"));
    }

    if let Some(process_id) = &self.process_id {
        sections.push(format!("Process running with session ID {process_id}"));
    }

    if let Some(original_token_count) = self.original_token_count {
        sections.push(format!("Original token count: {original_token_count}"));
    }

    sections.push("Output:".to_string());
    sections.join("\n")
}

cat > codex/scratch/s_exec.py <<'EOF'
# 剧本：启动一个等待输入的进程 → 用 write_stdin 交互 → 一条超长输出被截断
import re
def last_output(body):
    return [i for i in body["input"] if i["type"] == "function_call_output"][-1]["output"]
def reply(n, body):
    if n == 1:
        return [call("exec_command", {"cmd": "read -p '名字? ' x; echo 你好, $x", "tty": True, "yield_time_ms": 500}, "c1")]
    if n == 2:
        sid = int(re.search(r"session ID (\d+)", last_output(body)).group(1))
        return [call("write_stdin", {"session_id": sid, "chars": "codex\n", "yield_time_ms": 500}, "c2")]
    if n == 3:
        return [call("exec_command", {"cmd": "seq 1 100000", "max_output_tokens": 200}, "c3")]
    return [msg("完成")]
EOF

挑战
后台进程
让模型启动 python3 -m http.server 8999（yield 1000ms），再用另一个 exec_command 执行 curl -s localhost:8999 | head -3，最后不结束服务器就回答。turn 结束后服务器还在吗？
查看参考答案
第一次调用返回 session ID，服务器在后台运行；第二个命令能拿到目录列表。turn 结束后进程仍在（unified exec 进程属于会话而非 turn），直到会话关闭或被清理——这正是 Op::CleanBackgroundTerminals 与中断提示里“正在运行的 unified exec 进程可能仍在后台运行”的由来。如果实验中启动失败，先检查沙箱：默认的 read-only 沙箱下可改用 --sandbox danger-full-access（仅在临时目录中这样做）。

小结
记住这几点


  1. exec_command：参数 cmd、workdir、shell、login、tty、yield_time_ms、max_output_tokens，以及审批相关的 sandbox_permissions/justification/prefix_rule。yield_time_ms 被限制在 250–30000 ms。
  2. 会话：进程未结束时输出 “Process running with session ID N”；write_stdin{session_id, chars} 向它写入并收集新输出（chars 为空就只是轮询）。最多同时保留 64 个进程。
  3. 输出格式（tools/context.rs）：Chunk ID、Wall time、退出码或 session ID、Original token count，然后是 Output。模型据此判断进程状态。
  4. 截断：超过 max_output_tokens（默认 10000）时保留开头与结尾，中间用省略标记替换，并加上 “Warning: truncated output (original token count: …)” 和总行数。对比 pi 只保留尾部。
  5. 编排（unified_exec/mod.rs 的说明）：构建请求 → 编排器处理审批（跳过/缓存/询问）→ 选择沙箱 → 在 PTY 中运行；若被沙箱拒绝且策略允许，以无沙箱重试（不再询问）。第 11–13 课展开。
  6. 登录 shell：命令通过 /bin/bash -lc 运行；core 中还有 shell 环境快照机制（shell_snapshot.rs）。
