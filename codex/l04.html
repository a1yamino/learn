模型提供方与认证

pi 内置了 40 多家提供方和一千多个模型。Codex 的立场正好相反：源码注释写明“不想裁定哪些第三方提供方应该内置”，因此只内置 OpenAI、Amazon Bedrock 与两个本地开源提供方（Ollama、LM Studio），其余一律由用户在 config.toml 的 model_providers 中声明。本课看提供方结构 ModelProviderInfo、API key 的来源，以及 codex login 如何保存凭据。约 35 分钟。

pub fn built_in_model_providers(
    openai_base_url: Option<String>,
) -> HashMap<String, ModelProviderInfo> {
    use ModelProviderInfo as P;
    let openai_provider = P::create_openai_provider(openai_base_url);
    let amazon_bedrock_provider = P::create_amazon_bedrock_provider(/*aws*/ None);
    let amazon_bedrock_runtime_provider =
        P::create_amazon_bedrock_runtime_provider(/*aws*/ None);

    // We do not want to be in the business of adjucating which third-party
    // providers are bundled with Codex CLI, so we only include the OpenAI and
    // open source ("oss") providers by default. Users are encouraged to add to
    // `model_providers` in config.toml to add their own providers.
    [
        (OPENAI_PROVIDER_ID, openai_provider),
        (AMAZON_BEDROCK_PROVIDER_ID, amazon_bedrock_provider),
        (
            AMAZON_BEDROCK_RUNTIME_PROVIDER_ID,
            amazon_bedrock_runtime_provider,
        ),
        (
            OLLAMA_OSS_PROVIDER_ID,
            create_oss_provider(DEFAULT_OLLAMA_PORT, WireApi::Responses),
        ),
        (
            LMSTUDIO_OSS_PROVIDER_ID,
            create_oss_provider(DEFAULT_LMSTUDIO_PORT, WireApi::Responses),
        ),
    ]
    .into_iter()
    .map(|(k, v)| (k.to_string(), v))
    .collect()
}
从环境变量读 key：
codex-rs/model-provider-info/src/lib.rs  L482–498 ↗
pub fn api_key(&self) -> CodexResult<Option<String>> {
    match &self.env_key {
        Some(env_key) => {
            let api_key = std::env::var(env_key)
                .ok()
                .filter(|v| !v.trim().is_empty())
                .ok_or_else(|| {
                    CodexErr::EnvVar(EnvVarError {
                        var: env_key.clone(),
                        instructions: self.env_key_instructions.clone(),
                    })
                })?;
            Ok(Some(api_key))
        }
        None => Ok(None),
    }
}

cat > codex/scratch/mock.py <<'EOF'
#!/usr/bin/env python3
"""课程练习用的假 Responses API 服务器（离线，无需 API key）。
用法：python3 mock.py <剧本.py> <端口> <日志目录>
剧本里定义 reply(n, body) -> list[dict]：第 n 次请求（从 1 开始）要返回的输出项。
每次请求的完整 JSON 保存为 <日志目录>/reqNN.json，便于查看 Codex 实际发送了什么。"""
import json, sys, os, importlib.util, itertools
sys.dont_write_bytecode = True
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

spec = importlib.util.spec_from_file_location("script", sys.argv[1]); script = importlib.util.module_from_spec(spec); spec.loader.exec_module(script)
PORT, LOG = int(sys.argv[2]), sys.argv[3]; os.makedirs(LOG, exist_ok=True)
counter = itertools.count(1)

def msg(text):  # 便捷构造：助手文本消息
    return {"type": "message", "role": "assistant", "content": [{"type": "output_text", "text": text}]}
def call(name, args, cid=None):  # 便捷构造：函数调用
    return {"type": "function_call", "name": name, "arguments": json.dumps(args, ensure_ascii=False), "call_id": cid or f"call_{name}"}
script.msg, script.call = msg, call

class H(BaseHTTPRequestHandler):
    def log_message(self, *a): pass
    def do_GET(self):
        self.send_response(200); self.send_header("content-type", "application/json"); self.end_headers()
        self.wfile.write(b'{"object":"list","data":[],"models":[]}')
    def do_POST(self):
        body = json.loads(self.rfile.read(int(self.headers.get("content-length", 0))) or b"{}")
        n = next(counter)
        json.dump({"path": self.path, "headers": dict(self.headers), "body": body}, open(f"{LOG}/req{n:02d}.json", "w"), ensure_ascii=False, indent=1)
        items = script.reply(n, body)
        self.send_response(200); self.send_header("content-type", "text/event-stream"); self.end_headers()
        def ev(d): self.wfile.write(f"event: {d['type']}\ndata: {json.dumps(d, ensure_ascii=False)}\n\n".encode())
        rid = f"resp_{n}"
        ev({"type": "response.created", "response": {"id": rid}})
        for i, it in enumerate(items):
            it = {"id": f"item_{n}_{i}", **it}
            if it["type"] == "message":
                ev({"type": "response.output_item.added", "output_index": i, "item": {**it, "content": []}})
                ev({"type": "response.output_text.delta", "output_index": i, "item_id": it["id"], "delta": it["content"][0]["text"]})
            ev({"type": "response.output_item.done", "output_index": i, "item": it})
        ev({"type": "response.completed", "response": {"id": rid, "usage": {"input_tokens": 1000 * n, "input_tokens_details": {"cached_tokens": 0},
            "output_tokens": 50, "output_tokens_details": {"reasoning_tokens": 0}, "total_tokens": 1000 * n + 50}}})

ThreadingHTTPServer(("127.0.0.1", PORT), H).serve_forever()
EOF

#!/bin/bash
# run.sh <剧本.py> [codex 参数...]：启动假模型，用临时 CODEX_HOME 运行 codex exec

SCRIPT=$(realpath "$1"); shift
export CODEX_HOME=${CODEX_HOME:-$(mktemp -d)}; mkdir -p $CODEX_HOME; LOG=$CODEX_HOME/requests
PORT=$((20000 + RANDOM % 20000))
python3 "$(dirname "$0")/mock.py" "$SCRIPT" $PORT "$LOG" & MOCK=$!
trap "kill $MOCK 2>/dev/null" EXIT
cat > $CODEX_HOME/config.toml <<TOML
model = "$MODEL"
model_provider = "mock"
$EXTRA_CONFIG
[model_providers.mock]
$EXTRA_PROVIDER
name = "Mock"
base_url = "http://127.0.0.1:$PORT/v1"
wire_api = "responses"
request_max_retries = 0
stream_max_retries = 0
TOML
sleep 0.5
codex exec --skip-git-repo-check "$@" </dev/null
EOF

小结
记住这几点


  1. ModelProviderInfo：base_url、env_key（从哪个环境变量读 key）、wire_api（协议，默认 responses）、http_headers/env_http_headers、query_params、重试与超时（request_max_retries、stream_max_retries、stream_idle_timeout_ms）、requires_openai_auth、supports_websockets 等。
  2. 内置提供方：built_in_model_providers() 只有 openai、amazon-bedrock（两种）、ollama、lmstudio；用户配置的提供方与之合并，内置的一般不可覆盖（Bedrock 例外）。
  3. env_key：api_key() 读取环境变量，为空就报 Missing environment variable，并附上 env_key_instructions。
  4. OpenAI 认证：codex login 支持 ChatGPT 账号登录（OAuth）或 API key；凭据写在 $CODEX_HOME/auth.json（或系统钥匙串，取决于 cli_auth_credentials_store）。
  5. 请求头：authorization: Bearer …、originator（codex_exec / codex_cli_rs …）、session-id、带操作系统与终端信息的 user-agent。
  6. 模型元数据：模型能力（工具、shell 类型、apply_patch 类型、上下文窗口）来自 models-manager/models.json 或远程目录；未知模型使用回退元数据（第 1 课的警告）。
