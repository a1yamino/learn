一次 turn 的生命周期

在 pi 里，一次对话是 session.prompt() 触发的 agent 循环。Codex 的结构多了一层“队列”：前端把 Op（操作）提交到会话的提交队列，会话的 submission_loop 逐个处理，把一次用户输入变成一个 turn 任务；任务里的 run_turn 反复请求模型、执行工具，期间通过事件队列把 Event 发回前端。本课跟踪一次真实的 turn：从 exec 的 JSONL 事件，到假服务器收到的两次请求。约 40 分钟。

#[serde(tag = "type")]
pub enum ThreadEvent {
    /// Emitted when a new thread is started as the first event.
    #[serde(rename = "thread.started")]
    ThreadStarted(ThreadStartedEvent),
    /// Emitted when a turn is started by sending a new prompt to the model.
    /// A turn encompasses all events that happen while agent is processing the prompt.
    #[serde(rename = "turn.started")]
    TurnStarted(TurnStartedEvent),
    /// Emitted when a turn is completed. Typically right after the assistant's response.
    #[serde(rename = "turn.completed")]
    TurnCompleted(TurnCompletedEvent),
    /// Indicates that a turn failed with an error.
    #[serde(rename = "turn.failed")]
    TurnFailed(TurnFailedEvent),
    /// Emitted when a new item is added to the thread. Typically the item will be in an "in progress" state.
    #[serde(rename = "item.started")]
    ItemStarted(ItemStartedEvent),
    /// Emitted when an item is updated.
    #[serde(rename = "item.updated")]
    ItemUpdated(ItemUpdatedEvent),
    /// Signals that an item has reached a terminal state—either success or failure.
    #[serde(rename = "item.completed")]
    ItemCompleted(ItemCompletedEvent),
    /// Represents an unrecoverable error emitted directly by the event stream.
    #[serde(rename = "error")]
    Error(ThreadErrorEvent),

#!/usr/bin/env python3
"""show.py <requests 目录>：概览每次请求的 input 条目（类型/角色/摘要）与工具列表"""
import json, sys, glob
for f in sorted(glob.glob(sys.argv[1] + "/req*.json")):
    b = json.load(open(f))["body"]
    print(f"== {f.split('/')[-1]}  工具 {len(b.get('tools', []))} 个，input {len(b['input'])} 条")
    for it in b["input"]:
        t = it.get("type"); role = it.get("role", "")
        if t == "message":
            text = " ".join(c.get("text", "") for c in it["content"])
        elif t == "function_call":
            text = f"{it['name']}({it['arguments']})"
        elif t in ("function_call_output", "custom_tool_call_output"):
            o = it["output"]; text = o if isinstance(o, str) else json.dumps(o, ensure_ascii=False)
        elif t == "custom_tool_call":
            text = f"{it['name']}: {it['input']}"
        else:
            text = json.dumps(it, ensure_ascii=False)
        print(f"  {t:22} {role:9} {text.replace(chr(10), ' ⏎ ')[:int(sys.argv[2]) if len(sys.argv) > 2 else 70]}")
EOF

两轮工具调用
修改剧本：第 1 次请求调用 exec_command 执行 ls，第 2 次再执行 pwd，第 3 次回答。预测 exec --json 会输出几个 item.completed，req03 的 input 有几条。
查看参考答案
def reply(n, body):
    if n == 1: return [call("exec_command", {"cmd": "ls"}, "c1")]
    if n == 2: return [call("exec_command", {"cmd": "pwd"}, "c2")]
    return [msg("完成")]
三个 item.completed（两个 command_execution、一个 agent_message），仍然只有一个 turn。req03 的 input 是 4 条初始消息 + 2 对（function_call, function_call_output）= 8 条。注意 call_id 要不同，否则两次输出会对应到同一个调用。

小结
记住这几点


  1. SQ/EQ 模型：前端（tui、exec、app-server）只和会话交换两种消息——提交 Submission{id, op}，接收 Event{id, msg}。这让同一个内核可以服务多个前端。
  2. submission_loop（session/handlers.rs）：tokio::select! 等待关闭信号、新的提交或邮箱更新；Op::TurnInput 交给 turn_input::handle，它要么启动新 turn，要么把输入排进正在运行的 turn（转向，第 8 课）。
  3. 任务：turn 以 SessionTask 形式运行（tasks/regular.rs 调用 run_turn）；压缩、评审、用户 shell 命令也是任务。
  4. 一个 turn 内多次请求：第一次请求模型返回 exec_command 调用；codex 执行后，把 function_call 与 function_call_output 追加进历史，再发第二次请求，直到模型不再调用工具。
  5. exec 的 JSONL 事件：thread.started → turn.started → item.started/completed（命令执行、助手消息、文件修改……）→ turn.completed（附 token 用量）。这是内核事件的简化投影，定义在 exec/src/exec_events.rs。
  6. 请求里没有 instructions 字段：系统提示作为第一条 developer 消息发送，后面是技能说明、环境上下文（cwd、shell……）和用户消息。
