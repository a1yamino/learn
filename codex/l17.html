MCP：接入外部工具服务器

pi 刻意不内置 MCP，而是让扩展自己注册工具（第 15 课）。Codex 内置 MCP 客户端：在 config.toml 的 [mcp_servers.名字] 中配置一个 stdio 或 HTTP 服务器，Codex 启动它、执行 tools/list，把工具以 mcp__名字 命名空间暴露给模型，并在调用前按工具注解与配置决定是否需要审批。本课写一个 30 行的 MCP 服务器，亲手触发这三条分支。（注：在固定的这个提交中，codex 没有 mcp-server 子命令；把 Codex 嵌入其他程序走 app-server，见第 23 课。）约 40 分钟。

fn requires_mcp_tool_approval(annotations: Option<&ToolAnnotations>) -> bool {
    let destructive_hint = annotations.and_then(|annotations| annotations.destructive_hint);
    if destructive_hint == Some(true) {
        return true;
    }

    let read_only_hint = annotations
        .and_then(|annotations| annotations.read_only_hint)
        .unwrap_or(false);
    if read_only_hint {
        return false;
    }

    destructive_hint.unwrap_or(true)
        || annotations
            .and_then(|annotations| annotations.open_world_hint)
            .unwrap_or(true)
}

fn requires_mcp_tool_approval_for_mode(
    annotations: Option<&ToolAnnotations>,
    approval_mode: AppToolApproval,
) -> bool {
    match approval_mode {
        AppToolApproval::Auto => requires_mcp_tool_approval(annotations),
        AppToolApproval::Prompt => true,
        AppToolApproval::Writes => !annotations
            .and_then(|annotations| annotations.read_only_hint)
            .unwrap_or(false),
        AppToolApproval::Approve => false,
    }
}

cat > codex/scratch/mini_mcp.py <<'EOF'
# 最小的 stdio MCP 服务端：一个 add 工具（JSON-RPC，每行一条消息）
import json, os, sys
READONLY = "--readonly" in sys.argv  # 是否声明 readOnlyHint
def send(o): sys.stdout.write(json.dumps(o) + "\n"); sys.stdout.flush()
for line in sys.stdin:
    m = json.loads(line); mid = m.get("id"); meth = m.get("method")
    if meth == "initialize":
        send({"jsonrpc": "2.0", "id": mid, "result": {"protocolVersion": m["params"]["protocolVersion"],
              "capabilities": {"tools": {}}, "serverInfo": {"name": "mini", "version": "0.1"}}})
    elif meth == "tools/list":
        send({"jsonrpc": "2.0", "id": mid, "result": {"tools": [{"name": "add", "description": "两数相加",
              "inputSchema": {"type": "object", "properties": {"a": {"type": "number"}, "b": {"type": "number"}}, "required": ["a", "b"]},
              **({"annotations": {"readOnlyHint": True}} if READONLY else {})}]}})
    elif meth == "tools/call":
        a = m["params"]["arguments"]; print(f"[mini] add{a}", file=sys.stderr)
        send({"jsonrpc": "2.0", "id": mid, "result": {"content": [{"type": "text", "text": str(a["a"] + a["b"])}]}})
    elif mid is not None:
        send({"jsonrpc": "2.0", "id": mid, "result": {}})
EOF

不在了。gpt-5.5 的 supports_search_tool 为真，MCP 工具变为 Deferred：工具列表中多了 {"type":"tool_search","execution":"client",…}，其描述写着可搜索的来源（“- mini”）。模型需要先发出 tool_search_call（参数 query），Codex 在本地用 BM25 搜索延迟加载的工具元数据，把匹配的工具放进 tool_search_output，下一次请求中模型才能调用 add。工具很多时，这能显著缩短每次请求的工具列表。

小结
记住这几点


  1. 配置：[mcp_servers.mini] command/args/env（stdio）或 url（streamable HTTP）。codex mcp list/get/add/remove/login 管理它们。
  2. 环境变量白名单：stdio 服务器只继承 HOME/LOGNAME/PATH/SHELL/USER… 等默认变量（rmcp-client/src/utils.rs 的 DEFAULT_ENV_VARS），其余要在 env 或 env_vars 中显式给出——作者第一次用环境变量传参时就因此失败。
  3. 暴露方式（mcp_tool_exposure.rs）：模型的 supports_search_tool 为真（如 gpt-5.5）时，MCP 工具是 Deferred：请求里只有一个 tool_search，模型先搜索再加载；否则 Direct：作为 {"type":"namespace","name":"mcp__mini","tools":[…]} 直接给出。模型调用时带上 namespace 字段。
  4. 审批判定（mcp_tool_call.rs）：approval_mode 为 approve → 不问；prompt → 总是问；writes → 非只读就问；auto（默认）→ destructiveHint=true 要问，readOnlyHint=true 不问，否则看 destructive/openWorld（缺省都视为 true）——即未注解的工具默认需要审批。
  5. never 策略：需要审批而 approval_policy=never 时直接拒绝（“MCP tool call requires approval, but approval policy is never”），结果作为工具输出返回给模型。
  6. 事件：exec 的 JSONL 中是 mcp_tool_call 条目，带 server/tool/arguments/result/error/status。
