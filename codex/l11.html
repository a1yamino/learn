沙箱：macOS Seatbelt

pi 第 19 课的结论是：pi 不内置沙箱，安全来自容器或扩展。Codex 则把操作系统沙箱做进内核——模型发出的每条命令，默认都在沙箱中运行。在 macOS 上，它使用系统自带的 /usr/bin/sandbox-exec（Seatbelt），把一段 SBPL 策略与参数交给它。本课阅读这些策略：从 (deny default) 开始，逐项放开进程、sysctl、读文件，再按配置放开可写根目录与网络。约 40 分钟。

找出放开网络的条件
在 seatbelt.rs 中查找 MACOS_SEATBELT_NETWORK_POLICY 被追加到策略的条件，并说明 [sandbox_workspace_write] network_access = true 如何影响它。
查看参考答案
用 rg -n "NETWORK_POLICY|network_sandbox_policy" codex/codex-rs/sandboxing/src/seatbelt.rs 查找。网络沙箱策略（NetworkSandboxPolicy）为启用时追加网络策略段；配置中的 network_access 正是决定 workspace-write 模式下该策略取值的开关。此外 Codex 还有托管网络代理（network-proxy crate），可按域名放行；它与沙箱策略的组合方式见 dynamic_network_policy。

小结
记住这几点


  1. 只信任 /usr/bin/sandbox-exec：不在 PATH 中查找，防止攻击者注入假的 sandbox-exec（MACOS_PATH_TO_SEATBELT_EXECUTABLE）。
  2. 默认拒绝：seatbelt_base_policy.sbpl（116 行，参考 Chrome 渲染进程策略）第一条就是 (deny default)，然后允许 fork/exec、同沙箱内的信号、必要的 sysctl、伪终端等。
  3. 可写根目录参数化：build_seatbelt_access_policy 为每个可写根生成 (subpath (param "WRITABLE_ROOT_0"))，实际路径通过 -DWRITABLE_ROOT_0=/path 传入，避免把路径拼进策略文本带来的转义问题。最终命令：sandbox-exec -p <策略> -D… -- 命令。
  4. 可写根之下的保护：即使在可写目录中，顶层的 .git、.agents、.codex、.aws 仍受保护（PROTECTED_METADATA_PATH_NAMES）；可写根目录本身也不能被删除替换（“authority boundary”）。
  5. 网络：默认不放开；启用网络时追加 seatbelt_network_policy.sbpl（system-socket、相关 mach-lookup 等），还可以配合 Codex 的网络代理做按域名控制。
  6. 沙箱模式：read-only（默认）、workspace-write（工作目录与临时目录可写）、danger-full-access（不加沙箱）。第 13 课把它们与审批策略结合起来。
