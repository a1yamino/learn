Codex CLI · 第 21 课

hooks、技能与插件

pi 只有一种扩展：TypeScript 扩展，在进程内注册工具、命令与事件钩子（第 15 课）。Codex 把扩展拆成三种进程外、以文件声明的机制：hooks——在 14 个生命周期事件上运行外部命令，可以拦截工具调用；技能——一个目录加一个 SKILL.md，只把名称与描述放进开发者消息，正文由模型按需读取；插件——把技能、hooks、MCP 服务器打成一个可从市场安装的包。本课用一个 Python 钩子拦截 rm，再放一个仓库级技能，看它出现在请求中。约 45 分钟。

在你的电脑上练习
练习使用第 1 课的 mock.py（假的 Responses API 服务器）和 run.sh（以临时 CODEX_HOME 启动它并运行 codex exec）。剧本文件定义 reply(n, body)，返回第 n 次请求的输出项；每次请求的完整 JSON 保存在 $CODEX_HOME/requests/。


01
钩子脚本。
cat > codex/scratch/guard.py <<'EOF'
# PreToolUse 钩子：stdin 收到事件 JSON；命令中含 rm 就以退出码 2 阻止（原因写到 stderr）
import json, sys
e = json.load(sys.stdin)
cmd = json.dumps(e.get("tool_input"), ensure_ascii=False)
print(f"[hook] {e['hook_event_name']} tool_name={e['tool_name']} input={cmd}", file=open("/tmp/hook.log", "a"))
if "rm " in cmd:
    print("禁止删除文件：请改用 git rm 并说明理由", file=sys.stderr); sys.exit(2)
EOF
02
剧本：先 echo 再 rm。
cat > codex/scratch/s_hook.py <<'EOF'
# 剧本：先 echo，再 rm；把每次的工具输出报告出来
def reply(n, body):
    outs = [i["output"] for i in body["input"] if i.get("type") == "function_call_output"]
    if n > 1: print(f"[mock] 工具输出：{str(outs[-1])[:80]!r}", flush=True)
    if n == 1: return [call("exec_command", {"cmd": "echo hi"}, "c1")]
    if n == 2: return [call("exec_command", {"cmd": "rm -rf data"}, "c2")]
    return [msg("好的")]
EOF
03
三个实验。
cat > codex/scratch/l21.sh <<'EOF'
#!/bin/bash
# 两种扩展点：PreToolUse 钩子（拦截工具调用）与技能（SKILL.md 进入开发者消息）
S=$(pwd); export CODEX_HOME=$(mktemp -d); R=$(mktemp -d); cd $R; git init -q; mkdir data; rm -f /tmp/hook.log
cat > $CODEX_HOME/hooks.json <<JSON
{"hooks": {"PreToolUse": [{"matcher": ".*", "hooks": [{"type": "command", "command": "python3 $S/guard.py"}]}]}}
JSON
mkdir -p .agents/skills/commit-msg
cat > .agents/skills/commit-msg/SKILL.md <<'MD'
---
name: commit-msg
description: 按团队规范写提交信息（类型: 摘要），在用户要求提交时使用
---
1. 运行 git diff --staged 查看改动
2. 第一行格式：feat|fix|docs: 不超过 50 字的摘要
MD
echo "== 1. 未信任的钩子：不运行"
bash $S/run.sh $S/s_hook.py "清理" 2>/dev/null >/dev/null; echo "   hook.log：$(cat /tmp/hook.log 2>/dev/null || echo 无)"
echo "== 2. --dangerously-bypass-hook-trust：钩子运行"
bash $S/run.sh $S/s_hook.py --dangerously-bypass-hook-trust "清理" 2>/dev/null | grep '^\[mock\]'
cat /tmp/hook.log; echo "   data 目录还在吗：$(ls -d data 2>/dev/null || echo 不在)"
echo "== 3. 技能出现在第 2 条 developer 消息中（根目录表 + 条目）"
python3 - $CODEX_HOME/requests/req01.json <<'PY'
import json, sys; t = json.load(open(sys.argv[1]))["body"]["input"][1]["content"][0]["text"]
print("\n".join("   " + l for l in t.splitlines() if "commit-msg" in l or l.startswith("- `r")))
PY
EOF

挑战
用 JSON 而不是退出码
把 guard.py 改为退出码 0，并在 stdout 输出 Claude Code 风格的 JSON 决定：{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…"}}。效果相同吗？去 hooks/src/engine/output_parser.rs 找到解析它的函数。
查看参考答案
效果相同：退出码 0 时，pre_tool_use.rs 调用 output_parser::parse_pre_tool_use(&run_result.stdout)，解析出的 block_reason 与退出码 2 + stderr 走同一条阻止路径；格式不合法时得到 invalid_reason，作为一条错误条目显示而不阻止。JSON 方式的好处是可以同时返回 systemMessage（显示给用户）与 additionalContext（追加给模型）等字段。

小结
记住这几点


  1. 事件（protocol.rs 的 HookEventName）：PreToolUse、PermissionRequest、PostToolUse、Pre/PostCompact、SessionStart/End、UserPromptSubmit、SubagentStart/Stop、Stop、Interrupt、Pre/PostModelRequest。处理器类型：command、mcp_tool、prompt、agent。
  2. 声明位置（hooks/src/engine/discovery.rs）：每个配置层目录下的 hooks.json，或 config.toml 中的同构配置；插件包中的 hooks/hooks.json。两者规范化后计算同一个哈希作为信任身份。
  3. 信任：钩子会在你的机器上执行任意命令，所以未经信任（未记录其哈希）的钩子不运行——实验 1 中 hook.log 为空。交互界面中可审阅并信任；实验用 --dangerously-bypass-hook-trust 跳过。
  4. 协议（与 Claude Code 风格兼容）：stdin 收到事件 JSON（hook_event_name、tool_name、tool_input…；shell 工具的名字是 Bash）；退出码 0 时可在 stdout 返回 JSON 控制结果；PreToolUse 以退出码 2 阻止调用，stderr 作为原因，模型收到 “Command blocked by PreToolUse hook: 原因”。
  5. 技能：根目录按层收集（ext/skills/src/host_roots.rs）：仓库内从项目根到 cwd 的 .agents/skills、~/.agents/skills、旧位置 $CODEX_HOME/skills、系统缓存 skills/.system、管理员目录。开发者消息中给出根目录表 r0/r1/r2… 和每个技能的“名称: 描述 (file: rN/…/SKILL.md)”——渐进披露，正文不预先加载。
  6. 插件：codex plugin add/list/remove/marketplace；插件钩子的信任还绑定插件内容哈希（plugin_fingerprint.rs），内容变了需要重新信任。
