查看参考答案
是 cli-model。profile 只是叠加在 User 层上（ConfigLayerSource::User { profile }），而 -c 属于更高的 SessionFlags 层。在 l22.sh 最后加一行 ask --profile fast -c model=cli-model 即可验证。

小结
记住这几点


  1. 启动握手（实测原始字节）：开启括号粘贴 ESC[?2004h、键盘增强 ESC[>7u、焦点事件 ESC[?1004h；查询光标位置 ESC[6n、前景/背景色 OSC 10/11 ?（用于选择主题）、键盘协议 ESC[?u、设备属性 ESC[c。终端窗口大小为 0 时什么也不画——这是作者写 tui.py 时踩到的坑。
  2. 画面：进入备用屏幕 ESC[?1049h（tui.rs 中 alt_screen_enabled 可关闭），开启鼠标上报，每帧用同步更新 ESC[?2026h … ESC[?2026l 包裹，避免闪烁。
  3. 配置层（config/src/config_layer_source.rs）：PackagedDefaults、MDM、System、EnterpriseManaged、User（$CODEX_HOME/config.toml，可叠加 profile）、Project（.codex/）、SessionFlags（-c 与命令行参数）以及旧的托管配置。高优先级覆盖低优先级：实验中 -c > 项目 > 用户。
  4. 项目层需要信任：.codex/config.toml 只在项目 trust_level = "trusted" 时生效（实验 2 与 3 的差别）——仓库里的配置可以改模型、provider、沙箱，不能让克隆下来的仓库自动生效。
  5. profile 新写法：--profile fast 读取 $CODEX_HOME/fast.config.toml；config.toml 中旧的 [profiles.fast] 表会让加载直接报错并给出迁移提示（config/src/loader/mod.rs）。
  6. 特性开关：codex features list 列出每个特性的阶段（under development / experimental / stable / removed）与是否开启；--enable/--disable 或 [features] 表修改。
