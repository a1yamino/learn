会话线程、中断与转向

pi 的 Agent 类有两个队列：steer（在当前工具调用后插入）与 follow-up（等 agent 空闲后再处理）。Codex 的对应物是线程（thread）与它的输入队列：当一个 turn 正在运行时提交新输入，会话不会开新 turn，而是把它“转向”进当前 turn；中断则取消正在执行的工具，并在历史里留下明确的痕迹，告诉模型“用户是故意打断的”。本课用一个约 60 行的 app-server 客户端，在真实 codex 中演示转向与中断。约 45 分钟。

cat > codex/scratch/apc.py <<'EOF'
#!/usr/bin/env python3
"""apc.py：极简 app-server 客户端（JSON-RPC over stdio，每行一条 JSON）。
用法：在课程脚本中 from apc import AppServer"""
import json, subprocess, threading, queue, os, sys, time

class AppServer:
    def __init__(self, args=(), cwd=None, env=None):
        self.p = subprocess.Popen(["codex", "app-server", *args], stdin=subprocess.PIPE, stdout=subprocess.PIPE,
                                  stderr=subprocess.DEVNULL, text=True, cwd=cwd, env=env, bufsize=1)
        self.next_id, self.pending, self.events = 1, {}, queue.Queue()
        self.on_request = None  # 服务器发来的请求（如审批）的处理函数：(method, params) -> result
        threading.Thread(target=self._reader, daemon=True).start()

    def _reader(self):
        for line in self.p.stdout:
            m = json.loads(line)
            if "id" in m and "method" in m:          # 服务器 → 客户端的请求
                result = self.on_request(m["method"], m["params"]) if self.on_request else {}
                self._send({"id": m["id"], "result": result})
            elif "id" in m:                          # 对我们请求的响应
                self.pending.pop(m["id"]).put(m)
            else:                                    # 通知
                self.events.put(m)

    def _send(self, m):
        self.p.stdin.write(json.dumps(m, ensure_ascii=False) + "\n"); self.p.stdin.flush()

    def request(self, method, params):
        i = self.next_id; self.next_id += 1; q = queue.Queue(); self.pending[i] = q
        self._send({"id": i, "method": method, "params": params})
        m = q.get(timeout=60)
        if "error" in m: raise RuntimeError(f"{method}: {m['error']}")
        return m["result"]

    def notify(self, method, params=None):
        self._send({"method": method, **({"params": params} if params is not None else {})})

    def wait(self, method, timeout=60, show=None):
        """等待某个通知；show(m) 用于打印途中的通知"""
        end = time.time() + timeout
        while True:
            m = self.events.get(timeout=max(0.1, end - time.time()))
            if show: show(m)
            if m["method"] == method: return m["params"]

    def start(self, cwd):
        self.request("initialize", {"clientInfo": {"name": "course", "title": None, "version": "0"}})
        self.notify("initialized")
        return self.request("thread/start", {"cwd": cwd})["thread"]["id"]

    def close(self):
        self.p.stdin.close(); self.p.wait(timeout=10)

def text(t): return [{"type": "text", "text": t, "text_elements": []}]
EOF

# 转向与中断：用 app-server 在 turn 运行中插话、再中断另一个 turn
import os, sys, time, json; sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from apc import AppServer, text
a = AppServer(cwd=os.getcwd()); tid = a.start(os.getcwd())
def show(m):
    p = m.get("params", {}); it = p.get("item", {})
    if m["method"] in ("turn/started", "turn/completed"):
        print(f"  {m['method']:16} status={p['turn']['status']}")
    elif m["method"] == "item/completed" and it.get("type") in ("commandExecution", "agentMessage", "userMessage"):
        desc = it.get("text") or it.get("command") or json.dumps(it.get("content"), ensure_ascii=False)[:60]
        print(f"  item/completed   {it['type']}: {desc}")

print("== 1. 转向：慢命令运行时插入一句话")
turn = a.request("turn/start", {"threadId": tid, "input": text("第一个任务")})["turn"]["id"]
time.sleep(0.8)
r = a.request("turn/steer", {"threadId": tid, "input": text("顺便也看看 README"), "expectedTurnId": turn})
print("  turn/steer 返回同一个 turn：", r["turnId"] == turn)
a.wait("turn/completed", show=show)

print("== 2. 中断：慢命令运行时取消 turn")
turn = a.request("turn/start", {"threadId": tid, "input": text("第二个任务")})["turn"]["id"]
time.sleep(0.8)
a.request("turn/interrupt", {"threadId": tid, "turnId": turn})
a.wait("turn/completed", show=show)
print("== 3. 中断之后再发一条消息")
a.request("turn/start", {"threadId": tid, "input": text("第三个任务")})
a.wait("turn/completed", show=show)
a.close()
EOF

小结
记住这几点


  1. 线程：一个线程 = 一段可恢复的对话（有 id、历史、设置）；ThreadManager 管理多个线程，app-server 的 thread/start、thread/resume、thread/fork 操作它们。
  2. 开始还是转向（session/turn_input.rs）：这是内核里“唯一决定”输入去向的地方——有活动 turn 就调用 steer_input 排进去（返回 Steered，带同一个 turn id），否则启动新 turn（Started）。只有用户输入或独立的函数输出才能开始或转向。
  3. 转向何时生效：run_turn 每一圈开头取出排队输入（第 6 课）。实验中“顺便也看看 README”出现在 req02 的 function_call_output 之后——慢命令执行完、下一次请求之前。
  4. expectedTurnId：turn/steer 必须带上期望的活动 turn id，不匹配就失败，避免把话插进错误的 turn。
  5. 中断：Op::Interrupt（app-server 的 turn/interrupt）取消 turn；正在运行的工具得到输出 “Wall time: 0.7 seconds⏎aborted by user”，turn 状态为 interrupted。下一次请求还会附上一条 <turn_aborted> 用户消息：“用户是故意中断的……被中止的命令可能已部分执行”。
  6. 对比 pi：pi 的 abort 只是停止；Codex 把中断写进历史，让模型下一轮知道发生了什么。
