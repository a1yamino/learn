/plan 与 update_plan

Codex 里有两个都叫“plan”、却完全不同的东西。/plan 切换到 Plan 协作模式：换一段开发者指令（plan.md，128 行），让模型只探索、提问，最后输出一个 <proposed_plan> 块，客户端把它渲染成计划条目。update_plan 是一个 TODO 清单工具：模型调用它，客户端收到 turn/plan/updated 并显示进度。pi 刻意不内置计划模式（第 19 课）。本课用 app-server 在同一线程中分别以两种模式各跑一个回合。约 45 分钟。

fn apply_plan_slash_command(&mut self) -> bool {
    if !self.collaboration_modes_enabled() {
        self.add_info_message(
            "Collaboration modes are disabled.".to_string(),
            Some("Enable collaboration modes to use /plan.".to_string()),
        );
        return false;
    }
    if let Some(mask) = collaboration_modes::plan_mask(self.model_catalog.as_ref()) {
        self.set_collaboration_mask_from_user_action(mask);
        true
    } else {
        self.add_info_message(
            "Plan mode unavailable right now.".to_string(),
            /*hint*/ None,
        );
        false
    }
}

Plan Mode is a collaboration mode that can involve requesting user input and eventually issuing a `<proposed_plan>` block.

Separately, `update_plan` is a checklist/progress/TODOs tool; it does not enter or exit Plan Mode. Do not confuse it with Plan mode or try to use it while in Plan mode. If you try to use `update_plan` in Plan mode, it will return an error.

## Execution vs. mutation in Plan Mode

You may explore and execute **non-mutating** actions that improve the plan. You must not perform **mutating** actions.
  // …
When you present the official plan, wrap it in a `<proposed_plan>` block so the client can render it specially:

1) The opening tag must be on its own line.
2) Start the plan content on the next line (no text on the same line as the tag).
3) The closing tag must be on its own line.
4) Use Markdown inside the block.
5) Keep the tags exactly as `<proposed_plan>` and `</proposed_plan>` (do not translate or rename them), even if the plan content is in another language.

Example:

<proposed_plan>
plan content
</proposed_plan>

小结
记住这几点


  1. update_plan 默认关闭：config/mod.rs 的 resolve_update_plan_enabled 读 [tools.update_plan] enabled，缺省为 false。打开后处理器（tools/handlers/plan.rs）解析参数，发出 EventMsg::PlanUpdate，返回 “Plan updated”。app-server 把它转成 turn/plan/updated（状态 inProgress 等为驼峰式）。
  2. Plan 模式拒绝 update_plan：同一处理器在 turn.mode() == ModeKind::Plan 时返回错误 “update_plan is a TODO/checklist tool and is not allowed in Plan mode”，作为工具输出交给模型；plan.md 第 15 行也预先告诉模型这一点。
  3. /plan 的实现：slash_dispatch.rs 的 apply_plan_slash_command：协作模式未启用时提示 “Collaboration modes are disabled.”；否则取 collaboration_modes::plan_mask 并 set_collaboration_mask_from_user_action。之后每个回合的 collaborationMode 都是 plan。
  4. 指令从哪来：prompts/src/model_messages/collaboration.rs：模型目录若带有 collaboration_mode_messages 就用它，否则用内置 PLAN/DEFAULT 模板；context/world_state/collaboration_mode.rs 按 ModeKind 选择并放入 developer 消息。
  5. <proposed_plan>：session/turn.rs 用 extract_proposed_plan_text 从助手文本中取出计划，发出 plan 条目（及 item/plan/delta）；strip_proposed_plan_blocks 把它从普通消息文本中去掉。实验中 Plan 回合只得到一个 plan 条目。
  6. “不修改”靠提示：plan.md 要求只做非修改性操作；在核心代码中，Plan 模式的分支只出现在 update_plan 拒绝、request_user_input 变为阻塞、计划块解析等少数几处，并没有为它换一个更严的沙箱。
