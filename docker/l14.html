挑战

只用 runc 运行一个容器

不经过 Docker 和 containerd：准备一个 OCI bundle（alpine 的 rootfs + runc 生成的 config.json），把要运行的命令改成 echo hello from runc，用 runc 直接运行。

查看参考答案
mkdir -p /tmp/bundle/rootfs && cd /tmp/bundle
docker export $(docker create alpine:3.20) | tar -x -C rootfs
runc spec          # 生成默认的 config.json
sed -i 's/"terminal": true/"terminal": false/; s/"sh"/"echo","hello from runc"/' config.json
sudo runc run demo
hello from runc

config.json 里有你在前几课见过的一切：namespaces 列表、linux.resources（cgroups）、mounts、process.capabilities。Docker 做的就是根据镜像配置和你的参数生成这个文件。

小结

记住这几点

  1. 调用链：docker CLI → dockerd（REST API，/var/run/docker.sock）→ containerd（gRPC）→ containerd-shim-runc-v2 → runc。
  2. runc 是 OCI 运行时：读取一个 bundle（config.json + rootfs），调用 namespace、cgroups 等系统调用创建容器进程，然后退出。
  3. shim 留下来做容器进程的父进程：保持 stdio、收集退出码。所以 dockerd 和 containerd 可以重启而不影响运行中的容器（dockerd 需要开启 live-restore）。
  4. Kubernetes 通过 CRI 直接调用 containerd，不经过 dockerd。镜像和容器格式都是 OCI 标准，所以 Docker 构建的镜像在 Kubernetes 里照常运行。
  5. 能访问 docker.sock 就等于拥有宿主机的 root 权限。不要把它挂进不受信任的容器。
