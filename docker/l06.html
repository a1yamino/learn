05

冷备份：先正常停止 PostgreSQL，并确认它已退出；再用临时容器只读挂载卷和当前目录打包。没有业务写入，也不能保证运行中的数据库文件一致。

docker stop -t 60 pg
docker inspect -f "{{.State.Status}} {{.State.ExitCode}}" pg
# 确认 exited 0 后再备份；若超时被强制杀死，先排查并完成正常关闭
docker run --rm -v pgdata:/data:ro -v "$PWD":/backup alpine \
  tar czf /backup/pgdata.tgz -C /data .
ls -lh pgdata.tgz
-rw-r--r--  1 you  staff   6.4M Oct 21 18:10 pgdata.tgz

docker run -d --name web -p 8080:80 -v "$PWD/site":/usr/share/nginx/html:ro nginx:1.27

恢复到一个新卷

用上面的 pgdata.tgz，恢复到一个名为 pgdata2 的新卷，并用新卷启动 PostgreSQL，证明表 t 里有 hello。

查看参考答案
docker volume create pgdata2
docker run --rm -v pgdata2:/data -v "$PWD":/backup alpine \
  sh -c "cd /data && tar xzf /backup/pgdata.tgz"
docker run -d --name pg2 -e POSTGRES_PASSWORD=dev -v pgdata2:/var/lib/postgresql/data postgres:16
sleep 5; docker exec pg2 psql -U postgres -tc "SELECT x FROM t"
 hello

注意：本练习先正常停止数据库，再完整打包数据目录；恢复使用相同主版本 PostgreSQL 16。仅停止业务写入并不等于停止数据库后台写入。需要在线备份时使用 pg_dump 或配置正确的 pg_basebackup，并验证恢复结果。

小结

记住这几点

  1. 容器的可写层随容器删除。需要保留的数据（数据库、上传文件）要放在挂载点上。
  2. 命名卷由 Docker 管理，适合生产数据；绑定挂载把宿主机目录映射进去，适合开发时同步代码；tmpfs 在内存里，容器停止即消失。
  3. 挂载会遮住容器里同一路径原有的文件。空的命名卷第一次挂载时，Docker 会先把镜像里的内容复制进卷；绑定挂载不会。
  4. 推荐 --mount type=volume,src=...,dst=... 写法，比 -v 更明确；绑定挂载的路径不存在时 --mount 会报错，-v 会悄悄建一个空目录。
  5. 备份卷前先满足应用的一致性条件：本课正常停止 PostgreSQL 后，再用临时容器挂载卷并用 tar 打包。在线数据库备份使用数据库专用工具。
