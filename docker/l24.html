跨主机网络：overlay 与 Swarm 简介

一台机器装不下时：多台主机上的容器怎么互相访问、服务怎么分布和扩缩容、滚动更新怎么做。Swarm 是 Docker 内置的编排，也是理解 Kubernetes 的铺垫。约 45 分钟。

初始化单节点 Swarm。

docker swarm init 2>&1 | head -1

02

创建 overlay 网络和服务。

docker network create -d overlay --attachable appnet
docker service create --name web --replicas 3 --network appnet -p 8080:80 nginx:alpine

verify: Service web converged

挑战

用 stack 部署并自动回滚

写一个 Compose 文件：web（nginx:alpine，3 副本，健康检查用 wget -qO- localhost），更新策略为每次 1 个、失败自动回滚。部署后把镜像改成一个启动就退出的版本（如 command: ["sh","-c","exit 1"]）再部署，观察自动回滚。

查看参考答案
docker swarm init
cat > stack.yaml <<'EOF'
services:
  web:
    image: nginx:alpine
    ports: ["8080:80"]
    healthcheck:
      test: ["CMD", "wget", "-qO-", "localhost"]
      interval: 3s
      retries: 2
    deploy:
      replicas: 3
      update_config:
        parallelism: 1
        delay: 3s
        failure_action: rollback
        monitor: 10s
EOF
docker stack deploy -c stack.yaml demo
# 在 web 下加一行 command: ["sh","-c","exit 1"]，再部署
docker stack deploy -c stack.yaml demo
sleep 40; docker service inspect demo_web -f "{{.UpdateStatus.State}}"
rollback_completed

新任务启动失败，在 monitor 时间内被判定为失败，Swarm 按 failure_action: rollback 恢复到上一版本。期间另外两个旧副本一直在服务，网站没有中断。

小结

记住这几点

  1. bridge 网络只在一台主机内。overlay 网络用 VXLAN 把容器的二层帧封装进主机之间的 UDP 包（端口 4789），让不同主机上的容器在同一个虚拟网络里。
  2. Swarm：docker swarm init 成为 manager，其他机器 join。manager 用 Raft 保存集群状态，必须保留严格多数。N 个 manager 最多容忍 floor((N−1)/2) 个故障；4 个也能容忍 1 个，但与 3 个相比没有多容忍故障，因此通常选 3 或 5 个。
  3. service 是期望状态（镜像、副本数、网络），Swarm 把它拆成 task 调度到节点上，并持续把实际状态拉回期望状态。
  4. 服务名解析到一个虚拟 IP（VIP），负载均衡到所有副本。routing mesh：发布的端口在每个节点上都能访问。
  5. 滚动更新：--update-parallelism、--update-delay、--update-failure-action rollback。
  6. docker stack deploy -c compose.yaml 用 Compose 文件部署到 Swarm。更大规模、更丰富的生态请看 Kubernetes 课程。
