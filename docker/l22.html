在你的电脑上练习

亲手制造几种常见故障，再按顺序找出原因。
01

故障一：容器立刻退出。

docker run -d --name f1 alpine echo hi
docker ps -a --filter name=f1 --format "{{.Status}}"
Exited (0) 2 seconds ago
02

退出码 0：主进程正常结束了。容器只在主进程运行期间存在（第 2 课）。看日志确认。

docker logs f1; docker rm f1
hi
03

故障二：命令写错。

docker run --name f2 alpine pyhton; echo exit=$?; docker rm f2
docker: Error response from daemon: … exec: "pyhton": executable file not found in $PATH
exit=127
04

故障三：服务只监听 127.0.0.1，映射了端口却访问不到。

docker run -d --name f3 -p 8000:8000 python:3.12-slim python -m http.server 8000 --bind 127.0.0.1
sleep 2; curl -s -m 2 localhost:8000 || echo fail
docker exec f3 python -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:8000').status)"
fail
200
05

容器里能访问，外面不能：监听地址的问题。改成 0.0.0.0。

docker rm -f f3
docker run -d --name f3 -p 8000:8000 python:3.12-slim python -m http.server 8000 --bind 0.0.0.0
sleep 2; curl -s -o /dev/null -w "%{http_code}\n" localhost:8000; docker rm -f f3
200
06

用事件还原经过。--until 固定结束时间，使事件流退出，tail 才能打印最后几条；Docker 只保留最近 256 条事件，长期审计需额外收集。

docker events --since 5m --until "$(date +%s)" --filter type=container --format "{{.Time}} {{.Action}} {{.Actor.Attributes.name}}" | tail -4
1729507801 start f3
1729507804 kill f3
1729507804 die f3
1729507804 destroy f3
挑战

调试 distroless 容器

运行 docker run -d --name app -p 8080:8080 gcr.io/distroless/python3 -c "import http.server as h;h.HTTPServer(('',8080),h.SimpleHTTPRequestHandler).serve_forever()"。docker exec app sh 会失败。不修改这个容器，查看它的进程列表、监听端口，并在它的网络里访问自己。

查看参考答案
docker exec app sh            # exec: "sh": executable file not found
docker run --rm -it --pid container:app --network container:app nicolaka/netshoot
# 在 netshoot 里：
ps aux
ss -lntp
curl -s -o /dev/null -w "%{http_code}\n" localhost:8080
PID   USER     COMMAND
    1 root     /usr/bin/python3.11 -c import http.server …
LISTEN 0 5  0.0.0.0:8080  0.0.0.0:*  users:(("python3.11",pid=1))
200

工具容器加入目标的 PID 和网络命名空间（第 11 课），看到的是同一组进程和同一个 localhost，但文件系统是自己的。要看目标的文件，访问 /proc/1/root/。Docker Desktop 用户也可以直接 docker debug app。

小结

记住这几点

  1. 固定顺序：状态（ps -a、退出码）→ 日志（logs）→ 配置（inspect）→ 资源（stats、cgroup）→ 进入现场（exec、debug、nsenter）。
  2. 退出码：0 正常退出（主进程结束了）；1 应用报错；126/127 命令无法执行或找不到；137 被 SIGKILL（OOM 或 docker kill）；143 被 SIGTERM。
  3. docker events 记录 die、oom、health_status 等事件，用来还原“刚才发生了什么”。
  4. 精简镜像没有 shell：用 docker debug，或者启动一个工具容器共享目标的网络/PID 命名空间：--network container:X --pid container:X。
  5. 容器内网络问题按层查：DNS（getent hosts）→ 端口是否监听（ss -lnt）→ 监听地址是不是 127.0.0.1 → 防火墙/端口映射。
  6. 磁盘：docker system df，常见原因是不轮转的日志、悬空镜像、构建缓存、写进可写层的数据。
