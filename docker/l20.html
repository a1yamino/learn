在你的电脑上练习

用 Trivy（通过容器运行，不用安装）和 Docker 内置的工具。
01

扫描一个旧镜像，只看高危和严重。

docker run --rm aquasec/trivy:latest image --severity HIGH,CRITICAL --quiet python:3.9 | grep Total
Total: 187 (HIGH: 172, CRITICAL: 15)
（数字随漏洞库更新变化）
02

换成 slim 版本对比。

docker run --rm aquasec/trivy:latest image --severity HIGH,CRITICAL --quiet python:3.12-slim | grep Total
Total: 3 (HIGH: 3, CRITICAL: 0)
03

只显示有修复版本的漏洞。

docker run --rm aquasec/trivy:latest image --severity HIGH,CRITICAL --ignore-unfixed --quiet python:3.12-slim | grep Total
Total: 0 (HIGH: 0, CRITICAL: 0)
04

生成 SBOM（SPDX 格式），统计组件数量。

docker run --rm aquasec/trivy:latest image --format spdx-json --quiet python:3.12-slim > sbom.json
python3 -c "import json;print(len(json.load(open('sbom.json'))['packages']))"
112
05

在 SBOM 里查某个组件。

python3 - <<'PY'
import json
with open('sbom.json') as f:
    packages = json.load(f)['packages']
for package in packages:
    if package['name'].startswith('openssl'):
        print(package['name'], package.get('versionInfo', '未提供'))
PY
openssl 3.0.15-1~deb12u1
06

CI 用法：有可修复的高危漏洞时退出码非 0。

docker run --rm aquasec/trivy:latest image --severity CRITICAL --ignore-unfixed --exit-code 1 --quiet python:3.12-slim; echo exit=$?
exit=0
挑战

签名并验证

用第 10 课的本地仓库（localhost:5000）。下方 cosign 容器使用 host 网络访问它：需要 Linux Docker Engine，或 Docker Desktop 4.34 及以上并启用 Enable host networking。推送一个镜像，用 cosign 生成密钥对并按 digest 签名，然后验证。再推送一个同名但内容不同的镜像，验证它会失败。

查看参考答案
docker run -d -p 5000:5000 --name registry registry:2
docker pull alpine:3.20
docker tag alpine:3.20 localhost:5000/demo:1 && docker push localhost:5000/demo:1
DIGEST=$(docker buildx imagetools inspect localhost:5000/demo:1 --format '{{.Manifest.Digest}}')
D="localhost:5000/demo@$DIGEST"
alias cosign='docker run --rm --network host -v "$PWD":/w -w /w -e COSIGN_PASSWORD= gcr.io/projectsigstore/cosign:v2.4.1'
cosign generate-key-pair
cosign sign --key cosign.key --tlog-upload=false -y $D
cosign verify --key cosign.pub --insecure-ignore-tlog $D
Verification for localhost:5000/demo@sha256:… --
The following checks were performed on each of these signatures:
  - The signatures were verified against the specified public key
docker pull busybox:1.36
docker tag busybox:1.36 localhost:5000/demo:1 && docker push localhost:5000/demo:1
cosign verify --key cosign.pub --insecure-ignore-tlog localhost:5000/demo:1
Error: no matching signatures

签名绑定的是 digest，不是标签。标签被改指向新内容后，签名不再匹配。cosign.key 是私钥，不要提交到 git；CI 里可以用无密钥签名（OIDC + 公共透明日志）。本地仓库没有接入透明日志，所以用 --tlog-upload=false。

小结

记住这几点

  1. 漏洞扫描把镜像里每个软件包的版本和漏洞库对比。大多数漏洞来自基础镜像，换更小、更新的基础镜像收益最大。
  2. 看结果时关注：严重程度、是否有修复版本、是否真的被用到。没有修复版本的低危漏洞，通常记录下来而不是阻塞发布。
  3. SBOM（软件物料清单）记录镜像的所有组件。新漏洞公布时，查 SBOM 就知道哪些镜像受影响，不用重新扫描所有镜像。
  4. docker buildx build --sbom=true --provenance=mode=max 把 SBOM 和构建来源证明一起附加到镜像上。
  5. 签名（cosign）证明镜像来自你，且推送后没被改过。部署时按 digest 拉取并验证签名。
  6. 在 CI 里：构建 → 扫描（高危且可修复则失败）→ 生成 SBOM 并推送 → 对推送得到的 digest 签名 → 验证后部署。
