动手：最小 capabilities

一个 Web 服务，以 root 启动，需要绑定 80 端口，然后切换到 nginx 用户。从 --cap-drop ALL 开始，只加回必需的项。本模拟明确设定 net.ipv4.ip_unprivileged_port_start=1024；Docker 通常将其设为 0，此时绑定 80 端口不需要 NET_BIND_SERVICE。

在你的电脑上练习

亲手看到每一层限制生效。
01

容器里的 root 默认拥有哪些 capabilities？

docker run --rm alpine sh -c "apk add -q libcap; capsh --print | grep Current"
Current: cap_chown,cap_dac_override,cap_fowner,cap_fsetid,cap_kill,cap_setgid,cap_setuid,cap_setpcap,cap_net_bind_service,cap_net_raw,cap_sys_chroot,cap_mknod,cap_audit_write,cap_setfcap=ep
02

删除全部后，root 连改文件属主都不行。

docker run --rm --cap-drop ALL alpine chown nobody /etc/hosts
chown: /etc/hosts: Operation not permitted
03

NET_RAW 允许原始套接字，但现代 Linux 的 ping 也可使用无特权 ICMP socket。为观察权限拒绝，先在这个容器里禁止 ping socket，再移除 NET_RAW。

docker run --rm --cap-drop NET_RAW --sysctl "net.ipv4.ping_group_range=1 0" alpine ping -c1 127.0.0.1
ping: permission denied (are you root?)
04

seccomp 拦截 unshare 等系统调用（即使是 root）。

docker run --rm alpine unshare --user --map-root-user id
unshare: unshare(0x10000000): Operation not permitted
05

只读根文件系统，只给 /tmp 可写。

docker run --rm --read-only --tmpfs /tmp alpine sh -c "touch /x; touch /tmp/y && echo tmp ok"
touch: /x: Read-only file system
tmp ok
06

检查 Docker 是否运行在 rootless 模式。

docker info -f "{{.SecurityOptions}}"
[name=seccomp,profile=builtin name=cgroupns]
（rootless 模式下还会出现 name=rootless）
挑战

加固 nginx

让官方 nginx:alpine 在以下限制下仍能正常提供服务：删除所有 capabilities 只加回必需的、根文件系统只读、禁止提权、内存 64M、最多 100 个进程。用 curl 验证返回 200。

查看参考答案
docker run -d --name hard -p 8080:80 \
  --sysctl net.ipv4.ip_unprivileged_port_start=1024 \
  --cap-drop ALL --cap-add CHOWN --cap-add SETUID --cap-add SETGID --cap-add NET_BIND_SERVICE \
  --read-only --tmpfs /var/cache/nginx --tmpfs /var/run --tmpfs /tmp \
  --security-opt no-new-privileges \
  --memory 64m --pids-limit 100 nginx:alpine
curl -s -o /dev/null -w "%{http_code}\n" localhost:8080
200

主进程以 root 绑定 80 端口（NET_BIND_SERVICE），创建缓存目录时改属主（CHOWN），再把 worker 切换到 nginx 用户（SETUID/SETGID）。nginx 要写 /var/cache/nginx 和 /var/run/nginx.pid，所以给它们 tmpfs。更进一步：改用 nginxinc/nginx-unprivileged，监听 8080，以非 root 运行，就连这四项都不需要。启动失败时用 docker logs hard 查看缺了什么。

小结

记住这几点

  1. 容器里的 root 默认就是宿主机的 uid 0，只是被 namespace、capabilities、seccomp 等限制住。任何一层被突破，后果就严重。
  2. 第一道防线：镜像里用 USER 以非 root 运行（第 5 课）。
  3. Capabilities 把 root 权力拆成约 40 项。Docker 默认保留 14 项。最稳妥：--cap-drop ALL，再按需 --cap-add。
  4. seccomp 过滤系统调用，默认配置阻止约 40 多个危险调用（如 mount、kexec_load）。不要随手 --privileged 或 seccomp=unconfined。
  5. --security-opt no-new-privileges 阻止 setuid 程序提权；--read-only + --tmpfs 让根文件系统不可写。
  6. userns-remap 和 rootless 模式：容器里的 root 映射成宿主机上的普通用户，降低越界访问时的权限，但不能保证抵御内核提权漏洞。
