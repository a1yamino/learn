在你的电脑上练习

准备一个最小的 Python 项目，亲手验证缓存。时间会因网络和机器而不同。
01

新建目录和三个文件。

mkdir cache-demo && cd cache-demo
echo "requests==2.32.3" > requirements.txt
echo 'print("v1")' > app.py
cat > Dockerfile <<'EOF'
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "app.py"]
EOF
02

第一次构建。所有步骤都要执行，pip install 最慢。

docker build -t cache-demo .
[+] Building 21.4s (10/10) FINISHED
 => [2/5] WORKDIR /app
 => [3/5] COPY requirements.txt .
 => [4/5] RUN pip install --no-cache-dir -r requirements.txt   14.2s
 => [5/5] COPY . .
 => naming to docker.io/library/cache-demo
03

什么都不改，再构建一次。全部命中缓存。

docker build -t cache-demo .
[+] Building 0.6s (10/10) FINISHED
 => CACHED [2/5] WORKDIR /app
 => CACHED [3/5] COPY requirements.txt .

只改代码，再构建。只有最后一个 COPY 重新执行。

echo 'print("v2")' > app.py

挑战

让缓存失效的隐藏原因

在 cache-demo 目录里执行 mkdir .git && date > .git/HEAD（模拟一次 git 提交），不改任何代码，再构建。你会发现 COPY . . 重新执行了。找出原因，并用一个文件修复它。

查看参考答案

原因：COPY . . 会把整个构建上下文复制进去，包括 .git。.git 变了，这一层的内容就变了，缓存失效。

printf ".git\n__pycache__\n*.pyc\n.env\n" > .dockerignore
docker build -t cache-demo .
date > .git/HEAD
docker build -t cache-demo .
 => CACHED [5/5] COPY . .

.dockerignore 里的文件不会发送给构建器。.env 这类密钥文件也应该放进去。

小结

记住这几点

  1. Dockerfile 从上到下执行。RUN、COPY、ADD 生成新的文件层；CMD、ENV、EXPOSE 等只修改镜像配置。
  2. 构建时，每条指令先查缓存：指令文本相同、COPY 的文件内容相同，且上一层命中缓存，就直接复用。
  3. 某一层缓存失效后，它下面的所有层都要重新构建。
  4. 把变化少的放前面、变化多的放后面：先复制依赖清单并安装依赖，最后再复制源代码。
  5. 用 .dockerignore 排除 .git、node_modules、密钥等文件，构建更快，也避免把敏感文件打进镜像。
