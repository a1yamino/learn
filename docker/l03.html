01 Dockerfile = 镜像的“菜谱”

第 1 课说过，镜像由多个只读层叠成。那这些层从哪来？答案：Dockerfile 里的每条（会改文件系统的）指令，就生成一层。它就像一份可重复执行的部署文档——不再是“README 第 7 步：手动装 libpq”。

📄 Dockerfile
文本配方，进 Git 管理
⚙️ docker build
按配方一步步执行，每步产出一层
🧱 镜像
层的堆叠 + 元数据（启动命令、端口…）

一个典型的 Node API：

FROM node:20-slim                 # 基础镜像：别人做好的层
WORKDIR /app                      # 之后的命令都在 /app 下执行
COPY package*.json ./             # 先只复制依赖清单
RUN npm ci --omit=dev             # 安装依赖（慢！）
COPY . .                          # 再复制源代码
ENV NODE_ENV=production
EXPOSE 3000                       # 文档性质：声明端口
CMD ["node", "server.js"]         # 容器启动时运行的主进程




02 核心指令卡片


FROM image:tag
选基础镜像，必须是第一条。尽量写明确版本，别用 latest。


WORKDIR /app
设置工作目录（不存在会自动创建）。别用 RUN cd——每条 RUN 是独立的 shell。


COPY src dest
把构建上下文里的文件复制进镜像。文件内容变了，这层缓存就失效。


RUN 命令
构建时执行命令（装依赖、编译），结果固化成一层。


ENV K=V
环境变量，构建和运行时都可见。


ARG K
仅构建时的变量，--build-arg 传入（第 9 课细讲）。


EXPOSE 3000
只是“声明”，不会真的开放端口——真正映射要 -p（第 7 课）。


CMD / ENTRYPOINT
容器启动时的默认命令，见第 5 节。


USER node
以非 root 用户运行（安全，第 12 课）。


只有 RUN、COPY、ADD 会产生有内容的文件系统层；ENV、CMD、EXPOSE 等只改元数据。

04 🧪 层缓存实验室（本课核心）


缓存规则只有一条：从上往下逐层检查，如果“指令相同且输入文件没变”就复用（CACHED）；一旦某层失效，它下面所有层都必须重建。

05 CMD vs ENTRYPOINT，shell vs exec 形式


CMDENTRYPOINT


作用默认命令/参数固定的可执行程序


docker run img xxxxxx 替换整个 CMDxxx 作为参数追加


典型用途后端服务：CMD ["node","server.js"]CLI 工具镜像：ENTRYPOINT ["curl"]


试一试：镜像里写了下面的配置，你运行不同命令，实际执行的是什么？






务必用 exec 形式（JSON 数组）：CMD ["node","server.js"]。shell 形式 CMD node server.js 会变成 /bin/sh -c "node server.js"，PID 1 是 sh，docker stop 发的 SIGTERM 传不到 Node → 等满 10 秒被强杀（还记得第 2 课的坑吗？）。



06 构建上下文与 .dockerignore


docker build . 末尾的 . 是“构建上下文”：这个目录下的所有文件会先打包发给 Docker 引擎。COPY . . 也会把它们全拷进去——包括 node_modules、.git、甚至 .env 里的密码！

⚠️ 新手常见坑


COPY . . 放在 npm install 前面：每改一行代码都重装依赖。依赖清单先 COPY，代码后 COPY。


RUN apt-get update 和 apt-get install 分两行：update 那层被缓存后，install 可能用到过期的索引。写在一条 RUN 里：RUN apt-get update && apt-get install -y libpq5 && rm -rf /var/lib/apt/lists/*


以为后面的 RUN rm 能让镜像变小：上一层的文件已经固化，后面删只是“遮住”，体积不变。要在同一条 RUN里装完就清（第 5 课多阶段构建更彻底）。


把本地 node_modules 拷进镜像：可能含 macOS 编译的二进制，在 Linux 容器里直接崩。用 .dockerignore 排除。


RUN cd /app：不会影响下一条指令，用 WORKDIR。

📝 本课小结
    

  • Dockerfile 每条 RUN/COPY/ADD → 一层只读层；docker build -t 名:标签 . 构建。
    • 

  • 缓存：逐层比对“指令 + 输入”，某层失效 → 之后全部重建。
    • 

  • 黄金顺序：变化少的放上面（基础镜像 → 系统依赖 → 依赖清单 + 安装 → 源代码）。
    • 

  • 用 exec 形式的 CMD；CMD 可被覆盖，ENTRYPOINT 是固定程序。
    • 

  • .dockerignore 排除 node_modules、.git、.env，减小上下文、避免泄密。
