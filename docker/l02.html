04 运行中的容器：logs 和 exec

📜 docker logs api

看主进程写到 stdout/stderr 的内容。所以应用要把日志打到标准输出，而不是容器里的文件！常用：-f 实时跟随，--tail 100，--since 10m。

🚪 docker exec -it api sh

在已运行的容器里额外启动一个进程（这里是 shell）。退出 shell 不会停止容器，因为主进程不是它。

对比一下 exec 和 attach：

docker exec -it c shdocker attach c
做什么新开一个进程连接到主进程的输入输出
Ctrl+C / exit只结束那个 shell ✅可能直接杀掉主进程 ⚠️
推荐度⭐⭐⭐ 日常排查首选⭐ 很少用

    06 命令速查表

    命令作用状态变化
    docker run [opts] IMG [CMD]创建并启动∅ → Running
    docker create只创建不启动∅ → Created
    docker start / stop启动 / 优雅停止（SIGTERM，10 秒后 SIGKILL）Exited ⇄ Running
    docker restartstop + startRunning → Running
    docker kill立即 SIGKILLRunning → Exited
    docker pause / unpause冻结进程（cgroups freezer）Running ⇄ Paused
    docker rm [-f]删除容器（-f 强制删运行中的）Exited → Removed
    docker ps [-a]列出运行中 / 全部容器—
    docker logs [-f]看 stdout/stderr—
    docker exec -it C sh在容器里开新进程—
    docker container prune清理所有已停止容器Exited → Removed

    💡 容器 ID 可以只写前几位：docker stop 3f2a。给容器起名（--name）会让一切更好管理。

    ⚠️ 新手常见坑

    “我的容器一启动就退出了！” docker run ubuntu 的主进程是 bash，没有终端输入就立刻结束 → 容器 Exited。容器不是虚拟机，没有长期运行的主进程，它就不会“开着”。用 docker logs 和 docker ps -a 的退出码排查。
    名字冲突： Conflict. The container name "/api" is already in use——旧的同名容器虽然停了但还在。先 docker rm api，或者开发时用 --rm。
    stop 要等 10 秒？ 说明你的应用没处理 SIGTERM（或者用 shell 形式启动导致信号传不到）。Node/Python 服务要监听 SIGTERM 做优雅关闭（第 12 课细讲）。
    在容器里改了代码/装了包，重启后还在，但 rm 后就没了。 永远不要把容器当“手工维护的服务器”——要改就改 Dockerfile 重新构建（第 3 课）。
    退出码速记： 0 正常 · 1 应用报错 · 137 被 SIGKILL（常见：内存超限 OOM）· 143 被 SIGTERM。

    ✅ 自测 4 题

    📝 本课小结

    • 状态机：Created → Running ⇄ Paused → Exited → Removed。
    • 容器活多久 = 主进程活多久。
    • run = pull + create + start；服务用 -d，交互用 -it，临时用 --rm。
    • 日志打到 stdout，用 docker logs -f 看；排查用 docker exec -it c sh。
    • stop 是优雅停止（SIGTERM→SIGKILL），kill 是立即杀。
