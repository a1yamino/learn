在你的电脑上练习

01

新建项目。

mkdir cfg-demo && cd cfg-demo
echo "TAG=3.20" > .env
echo "LEVEL=from-env-file" > app.env
echo "s3cr3t" > db_password.txt
cat > compose.yaml <<'EOF'
services:
  app:
    image: alpine:${TAG}
    env_file: app.env
    environment:
      MODE: dev
    secrets:
      - db_password
    command: ["sh", "-c", "echo MODE=$$MODE LEVEL=$$LEVEL; cat /run/secrets/db_password"]
secrets:
  db_password:
    file: ./db_password.txt
EOF
02

查看 Compose 替换后的配置。${TAG} 已经换成 3.20。

docker compose config | grep image
    image: alpine:3.20
03

运行。env_file、environment 和 secret 都生效了。

docker compose run --rm app
MODE=dev LEVEL=from-env-file
s3cr3t
04

命令行覆盖 environment。

docker compose run --rm -e MODE=prod app
MODE=prod LEVEL=from-env-file
s3cr3t
05

.env 里的变量不会自动进入容器。

docker compose run --rm app sh -c 'echo "TAG=[$TAG]"'
TAG=[]
06

secret 是文件，不是环境变量，inspect 看不到它的内容。

docker compose run -d --name cfg app sleep 60
docker inspect -f "{{json .Config.Env}}" cfg
["MODE=dev","LEVEL=from-env-file","PATH=/usr/local/sbin:…"]
07

清理。

docker rm -f cfg; docker compose down
cfg
挑战

构建时用密钥，但不留在镜像里

构建时需要一个私有包仓库的 token（假设为文件 token.txt）。写一个 Dockerfile，在 RUN 里读取它，并用 docker history 和导出镜像文件两种方法证明 token 不在镜像里。

查看参考答案
cat > Dockerfile <<'EOF'
# syntax=docker/dockerfile:1
FROM alpine:3.20
RUN --mount=type=secret,id=token \
    echo "using token of length $(wc -c < /run/secrets/token)"
EOF
echo mytoken123 > token.txt
docker build --secret id=token,src=token.txt --progress=plain -t sec-demo . 2>&1 | grep "using token"
docker history --no-trunc sec-demo | grep -c mytoken123
docker save sec-demo | tar -xO 2>/dev/null | grep -ac mytoken123
#5 0.21 using token of length 11
0
0

secret 只在这条 RUN 执行期间挂载在 /run/secrets/token，不写入任何层，也不进入构建缓存的键。第 17 课会结合 SSH 挂载和缓存挂载深入讲。

小结

记住这几点

  1. 镜像不包含环境相关的配置。配置在运行时注入：-e、--env-file、Compose 的 environment / env_file。
  2. Compose 中的优先级（高到低）：docker compose run -e → environment → env_file → Dockerfile 的 ENV。
  3. 项目目录下的 .env 用于 compose.yaml 里的 ${变量} 替换，不会自动进入容器。用 docker compose config 查看替换结果。
  4. 镜像里的一切都能被读出来：ENV、ARG、复制进去的文件，即使后面的层删除了。
  5. 运行时密钥用 Compose / Swarm 的 secrets（挂载为 /run/secrets/名字 文件）；构建时密钥用 BuildKit 的 --mount=type=secret。
