在你的电脑上练习

亲手触发 OOM 和 CPU 节流。
01

在 64 MB 限制下分配 100 MB 内存。

docker run --name oom --memory 64m --memory-swap 64m python:3.12-slim python -c "b=bytearray(100*1024*1024)"; echo exit=$?
exit=137
02

确认是 OOM。

docker inspect oom -f "{{.State.OOMKilled}} {{.State.ExitCode}}"; docker rm oom
true 137
03

限制 0.5 核，跑满 CPU。

docker run -d --name burn --cpus 0.5 alpine sh -c "while :; do :; done"
sleep 5; docker stats --no-stream --format "{{.CPUPerc}}" burn
50.12%
04

查看节流统计（cgroup v2）。

docker exec burn cat /sys/fs/cgroup/cpu.stat | grep throttled
nr_throttled 49
throttled_usec 2463120
05

调整正在运行的容器的限制。

docker update --cpus 1 burn && sleep 3 && docker stats --no-stream --format "{{.CPUPerc}}" burn; docker rm -f burn
burn
99.87%
06

限制日志大小。

docker run -d --name logs --log-driver local --log-opt max-size=1m alpine sh -c "while :; do echo spam; done"
sleep 5; docker inspect logs -f "{{.HostConfig.LogConfig}}"; docker rm -f logs
{local map[max-size:1m]}
挑战

找到合适的内存限制

运行 docker run -d --name app --memory 256m --memory-swap 256m python:3.12-slim python -c "import time;b=[];[b.append(bytearray(10*1024*1024)) or time.sleep(0.2) for _ in range(30)];time.sleep(600)"。它会逐步分配到约 300 MB。观察它被杀，找到峰值，给出一个带余量的限制并验证它稳定运行。

查看参考答案
docker inspect app -f "{{.State.OOMKilled}}"     # true
docker rm app
docker run -d --name app --memory 1g python:3.12-slim python -c "import time;b=[];[b.append(bytearray(10*1024*1024)) or time.sleep(0.2) for _ in range(30)];time.sleep(600)"
sleep 10; docker exec app cat /sys/fs/cgroup/memory.peak
true
323244032

先给一个宽松的上限，读 memory.peak（约 308 MB）得到真实峰值，再加 25% 左右的余量：docker update --memory 400m --memory-swap 400m app。Linux 上 docker stats 的 MEM USAGE 会扣除一部分缓存（cgroup v2 中为 inactive_file），与 memory.current / memory.peak 口径不同。应同时观察 cgroup 总用量、峰值和应用指标，不能把 stats 的数字当成完整峰值。生产里峰值要来自真实负载测试，而不是一次运行。

小结

记住这几点

  1. 内存达到上限会触发回收；有可用 swap 时还可能换出匿名页。回收仍不足才可能触发 OOM；本课禁止 swap，主进程被杀后退出为 137、OOMKilled=true。限制要高于峰值，并让应用知道自己的上限（如 JVM -XX:MaxRAMPercentage）。
  2. --cpus 是配额：用完本周期（100ms）的额度就被节流，延迟突增但不会被杀。看 cpu.stat 里的 nr_throttled。
  3. --cpu-shares 只在争抢时按比例分配；--cpuset-cpus 绑定具体核心，适合延迟敏感的服务。
  4. 频繁写入的数据放卷里，不要写容器可写层（第 16 课）。日志用 local 驱动或设置 max-size，否则 json-file 会占满磁盘。
  5. 需要极致网络性能时可用 --network host 跳过 NAT 和 veth，代价是失去隔离。
  6. 先测量再调：docker stats、cgroup 文件、应用自身指标。
