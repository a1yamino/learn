在你的电脑上练习

从零写一个 FastAPI 服务并容器化。
01

新建项目和代码。

mkdir api-demo && cd api-demo
cat > main.py <<'EOF'
import os
from fastapi import FastAPI
app = FastAPI()

@app.get("/health")
def health():
    return {"ok": True, "user": os.getenv("USER") or os.getuid()}
EOF
echo -e "fastapi==0.115.0\nuvicorn==0.30.6" > requirements.txt
printf ".git\n__pycache__\n.env\n" > .dockerignore
02

写 Dockerfile。

cat > Dockerfile <<'EOF'
FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
RUN useradd --create-home --uid 10001 app
USER app
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
EOF

05

确认 PID 1 是 uvicorn，而不是 sh。

docker exec api cat /proc/1/cmdline | tr "\0" " "; echo
/usr/local/bin/python /usr/local/bin/uvicorn main:app --host 0.0.0.0 --port 8000
06

计时停止。应用收到 SIGTERM 立刻退出，不到 1 秒。

time docker stop api
api

07

对比：改成 shell 形式再试一次。sh 不转发信号，要等满 10 秒被 SIGKILL。

docker rm api
sed -i.bak 's|^CMD .*|CMD uvicorn main:app --host 0.0.0.0 --port 8000|' Dockerfile
docker build -t api-demo:shell . && docker run -d --name api -p 8000:8000 api-demo:shell
time docker stop api
api
real    0m10.4s
08

恢复 exec 形式并清理。

mv Dockerfile.bak Dockerfile; docker rm api

挑战

加上健康检查

让 docker ps 的 STATUS 显示 (healthy)。提示：slim 镜像里没有 curl，用 Python 自己发请求。

查看参考答案
cat >> Dockerfile <<'EOF'
HEALTHCHECK --interval=10s --timeout=3s --retries=3 \
  CMD python -c "import urllib.request,sys; sys.exit(0 if urllib.request.urlopen('http://127.0.0.1:8000/health').status==200 else 1)"
EOF
docker build -t api-demo:1.1 . && docker run -d --name api -p 8000:8000 api-demo:1.1
sleep 15; docker ps --format "{{.Names}} {{.Status}}"
api Up 15 seconds (healthy)

健康检查在容器内部执行，所以访问 127.0.0.1 就可以。连续失败 3 次后状态变为 unhealthy。Compose 的 depends_on: condition: service_healthy 可以在启动依赖服务时等待健康检查，但普通 Docker / Compose 不会仅因 unhealthy 自动重启容器，restart 策略针对的是进程退出。Swarm 可以替换不健康的任务；Kubernetes 使用自己配置的探针，不读取镜像的 HEALTHCHECK。

小结

记住这几点

  1. 容器里的服务要监听 0.0.0.0。监听 127.0.0.1 时，只有容器自己能访问。
  2. -p 宿主机端口:容器端口 才真正打开访问通道；EXPOSE 只是文档说明。
  3. 用 exec 形式的 CMD ["..."]，让应用自己成为 PID 1，收到 SIGTERM 后优雅退出。shell 形式会让 sh 当 PID 1，信号传不到应用。
  4. 用 USER 切换到非 root 用户运行。容器被攻破时，损失更小。
  5. PYTHONUNBUFFERED=1 让日志立即输出；HEALTHCHECK 让 Docker 知道服务是否真的可用。
