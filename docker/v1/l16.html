在你的电脑上练习

比较写入速度，查看卷的挂载方式，限制日志大小。
01

写容器层：1 万个小文件。

time docker run --rm alpine sh -c 'mkdir /d; for i in $(seq 10000); do echo x > /d/$i; done'
real    0m2.9s
02

写命名卷：同样的操作。

docker volume create fast
time docker run --rm -v fast:/d alpine sh -c 'for i in $(seq 10000); do echo x > /d/$i; done'
real    0m2.7s
03

（Mac / Windows）写绑定挂载：明显更慢。

SLOW_DIR=$(mktemp -d)
time docker run --rm -v "$SLOW_DIR":/d alpine sh -c 'for i in $(seq 10000); do echo x > /d/$i; done'
real    0m9.8s   （Linux 上和前两次接近）
04

看卷在容器里是怎样挂载的：一个普通的块设备目录，不是 overlay。

docker run --rm -v fast:/d alpine sh -c "grep -E ' / | /d ' /proc/mounts"
overlay / overlay rw,relatime,lowerdir=…
/dev/vda1 /d ext4 rw,relatime 0 0

挑战

找出并限制失控的日志

运行一个疯狂打日志的容器：docker run -d --name noisy alpine sh -c "while :; do echo spam spam spam; done"。一分钟后，在不进入容器的情况下找出它的日志文件和大小。然后重新创建它，让日志最多占用 30 MB。

查看参考答案
docker inspect -f "{{.LogPath}}" noisy
sudo ls -lh $(docker inspect -f "{{.LogPath}}" noisy)   # Linux
docker rm -f noisy
docker run -d --name noisy --log-opt max-size=10m --log-opt max-file=3 alpine \
  sh -c "while :; do echo spam spam spam; done"
/var/lib/docker/containers/9c1e…/9c1e…-json.log
-rw-r----- 1 root root 1.3G Oct 21 18:45 …-json.log

一分钟 1.3 GB。max-size=10m, max-file=3 最多保留 3 个 10 MB 的文件。全局默认值写在 /etc/docker/daemon.json：{"log-driver":"local","log-opts":{"max-size":"10m"}}（local 驱动自带压缩和轮转），只对之后新建的容器生效。Mac / Windows 上日志在虚拟机里，不能直接在桌面系统访问 LogPath。docker system df -v 的容器大小不包含日志，不可据此判断日志占用；可在 Linux 实验机执行上面的文件大小检查。在 Desktop 上仍可用 inspect 确认日志轮转配置。清理：docker rm -f noisy。

小结

记住这几点

  1. 存储驱动（overlay2、btrfs、zfs、fuse-overlayfs…）负责镜像层和容器层。新版 Docker 默认改用 containerd 的 snapshotter，原理相同。
  2. 数据卷不经过存储驱动：local 驱动的卷就是一个目录，通过 bind mount 直接挂进容器。没有 copy-up，写入性能等同于宿主机磁盘。
  3. Mac / Windows 上，容器跑在虚拟机里。绑定挂载要跨越虚拟机边界（virtiofs 等文件共享），大量小文件时明显变慢；命名卷在虚拟机磁盘里，快得多。
  4. docker system df 看磁盘占用。prune 系列命令清理；volume prune 会删数据，执行前确认。
  5. 容器日志默认用 json-file 驱动且不限大小，是磁盘被占满的常见原因。用 --log-opt max-size 或在 daemon.json 里全局设置。
