01

限制内存 100 MB，申请 200 MB。

docker run --name oom -m 100m --memory-swap 100m python:3.12-slim \
  python -c "x = bytearray(200*1024*1024); print('done')"; echo "exit=$?"
exit=137

确认是被 OOM 杀死的。

docker inspect -f "{{.State.OOMKilled}} {{.State.ExitCode}}" oom; docker rm oom

挑战

看到限流的证据

运行 docker run -d --name busy --cpus 0.2 alpine sh -c "while :; do :; done"。从容器的 cgroup 文件里读出它被限流了多少次、累计被限流了多长时间，并解释为什么 docker stats 显示的 CPU 大约是 20%。

查看参考答案
docker exec busy cat /sys/fs/cgroup/cpu.stat
usage_usec 2010442
nr_periods 101
nr_throttled 100
throttled_usec 7989310

每 100ms 一个周期，容器只能用 20ms。死循环每个周期都用完配额，于是几乎每个周期都被限流（nr_throttled ≈ nr_periods），剩下 80ms 在等待。延迟敏感的服务如果 nr_throttled 持续增长，说明 CPU 限制太紧，第 21 课会讲怎样调整。清理：docker rm -f busy。

小结

记住这几点

  1. cgroups（控制组）是内核功能：把进程分组，限制和统计每组的资源。现代发行版使用 cgroup v2，挂载在 /sys/fs/cgroup。
  2. --memory 256m 写入 memory.max。达到上限后先尝试回收；是否使用 swap 取决于配置。回收仍不足时可能触发 cgroup OOM。主进程被杀才会使容器退出为 137；只杀子进程时容器可能继续运行。
  3. --cpus 0.5 写入 cpu.max（每 100ms 周期最多 50ms）。超出不会被杀，而是被限流（throttled），表现为变慢。
  4. --pids-limit 限制进程数，防止 fork 炸弹拖垮宿主机。
  5. 不设限制时，一个容器可以用光整台机器的内存和 CPU。生产环境的每个容器都应该设置限制。
