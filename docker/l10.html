在你的电脑上练习

在本机运行一个私有仓库，完整走一遍推送和拉取。
01

启动本地仓库（官方 registry 镜像）。

docker run -d --name registry -p 5000:5000 registry:2
a8c0…
02

给已有镜像打标签。名字的第一段是仓库地址。

docker pull alpine:3.20
docker tag alpine:3.20 localhost:5000/tools/alpine:3.20
docker images --format "{{.Repository}}:{{.Tag}} {{.ID}}" | grep alpine
alpine:3.20 91ef0af61f39
localhost:5000/tools/alpine:3.20 91ef0af61f39
03

两个名字，同一个镜像 ID。推送。

docker push localhost:5000/tools/alpine:3.20
The push refers to repository [localhost:5000/tools/alpine]
63ca1fbb43ae: Pushed
3.20: digest: sha256:9cee2b38… size: 528
04

用仓库的 HTTP API 查看内容。

curl -s localhost:5000/v2/_catalog
curl -s localhost:5000/v2/tools/alpine/tags/list
{"repositories":["tools/alpine"]}
{"name":"tools/alpine","tags":["3.20"]}
05

删除本地副本，按摘要拉取。

docker rmi localhost:5000/tools/alpine:3.20
docker pull localhost:5000/tools/alpine@sha256:9cee2b38…（换成上一步的摘要）
…
Status: Downloaded newer image for localhost:5000/tools/alpine@sha256:9cee2b38…
06

再推一次同样的内容：所有层都已存在。

docker push localhost:5000/tools/alpine:3.20
63ca1fbb43ae: Layer already exists
07

清理。

docker rm -f registry
registry
挑战

推送到 GitHub Container Registry

把第 4 课的 api-demo 推送到 ghcr.io/你的用户名/api-demo，同时打上版本号和 git 提交号两个标签，并让 GitHub 上的包页面自动关联到你的仓库。

查看参考答案
# 用一个有 write:packages 权限的 token 登录
echo "$GHCR_TOKEN" | docker login ghcr.io -u 你的用户名 --password-stdin

# Dockerfile 里加一行，关联源码仓库
LABEL org.opencontainers.image.source=https://github.com/你的用户名/api-demo

SHA=$(git rev-parse --short HEAD)
docker build -t ghcr.io/你的用户名/api-demo:1.0.0 -t ghcr.io/你的用户名/api-demo:sha-$SHA .
docker push --all-tags ghcr.io/你的用户名/api-demo
1.0.0: digest: sha256:4f1e… size: 1990
sha-a1b2c3d: digest: sha256:4f1e… size: 1990

两个标签，同一个摘要。不要把 token 写进命令行参数（会留在 shell 历史里），用 --password-stdin。第 23 课会在 CI 里自动完成这些步骤。

小结

记住这几点

  1. 完整的镜像名：仓库地址/命名空间/仓库名:标签@摘要。省略时默认 docker.io/library/…:latest。
  2. 标签是可移动的指针，同一个标签可以先后指向不同内容；摘要（sha256:…）由内容计算得出，永远指向同一份内容。
  3. latest 只是一个默认标签名，不代表“最新”。生产部署用明确的版本号，或者固定到摘要。
  4. 常见标签策略：每次发布同时打 1.2.3、1.2、1，再加上 git 提交号，便于追溯。
  5. docker tag 不复制任何数据，只是多一个名字；docker push 只上传仓库里还没有的层。
