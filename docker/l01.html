为什么需要 Docker

内容：Docker 解决什么问题；镜像和容器是什么、怎样配合。约 15 分钟。

  1. 问题：环境不一致
  2. 虚拟机与容器
  3. 镜像与容器
  4. 前三条命令
  5. 自测与小结
01

代码一样，环境不一样。

本地一切正常

你在自己电脑上写了一个 Python 后端。环境是 Python 3.12、OpenSSL 3.0、requests 2.31。测试全部通过。

服务器上跑不起来

服务器是几年前装的，三个版本都更旧。同样的代码在这里报 ImportError 和 SSL 错误。

代码没变，变的是环境。

把环境和代码一起打包

Docker 把应用连同运行时、依赖库、配置打包成一个镜像。镜像里固定了这三个版本。

在服务器上运行同一个镜像

服务器只需要安装 Docker，然后运行这个镜像。镜像里的版本和你本地完全一样，服务器原来装了什么版本不再重要。

02

虚拟机带着整个系统，容器只带应用。

虚拟机：每个应用一套系统

以前的做法是虚拟机。Hypervisor 模拟出多台“电脑”，每台都要装自己的操作系统（Guest OS）。

三个应用 = 三套操作系统，每套占用 GB 级的磁盘和内存。

容器：共享宿主机内核

容器去掉了 Guest OS，只保留应用和它的依赖，所有容器共用宿主机的 Linux 内核。

隔离靠内核功能：namespace 让容器看不到彼此的进程和网络，cgroups 限制 CPU 和内存。所以，容器就是一个被隔离起来的普通进程。

结果：更快、更小

不用启动操作系统，容器通常不到一秒就能启动；镜像通常只有几十到几百 MB。

代价：隔离不如虚拟机彻底，而且容器必须使用宿主机的内核。在 Mac 和 Windows 上，Docker Desktop 会先启动一个小型 Linux 虚拟机。

03

镜像是只读的层，容器在上面加一层可写层。

镜像由只读层组成

镜像是一叠只读层。每一层记录一次文件变化：基础系统、安装的依赖、你的代码。层生成之后就不再改变。

docker run：加一层可写层

执行 docker run 时，Docker 不复制镜像，而是在只读层上面加一层可写层，然后启动进程。

只读层 + 可写层 + 运行中的进程 = 容器。

多个容器共享同一份镜像

再运行两次，得到三个容器。只读层在磁盘上仍然只有一份，每个容器只多出自己的可写层。这就是容器启动快、占用小的原因。

写入只影响自己

容器 1 写入了 /tmp/log.txt。文件进入容器 1 自己的可写层，镜像和另外两个容器都看不到它。这叫写时复制（Copy-on-Write）。

删除容器，镜像不变

docker rm 删除容器 3，它的可写层和里面的数据一起被删除。镜像不受影响，随时可以再启动新容器。

需要长期保存的数据（比如数据库）要放在 Volume 里，第 6 课会讲。

小结
记住这五点
    

  1. Docker 把应用和运行环境一起打包成镜像，解决环境不一致。
  2. 容器共享宿主机内核，比虚拟机启动快、占用小。隔离靠 namespace 和 cgroups。
  3. 镜像由只读层组成。容器 = 镜像 + 一层可写层 + 运行中的进程。
  4. 多个容器共享同一个镜像的只读层；写入只进入各自的可写层。
  5. 删除容器会删除它的可写层。需要保存的数据放在 Volume 里。
