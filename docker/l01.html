👉 Docker 的核心思路：把应用和它需要的一切（运行时、库、配置）一起打包，在任何装了 Docker 的机器上表现一致。

02 虚拟机 vs 容器

以前隔离环境靠虚拟机（VM）。容器也能隔离，但轻得多——关键在于容器共享宿主机的内核，不需要每个都带一个完整操作系统。

虚拟机
启动时间
分钟级 · 每个 GB 级
容器
启动时间
秒级 · 通常 MB 级

注意：容器隔离靠 Linux 的 namespace（看不到别人的进程/网络）和 cgroups（限制 CPU/内存）。容器本质上就是一个“被隔离起来的普通进程”。

03 镜像（Image）vs 容器（Container）

🧱 镜像 ≈ 类（Class）
只读的模板，由多层只读层叠成。每层是文件系统的一次变更。
🏃 容器 ≈ 实例（Object）
镜像 + 顶上一层可写层，然后作为进程跑起来。

机制：多个容器共享同一个镜像的只读层（不复制，所以省空间、启动快）；每个容器写文件时，写进自己的可写层（写时复制 Copy-on-Write）。删掉容器，可写层也就没了——镜像不受影响。

镜像 myapp:1.0 🔒只读
① FROM python:3.12-slim
② pip install -r req.txt
③ COPY app.py

点击 docker run 看看容器从同一个镜像“生出来”。

05 自测 3 题

⚠️ 新手常见坑

“容器停了，我的数据呢？” 写在可写层里的数据，docker rm 后就没了。数据库数据要用 Volume（第 6 课）。
每次 docker run 都是新容器。 想重新启动旧容器用 docker start，否则 docker ps -a 里会堆满已退出的容器（第 2 课）。
容器 ≠ 轻量虚拟机。 它没有自己的内核，Linux 镜像在 Mac/Windows 上其实跑在 Docker Desktop 的一个小 Linux VM 里。
latest 不等于“最新版”。 它只是一个默认标签名，生产环境请写明确版本（第 10 课）。

📝 本课小结

  • Docker 把应用 + 运行环境打包，解决“在我电脑上能跑”。
  • 容器共享宿主机内核 → 比虚拟机轻、快；隔离靠 namespace + cgroups。
  • 镜像 = 多个只读层；容器 = 镜像 + 可写层 + 运行中的进程。
  • 多个容器共享同一镜像层，写入走 Copy-on-Write。
  • 命令：docker run、docker ps -a、docker images。

06 后续预告：容器生命周期 & Dockerfile 🛠️

今天的镜像是别人做好的。下一课你将自己写 Dockerfile，把一个后端服务打包成镜像：

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["python", "app.py"]

（课程顺序：第 2 课先讲容器生命周期，第 3 课正式写 Dockerfile。）提示：每条指令≈一层。你会看到为什么先 COPY requirements 再 COPY 代码能让构建快 10 倍（层缓存）。
