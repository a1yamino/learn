OCI 镜像：层、配置与内容身份

分清标签、摘要和镜像 ID，明白为什么同一个名字不保证同一份内容。

先想一想

上周和今天都 pull 了 python:3.12-slim，标签一样，镜像 ID 却不同。是哪里变了？

原理图解推演迁移面试小结
01原理

原理

镜像由清单、配置和层组成

一个 OCI 镜像有三类内容：层是一组 tar 包，记录文件变化；配置是一份 JSON，写明环境变量、入口命令、用户和层的顺序；清单把配置和层串起来，每一项都用内容的 sha256 摘要来引用。

多平台镜像在清单之上还有一层索引，按 CPU 架构指向不同的清单。

标签会移动，摘要不会

标签是仓库里的一个可变指针，维护者发布新补丁时，python:3.12-slim 就指向了新的清单。摘要是内容的哈希，内容变了摘要必然变。

所以想固定版本，要用 name@sha256:... 来引用。镜像 ID 是本地配置的摘要，和仓库里的清单摘要不是一个东西，不要混着比。

相同的层只存一份

层按摘要寻址，两个镜像用了同一个基础层，本地和仓库里都只存一份，pull 时也只下载缺的部分。

这也意味着删掉一个文件不会让镜像变小：前一层里那个文件还在，新层只是记了一笔“它被删了”。

一次 pull 实际做了什么

客户端先向仓库请求标签对应的清单或索引，拿到摘要；如果是索引，再选出本平台的清单。然后读出清单里列的配置和层的摘要，本地已有的跳过，缺的才下载。

下载完成后逐个校验摘要，不一致就拒绝。这就是内容寻址带来的保证：只要摘要对得上，你拿到的就是那份内容，不管它经过了哪个镜像源或代理。

层的两个摘要

清单里记录的是压缩后层的摘要，用于下载和校验；配置里的 rootfs.diff_ids 记录的是解压后内容的摘要，用于本地存储和判断层是否相同。

同一份内容用不同的压缩方式（gzip、zstd）推送，清单摘要会不同，但 diff_id 一样。比较“两个镜像的文件是否相同”，看 diff_id 更可靠。

常见误区

镜像 ID 相同就说明是同一个仓库镜像
镜像 ID 是本地配置的摘要。两个仓库里内容相同的镜像 ID 一致，但仓库摘要可能因为压缩不同而不同。
latest 表示最新版本
latest 只是一个默认的标签名，维护者不推它就不会更新。它不代表任何时间上的“最新”。

放到生产里

部署清单里写 name@sha256:...，标签可以保留在前面方便阅读，比如 api:1.4@sha256:...，此时以摘要为准。

定期清理不再引用的镜像和层，但要先确认回滚需要的摘要仍在仓库里。

03推演

先猜，再看结果

Dockerfile 里先 COPY 一个 300MB 的安装包，下一条 RUN rm 掉它。最终镜像大约多大？

COPY 那一层已经记录了这个文件，后面的 RUN rm 只是新加一层，标记它被删除。层是叠加的，前面的内容不会消失。要在同一条 RUN 里下载、使用并删除，或者用多阶段构建只拷贝结果。

示例输出 · 只读
$ docker history app:bloat --format '{{.Size}}\t{{.CreatedBy}}'
0B      RUN /bin/sh -c rm /tmp/pkg.tar
301MB   COPY pkg.tar /tmp/ # buildkit
...
04迁移

换个场景

生产环境部署脚本写的是 image: api:latest。某天回滚到“上一个版本”，结果跑起来的还是有问题的代码。为什么？

先在心里走一遍：现象说明了什么，哪条证据能区分你的几个猜测。

展开推理

latest 只是一个标签，回滚脚本如果仍然拉 latest，拿到的是当前指针指向的内容，也就是有问题的版本。标签不记录历史。

发布记录里应该保存实际部署的摘要，回滚时按摘要拉取。这样“上一个版本”指的就是那份确定的内容。

05面试

讲给面试官听

镜像的标签、摘要、镜像 ID 有什么区别？

先用自己的话说一遍，大约一两分钟，再对照参考。

参考回答

标签是仓库里可移动的名字；摘要是清单内容的 sha256，内容不变它就不变，适合固定版本；镜像 ID 是本地配置 JSON 的摘要，用来在本机识别镜像。部署和审计应该记录仓库摘要，标签只适合给人看。

追问：为什么删文件不能让镜像变小？

层是只增不减的叠加，删除只在新层里写一个 whiteout 标记，旧层里的数据仍在。要在同一层内完成，或用多阶段构建。

追问：多平台镜像的摘要指的是什么？

通常指索引的摘要。拉取时客户端从索引里挑出匹配平台的清单，所以同一个索引摘要在不同架构上会落到不同的清单。

06小结

带走这几句

  1. 镜像 = 索引/清单 + 配置 + 层，全部内容寻址。
  2. 标签会移动，部署与回滚应记录摘要。
  3. 层只增不减，删除文件不会减小镜像。
