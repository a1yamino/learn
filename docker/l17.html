01

准备一个 Python 项目，Dockerfile 使用缓存挂载。

mkdir bk-demo && cd bk-demo
echo "numpy==2.1.2" > requirements.txt
cat > Dockerfile <<'EOF'
# syntax=docker/dockerfile:1
FROM python:3.12-slim
COPY requirements.txt .
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install -r requirements.txt
EOF
docker build -t bk-demo .
=> [3/3] RUN --mount=type=cache,target=/root/.cache/pip pip install -r requirements.txt   9.4s
02

加一个依赖。层缓存失效，但 numpy 不再重新下载。

echo "requests==2.32.3" >> requirements.txt
docker build --progress=plain -t bk-demo . 2>&1 | grep -E "Using cached|Downloading" | head -3
#7 1.12 Using cached numpy-2.1.2-cp312-…-manylinux_2_17_x86_64.whl
#7 1.31 Downloading requests-2.32.3-py3-none-any.whl

04

创建支持多平台的构建器。Linux 上先安装 QEMU 模拟器：docker run --privileged --rm tonistiigi/binfmt --install all（Docker Desktop 已内置）。

docker buildx create --name multi --driver docker-container --use
docker buildx inspect --bootstrap | grep Platforms
Platforms: linux/amd64, linux/arm64, linux/riscv64, linux/ppc64le, linux/s390x, linux/386, linux/arm/v7, linux/arm/v6
05

为两个平台构建，导出为 OCI 文件。

docker buildx build --platform linux/amd64,linux/arm64 -t bk-demo:multi -o type=oci,dest=bk.tar .
tar -xOf bk.tar index.json | python3 -m json.tool | grep architecture
"architecture": "amd64",
"architecture": "arm64",
06

清理。

docker buildx rm multi; rm -f bk.tar
multi removed
挑战

交叉编译的多平台 Go 镜像

用第 5 课的 slim-demo（Go）。改写 Dockerfile，让编译阶段始终在本机架构上运行，通过交叉编译产出目标架构的二进制，然后为 amd64 和 arm64 构建，推送到第 10 课的本地仓库，并确认 index 里有两个平台。

查看参考答案
FROM --platform=$BUILDPLATFORM golang:1.23 AS builder
ARG TARGETOS TARGETARCH
WORKDIR /src
COPY go.mod ./
RUN --mount=type=cache,target=/go/pkg/mod go mod download
COPY . .
RUN --mount=type=cache,target=/go/pkg/mod --mount=type=cache,target=/root/.cache/go-build \
    CGO_ENABLED=0 GOOS=$TARGETOS GOARCH=$TARGETARCH go build -ldflags="-s -w" -o /app .

FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=builder /app /app
ENTRYPOINT ["/app"]
docker run -d -p 5000:5000 --name registry registry:2
docker buildx create --name multi --driver docker-container --driver-opt network=host --use
docker buildx build --platform linux/amd64,linux/arm64 -t localhost:5000/slim:multi --push .
docker buildx imagetools inspect localhost:5000/slim:multi | grep Platform
  Platform:  linux/amd64
  Platform:  linux/arm64

$BUILDPLATFORM 是执行构建的机器，TARGETARCH 是目标。builder 阶段不用模拟，只有最终的 distroless 阶段按目标平台拉取（它只有 COPY，不需要执行任何命令）。--driver-opt network=host 让构建器容器能访问宿主机的 localhost:5000。

小结

记住这几点

  1. BuildKit 把 Dockerfile 变成依赖图：互不依赖的阶段并行构建，最终目标用不到的阶段直接跳过。
  2. RUN --mount=type=cache：给包管理器一个跨构建保留的缓存目录。层缓存失效时，下载过的包仍然可以复用；缓存目录不会进入镜像。
  3. --mount=type=secret 和 --mount=type=ssh：构建时使用密钥和 SSH agent，不写入任何层（第 9 课）。
  4. 多平台：docker buildx build --platform linux/amd64,linux/arm64 生成一个 index。能交叉编译的语言用 FROM --platform=$BUILDPLATFORM + TARGETARCH，比 QEMU 模拟快得多。
  5. CI 的每次构建都是新机器，本地缓存为空。用 --cache-to / --cache-from 把缓存存到仓库或 CI 的缓存服务里。
