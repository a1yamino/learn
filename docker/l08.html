在你的电脑上练习

一个计数 API 加 Redis。
01

新建项目：代码、依赖、Dockerfile。

mkdir compose-demo && cd compose-demo
cat > main.py <<'EOF'
import os
from fastapi import FastAPI
import redis
app = FastAPI()
r = redis.Redis(host=os.environ["REDIS_HOST"])

@app.get("/")
def hit():
    return {"hits": r.incr("hits")}
EOF
echo -e "fastapi==0.115.0\nuvicorn==0.30.6\nredis==5.0.8" > requirements.txt
cat > Dockerfile <<'EOF'
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
EOF
02

写 compose.yaml。

cat > compose.yaml <<'EOF'
services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      REDIS_HOST: cache
    depends_on:
      - cache
  cache:
    image: redis:7
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redisdata:/data
volumes:
  redisdata:
EOF

挑战

等数据库真正就绪

把 cache 换成 PostgreSQL（postgres:16）作为新服务 db，让 api 在 db 能接受连接之后才启动。用 docker compose up -d 的输出证明顺序。

查看参考答案
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: dev
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 2s
      timeout: 3s
      retries: 15
  api:
    depends_on:
      db:
        condition: service_healthy
 ✔ Container compose-demo-db-1    Healthy
 ✔ Container compose-demo-api-1   Started

api 会等到 db 的状态变成 Healthy 才启动。应用本身仍然应该在连接失败时重试：数据库在运行中也可能重启。

小结

记住这几点

  1. compose.yaml 描述服务（容器）、网络和数据卷。docker compose up -d 一次创建全部。
  2. Compose 为每个项目创建一个网络，服务之间用服务名互相访问。
  3. depends_on 只保证启动顺序，不保证对方已经可以接受连接。要等就绪，用 condition: service_healthy 加健康检查。
  4. up 是声明式的：只重建配置变化了的服务。代码变了要加 --build。
  5. down 删除容器和网络，保留数据卷；down -v 连数据卷一起删除。
