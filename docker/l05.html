02 多阶段构建：工厂 🏭 vs 包裹 📦

一个 Dockerfile 里写多个 FROM。前面的阶段负责编译，最后一个阶段从干净的小镜像开始，只用 COPY --from= 拿走编译产物。最终镜像只包含最后一个阶段的层。

05 基础镜像怎么选？


基础镜像大小（约）有 shell/包管理器适合


node:20 / python:3.121GB✅ 很全构建阶段


*-slim（Debian 精简）150–200MB✅ aptNode/Python 运行阶段首选，兼容性好


*-alpine50–130MB✅ apk小，但 musl libc 可能与原生依赖（如某些 Python wheel）不兼容


distroless2–50MB❌ 无 shell安全性最好；调试要用 :debug 变体


scratch0❌ 什么都没有Go/Rust 静态二进制（注意 CA 证书、时区）


06 查看镜像里到底有什么


⚠️ 新手常见坑


scratch 里 HTTPS 请求失败 x509: certificate signed by unknown authority：没有 CA 证书。用 distroless/static，或 COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/。


Go 二进制在 alpine/scratch 里报 “not found”：动态链接了 glibc。编译时加 CGO_ENABLED=0。


distroless 里 docker exec sh 失败：本来就没 shell。调试用 :debug 标签或 docker debug（第 11 课）。


为了小盲目上 alpine：Python 可能要从源码编译依赖，反而更慢更大。先用 slim。


✅ 自测 4 题


📝 本课小结
  • 层只增不减：后面 rm 不会减小体积。
  • 多阶段：FROM ... AS builder 编译，最终阶段 COPY --from=builder 只拿产物。
  • Go：CGO_ENABLED=0 + distroless/scratch → 十几 MB。
  • Node/Python：构建阶段装 dev 依赖编译，运行阶段用 slim + 生产依赖。
  • 用 docker history / dive 分析每层大小。
