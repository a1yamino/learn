多阶段构建

一个 Dockerfile 里写多个 FROM。每个 FROM 开始一个新阶段，最终镜像只包含最后一个阶段。

在你的电脑上练习

用 Go 写一个最小的 HTTP 服务，对比单阶段和多阶段。不需要在本机安装 Go。
01

新建项目。

mkdir slim-demo && cd slim-demo
cat > main.go <<'EOF'
package main

import (
	"fmt"
	"net/http"
)

func main() {
	http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) { fmt.Fprintln(w, "ok") })
	http.ListenAndServe(":8080", nil)
}
EOF
cat > go.mod <<'EOF'
module slim

go 1.23
EOF
02

单阶段：直接用 golang 镜像构建并运行。

cat > Dockerfile.single <<'EOF'
FROM golang:1.23
WORKDIR /src
COPY . .
RUN go build -o /app .
CMD ["/app"]
EOF
docker build -f Dockerfile.single -t slim:single .
03

多阶段：builder 编译，distroless 运行。

cat > Dockerfile <<'EOF'
FROM golang:1.23 AS builder
WORKDIR /src
COPY go.mod ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -ldflags="-s -w" -o /app .

FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=builder /app /app
USER nonroot
EXPOSE 8080
ENTRYPOINT ["/app"]
EOF
docker build -t slim:multi .
04

比较大小。

docker images slim
REPOSITORY   TAG      SIZE
slim         multi    7.9MB
slim         single   880MB
05

运行并访问。

docker run -d --name slim -p 8080:8080 slim:multi
curl -s localhost:8080
ok

挑战

给 Python 服务瘦身

第 4 课的 api-demo 再加一个需要编译的依赖：在 requirements.txt 加一行 psycopg2==2.9.9（需要 gcc 和 libpq-dev 才能安装）。写一个多阶段 Dockerfile：编译工具只留在 builder 阶段，最终镜像小于 200 MB，并且能正常 import psycopg2。

查看参考答案
FROM python:3.12-slim AS builder
RUN apt-get update && apt-get install -y --no-install-recommends gcc libpq-dev \
 && rm -rf /var/lib/apt/lists/*
RUN python -m venv /venv
ENV PATH=/venv/bin:$PATH
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

FROM python:3.12-slim
RUN apt-get update && apt-get install -y --no-install-recommends libpq5 \
 && rm -rf /var/lib/apt/lists/* && useradd -u 10001 app
COPY --from=builder /venv /venv
ENV PATH=/venv/bin:$PATH PYTHONUNBUFFERED=1
WORKDIR /app
COPY . .
USER app
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
docker build -t api-demo:slim . && docker images api-demo
docker run --rm api-demo:slim python -c "import psycopg2; print(psycopg2.__version__)"
api-demo   slim   ~170MB
api-demo   1.0    ~190MB（单阶段装 gcc 后会超过 400MB）
2.9.9 (dt dec pq3 ext lo64)

要点：虚拟环境 /venv 是一个可以整体复制的目录；运行阶段只需要运行时库 libpq5，不需要 gcc 和 -dev 头文件。

小结

记住这几点

  1. 镜像只增不减：后面的层删除文件，前面的层并不会变小。清理要在同一个 RUN 里完成。
  2. 多阶段构建：在 builder 阶段编译，只把产物 COPY --from=builder 到干净的运行阶段。编译器和源码都不会进入最终镜像。
  3. Go 这类静态二进制可以用 distroless/static 或 scratch；Python 用 slim 镜像，把虚拟环境整体复制过去。
  4. Alpine 用 musl libc，一些依赖 glibc 的 Python 包需要从源码编译，反而更大更慢。
  5. 更小的镜像：拉取更快、启动更快、漏洞更少。但没有 shell 的镜像调试更难，第 22 课讲怎样调试。
