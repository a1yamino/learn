事务基础：ACID 与 BEGIN / COMMIT

事务把多条语句变成一个不可分割的整体：要么全部生效，要么全部不生效。本课讲 ACID 四个性质各自由什么机制保证、BEGIN / COMMIT / ROLLBACK 和保存点、出错后事务进入的 aborted 状态，以及长事务为什么危险。隔离级别和 MVCC 的细节留到第 14、15 课。约 50 分钟。

挑战
写一个安全的转账
写一段转账脚本：从 A 转 30 给 B。要求：任何一步失败都整体回滚；余额不足时不能出现负数；并发执行两次也不会多扣。说明每一点由什么保证。
查看参考答案
BEGIN;
UPDATE accounts SET balance = balance - 30 WHERE name = 'A' AND balance >= 30;
-- 应用检查受影响行数：为 0 则 ROLLBACK，提示余额不足
UPDATE accounts SET balance = balance + 30 WHERE name = 'B';
COMMIT;
BEGIN
UPDATE 1
UPDATE 1
COMMIT
整体回滚由事务的原子性保证：中途任何错误都会让事务进入 aborted，最终只能回滚。不出现负数有两层：WHERE balance >= 30 让余额不足时更新 0 行，CHECK 约束兜底。并发安全来自行锁：两个事务同时更新 A 的那一行，第二个会等待第一个提交，然后在 READ COMMITTED 下重新读取最新的行再判断条件，所以不会基于旧余额扣两次（第 14、17 课详细讲）。不要先 SELECT 余额、在应用里判断、再 UPDATE 写回计算值，那样两个并发请求会读到同一个旧值。

小结
记住这几点


  1. 事务是一组要么全部提交、要么全部回滚的语句。没有显式 BEGIN 时，PostgreSQL 把每条语句当作一个单独的事务自动提交（autocommit）。
  2. Atomicity 原子性：靠回滚和 WAL 保证；Consistency 一致性：约束、外键和触发器在提交前必须成立；Isolation 隔离性：MVCC 与锁，默认级别 READ COMMITTED；Durability 持久性：COMMIT 返回前 WAL 已刷到磁盘（synchronous_commit = on）。
  3. 事务中任何一条语句出错，整个事务进入 aborted 状态：之后的语句都会报 current transaction is aborted, commands ignored until end of transaction block，只能 ROLLBACK。COMMIT 也只会变成回滚。
  4. SAVEPOINT s / ROLLBACK TO SAVEPOINT s 只撤销保存点之后的部分，事务可以继续。psql 的 \set ON_ERROR_ROLLBACK interactive 就是给每条语句自动加保存点。
  5. 事务尽量短：长事务持有锁、阻止 VACUUM 清理旧版本（表膨胀），空闲的 idle in transaction 连接还占着连接槽。用 idle_in_transaction_session_timeout 和 pg_stat_activity 防范。
  6. 事务里不要做网络调用、等待用户输入或发邮件这类外部副作用；外部动作无法随 ROLLBACK 撤销。
