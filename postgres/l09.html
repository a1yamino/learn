缓冲区与 I/O：shared_buffers 与操作系统缓存

PostgreSQL 读写数据页都要经过共享缓冲区，而共享缓冲区下面还有操作系统的页缓存。本课讲一次读页请求怎样命中或未命中、clock-sweep 如何选择要淘汰的页、脏页由谁写回、shared_buffers 和 effective_cache_size 怎么设，以及如何用 EXPLAIN (BUFFERS) 和 pg_stat 视图判断查询的 I/O。约 55 分钟。

04
用 pg_buffercache 看 orders 占了多少缓冲区。
CREATE EXTENSION pg_buffercache;
SELECT c.relname, count(*) AS buffers, pg_size_pretty(count(*) * 8192) AS size
FROM pg_buffercache b JOIN pg_class c ON b.relfilenode = pg_relation_filenode(c.oid)
WHERE b.reldatabase = (SELECT oid FROM pg_database WHERE datname = current_database())
GROUP BY c.relname ORDER BY 2 DESC LIMIT 3;

-----------------+---------+--------
 orders          |    1370 | 11 MB
 orders_pkey     |     276 | 2208 kB
 pg_attribute    |      38 | 304 kB

挑战
定位一个“慢但没缺索引”的查询
某接口偶尔慢：SELECT * FROM orders WHERE user_id = $1 ORDER BY created_at DESC LIMIT 20。已有索引 (user_id, created_at)。慢的时候 EXPLAIN 显示 Buffers: shared hit=3 read=21、I/O Timings: shared read=38.5，快的时候 shared hit=24。解释原因，给出两种改进方向。
查看参考答案
计划本身没问题，都是 24 个页。慢的那次有 21 页不在共享缓冲区，需要从操作系统读；38.5 ms 的读耗时说明它们也不在页缓存里，是真的读盘（每页约 2 ms，典型的云盘随机读）。冷门用户的订单分散在很多堆页上，每一行都在不同的页。
方向一：减少要读的页。用覆盖索引 CREATE INDEX ON orders (user_id, created_at DESC) INCLUDE (amount, status) 并只查需要的列，配合可见性映射走 Index Only Scan，几乎不读堆页；或者按 user_id 定期 CLUSTER（需锁表，通常用 pg_repack）让同一用户的行相邻。
方向二：让更多数据留在内存——工作集放不下时增大内存和 shared_buffers，或换随机读延迟更低的存储。先做方向一，代价小、效果确定。

小结
记住这几点


  1. 所有页的读写都经过共享缓冲区（shared_buffers，默认 128 MB，太小）。未命中时向操作系统发出读请求，操作系统的页缓存可能命中，否则才真正读盘——所以存在“双重缓存”。
  2. 常见起点：专用数据库服务器上 shared_buffers ≈ 内存的 25%，其余留给操作系统缓存和查询内存。effective_cache_size ≈ 50%–75% 只是告诉规划器总缓存大概多大，不分配内存。
  3. 淘汰用 clock-sweep：每个缓冲区有使用计数（最多 5），时钟指针转一圈逐个减一，减到 0 且未被固定（pin）的就被替换。热页计数高，留得久。大表顺序扫描和 VACUUM 使用小的环形缓冲区，不会冲掉整个缓存。
  4. 脏页由三方写回：检查点进程（周期性全部写回）、后台写进程 bgwriter（提前写一部分）、以及后端进程自己（找不到干净缓冲区时被迫写，最差）。
  5. EXPLAIN (ANALYZE, BUFFERS) 显示 shared hit（缓冲区命中）、read（向操作系统读，可能来自页缓存或磁盘）、dirtied、written。track_io_timing = on 后能看到 I/O 实际耗时，区分页缓存命中和真读盘。
  6. 命中率 blks_hit / (blks_hit + blks_read) 在 OLTP 系统通常应高于 99%。命中率低时先看是否缺索引导致大扫描，再考虑加内存。PostgreSQL 18 引入了异步 I/O（io_method），顺序扫描、VACUUM 等可以并发预读。
