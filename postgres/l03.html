窗口函数：每个用户最近的一笔订单。
SELECT user_id, id, amount, created_at FROM (
  SELECT o.*, row_number() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
  FROM orders o
) t WHERE rn = 1 ORDER BY user_id LIMIT 3;
 user_id |  id   | amount |          created_at
---------+-------+--------+-------------------------------
       1 | 48213 | 312.40 | 2026-10-20 07:41:09.12+00
       2 | 90117 |  45.10 | 2026-10-19 22:03:55.87+00
       3 | 11872 | 488.93 | 2026-10-21 01:17:30.44+00
06
窗口函数：按月的收入和环比。
WITH m AS (
  SELECT date_trunc('month', created_at) AS month, sum(amount) AS revenue
  FROM orders WHERE status IN ('paid','shipped') GROUP BY 1
)
SELECT month::date, revenue,
       round(100.0 * (revenue / lag(revenue) OVER (ORDER BY month) - 1), 1) AS mom_pct
FROM m ORDER BY month DESC LIMIT 3;
   month    |  revenue   | mom_pct
------------+------------+---------
 2026-10-01 | 1066312.75 |   -30.4
 2026-09-01 | 1532091.04 |     2.8
 2026-08-01 | 1490228.66 |    -2.1
挑战
NOT IN 与 NULL
执行 SELECT count(*) FROM users WHERE id NOT IN (SELECT user_id FROM orders); 得到 100。现在往 orders 里加一行 user_id 为 NULL 的数据（先临时去掉 NOT NULL 约束），再执行一次，结果变成多少？为什么？换成哪种写法不受影响？最后恢复约束。
查看参考答案
ALTER TABLE orders ALTER COLUMN user_id DROP NOT NULL;
INSERT INTO orders (user_id, amount) VALUES (NULL, 1);
SELECT count(*) FROM users WHERE id NOT IN (SELECT user_id FROM orders);
SELECT count(*) FROM users u WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
DELETE FROM orders WHERE user_id IS NULL;
ALTER TABLE orders ALTER COLUMN user_id SET NOT NULL;
 count
-------
     0

 count
-------
   100
id NOT IN (1, 2, …, NULL) 等价于 id <> 1 AND id <> 2 AND … AND id <> NULL。最后一项永远是 NULL（未知），整个条件不可能为 true，于是一行都不返回。NOT EXISTS 只判断“是否存在匹配的行”，NULL 不会匹配任何 id，所以结果正确；它通常也能被规划器执行为高效的反连接（anti join）。

小结
记住这几点


  1. INNER JOIN 只保留两边都匹配的行；LEFT JOIN 保留左表所有行，右边没有匹配时填 NULL。“没有订单的用户”用 LEFT JOIN … WHERE o.id IS NULL，或 NOT EXISTS。
  2. LEFT JOIN 时，对右表的过滤条件写在 ON 里才会保留左表行；写在 WHERE 里会把 NULL 行过滤掉，结果等同于 INNER JOIN。
  3. GROUP BY 把多行折叠成一行；SELECT 中的非聚合列必须出现在 GROUP BY 中（或函数依赖于主键）。WHERE 在分组前过滤行，HAVING 在分组后过滤组。count(*) 数行，count(列) 不计 NULL。
  4. 窗口函数 … OVER (PARTITION BY … ORDER BY …) 在不折叠行的情况下计算：排名（row_number、rank）、累计和、与上一行比较（lag）。“每个用户最近一笔订单”是典型用法。
  5. NULL 表示“未知”：NULL = NULL 结果是 NULL 而不是 true，判断要用 IS NULL / IS DISTINCT FROM；NOT IN (子查询) 遇到 NULL 会返回空，优先用 NOT EXISTS。
  6. CTE（WITH）让复杂查询分步可读；PostgreSQL 12 起，只被引用一次的 CTE 会被内联优化，不再是优化屏障（需要时可写 MATERIALIZED）。
