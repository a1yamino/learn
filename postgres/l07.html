存储：页、堆元组与 TOAST

从这一课开始进入内部原理。表在磁盘上是一组文件，文件由 8 KB 的页组成，页里存放带头部信息的元组。本课讲数据目录的结构、页的布局、元组头里的 xmin / xmax、ctid 是什么，以及超过约 2 KB 的大字段如何被 TOAST 压缩和切片存放。约 60 分钟。

06
TOAST：插入一个大文本，看主表和 TOAST 表的大小。
CREATE TABLE docs (id int, body text);
INSERT INTO docs SELECT 1, string_agg(md5(i::text), '') FROM generate_series(1, 20000) i;
SELECT pg_size_pretty(pg_relation_size('docs')) AS heap,
       pg_size_pretty(pg_relation_size(reltoastrelid)) AS toast,
       pg_column_size(body) AS stored, octet_length(body) AS raw
FROM pg_class, docs WHERE relname = 'docs';
 heap  | toast  | stored | raw
-------+--------+--------+--------
 8192 bytes | 352 kB | 352424 | 640000
挑战
列顺序与对齐
创建两张列相同但顺序不同的表：(a boolean, b bigint, c boolean, d bigint) 和 (b bigint, d bigint, a boolean, c boolean)，各插入 100 万行，比较表大小。解释差异来自哪里。
查看参考答案
CREATE TABLE t_bad (a boolean, b bigint, c boolean, d bigint);
CREATE TABLE t_good (b bigint, d bigint, a boolean, c boolean);
INSERT INTO t_bad SELECT true, i, false, i FROM generate_series(1,1000000) i;
INSERT INTO t_good SELECT i, i, true, false FROM generate_series(1,1000000) i;
SELECT relname, pg_size_pretty(pg_relation_size(oid)) FROM pg_class WHERE relname LIKE 't\_%';
 relname | pg_size_pretty
---------+----------------
 t_bad   | 50 MB
 t_good  | 42 MB
bigint 要求 8 字节对齐。t_bad 中 boolean（1 字节）后面紧跟 bigint，要补 7 个填充字节，两处共 14 字节浪费；t_good 把两个 bigint 放在前面，两个 boolean 紧挨在后面。每行再加上 23 字节头（对齐到 24）和 4 字节行指针，差距约 16%。对宽表和大表值得在建表时把定长的宽类型放前面、变长类型放后面；对已有表通常不值得为此重建。

小结
记住这几点


  1. 数据目录 PGDATA（容器里是 /var/lib/postgresql/18/docker）下，base/<数据库 OID>/<relfilenode> 就是一张表的文件。超过 1 GB 切成 .1、.2 段；_fsm 是空闲空间映射，_vm 是可见性映射。
  2. 表文件（堆）由 8 KB 的页组成。页头之后是行指针数组（line pointer，向后增长），元组从页尾向前存放，中间是空闲空间。
  3. ctid = (页号, 行指针号) 是元组的物理位置，索引条目存的就是它。UPDATE 会生成新版本、ctid 改变，所以 ctid 不能当作稳定的行标识。
  4. 每个元组有约 23 字节的头：xmin（插入它的事务）、xmax（删除或锁定它的事务）、infomask 标志位、NULL 位图。列按类型对齐存放，列顺序会影响填充字节（把 8 字节的列放前面能省空间）。
  5. 元组不能跨页。一行超过约 2 KB（TOAST_TUPLE_THRESHOLD）时，变长字段先被压缩（默认 pglz，可设为 lz4），仍然太大就切成约 2 KB 的块存进该表专属的 TOAST 表，主元组里只留一个指针。
  6. SELECT * 会把 TOAST 字段读出并解压；只查需要的列，大字段不读就不付出代价。频繁更新大 jsonb 字段的一小部分，代价是整个值重写。
