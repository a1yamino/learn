错误处理：重试主题与死信队列

消费者处理一条消息失败时，只有几种选择：卡住重试、跳过、或者把它挪到别处稍后处理。错误的选择会让一条坏消息堵住整个分区，或者悄悄丢掉数据。本课区分可重试与不可重试错误，讲阻塞重试、非阻塞的重试主题链、死信队列（DLQ）的设计，以及 Kafka Connect 与 Streams 中的内置错误处理和反序列化失败的毒丸消息。约 60 分钟。

02
写一个带 DLQ 的 Sink 连接器配置。
cat > /tmp/sink.properties <<'X'
name=pay-sink
connector.class=org.apache.kafka.connect.file.FileStreamSinkConnector
topics=payments
file=/tmp/payments.out
value.converter=org.apache.kafka.connect.json.JsonConverter
value.converter.schemas.enable=false
errors.tolerance=all
errors.deadletterqueue.topic.name=payments-dlt
errors.deadletterqueue.topic.replication.factor=1
errors.deadletterqueue.context.headers.enable=true
errors.log.enable=true
X

挑战
为支付回调消费者设计错误处理
消费者读 payments（key = 订单号），调用账务服务记账。观察到：账务服务偶尔超时（几秒）、每周维护停机 30 分钟、偶有上游发来缺字段的消息。同一订单的支付事件必须按顺序处理。请设计重试与 DLQ 策略，并说明 max.poll.interval.ms 等配置。
查看参考答案
  1. 分类：缺字段/反序列化失败 → 不可重试，立即进 payments-dlt（带原主题、分区、位移、异常 header），继续处理下一条。
  2. 短暂超时：阻塞重试，指数退避 200ms→5s，最多约 30 秒；max.poll.records 调小（如 50），确保 max.poll.records × 单条最坏耗时 + 重试时间 < max.poll.interval.ms（如 5 分钟）。
  3. 维护停机 30 分钟：因为要求按订单有序，不适合非阻塞重试主题（会乱序）。应在检测到下游持续不可用时 consumer.pause(assignment)，保持 poll 心跳但不取数据，定期探测，恢复后 resume；消息安全地留在 Kafka 中。
  4. 若必须用重试主题：失败消息进重试主题时，同时记录“该订单有待重试消息”，后续同一订单的消息也直接排到重试队列，以保持顺序（代价是复杂度）。
  5. DLQ 监控消息数并告警，提供重放工具，修复后写回 payments；记账接口按事件 ID 幂等，重放与重复都安全。

小结
记住这几点


  1. 先分类：可重试（下游超时、限流、数据库锁冲突）与不可重试（无法反序列化的毒丸消息、字段校验失败、业务规则拒绝）。不可重试的错误重试多少次都一样，应该直接进入死信队列。
  2. 阻塞重试：在消费者里原地重试（带退避），保持了分区内顺序，但会堵住这个分区的后续消息；重试总时长必须小于 max.poll.interval.ms，否则消费者被踢出组，引发再平衡和重复处理（第 7 课）。适合短暂故障和必须有序的场景。
  3. 非阻塞重试：失败的消息写入 orders-retry-1m、orders-retry-10m 等主题，提交原位置继续处理后面的消息；重试消费者读到消息后，等到“失败时间 + 延迟”再处理，仍失败就送往下一级，最后送入 orders-dlt。代价：同一 key 的消息可能乱序。
  4. 死信消息要带上下文 header：原主题、分区、位移、异常类、异常信息、重试次数、首次失败时间。DLQ 需要有人看：监控其消息量并告警，提供查看与重新投递的工具；修复后把消息写回原主题。
  5. Kafka Connect：errors.tolerance=all、errors.deadletterqueue.topic.name、errors.deadletterqueue.context.headers.enable=true、errors.retry.timeout.ms。Kafka Streams：deserialization.exception.handler（如 LogAndContinueExceptionHandler）、processing.exception.handler、production.exception.handler；新版本内置的处理器支持把失败记录发到死信主题。
  6. Java 消费者在 poll() 时反序列化失败会抛出 RecordDeserializationException，它带有分区与位移：可以记录、把原始字节发往 DLQ，然后 seek(offset + 1) 跳过。更稳妥的做法是用 ByteArrayDeserializer 接收，在自己的代码里反序列化。
