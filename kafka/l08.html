挑战
写一个“至少一次 + 幂等”的消费者
消费者从 payments 读取支付成功事件（每条有唯一的 event_id），为订单更新状态并给用户加积分，写入 PostgreSQL。要求：不丢事件、积分不重复、关闭和再平衡时尽量少重复。用伪代码写出主循环、提交方式、再平衡监听器和数据库中的幂等处理。
查看参考答案
props: enable.auto.commit=false, auto.offset.reset=earliest, max.poll.records=200
processedOffsets = {}  // 每分区已完成的连续位置；不是 poll 返回的末尾
consumer.subscribe(["payments"], listener)
while running:
  records = consumer.poll(500ms)
  for r in records:
    db.tx:
      inserted = INSERT INTO processed(event_id) VALUES (r.event_id)
                 ON CONFLICT DO NOTHING
      if inserted:
        UPDATE orders SET status = 'paid' WHERE id = r.order_id
        UPDATE users SET points = points + r.points WHERE id = r.user_id
    processedOffsets[r.partition] = r.offset + 1  // 只有数据库事务提交成功后才推进
  consumer.commitAsync(copy(processedOffsets))
finally:
  try: consumer.commitSync(copy(processedOffsets))
  finally: consumer.close()

listener.onPartitionsRevoked(parts):
  consumer.commitSync(processedOffsets 中属于 parts 的位置)
  从 processedOffsets 删除这些分区
listener.onPartitionsAssigned(parts):
  按各分区实际起点初始化已处理位置，不继承上一任成员的位置
无参数提交会使用 poll 已推进的位置；批次中途失败时不能在 finally 提交它。这里显式只提交业务已成功处理的连续位置，失败记录及其后续记录保留待重放。先处理后提交保证不丢；崩溃后会重放未提交的一部分，processed 表的唯一约束保证积分只加一次（幂等键与业务写入在同一数据库事务中）。processed 表可以按时间清理（保留时间大于可能的重放窗口）。另一种做法是把偏移量也存在数据库里并在启动时 seek()，实现精确一次。

小结
记住这几点


  1. 提交的偏移量是下一条要读的位置：处理完偏移量 41 后提交 42。提交写入内部主题 __consumer_offsets（默认 50 个分区，压缩主题），key 为 (组, 主题, 分区)。
  2. 自动提交（enable.auto.commit=true，默认，间隔 auto.commit.interval.ms 5 秒）：在 poll() 内部提交上一次 poll 返回的位置。只要在下一次 poll 前处理完上一批，就不会丢；但崩溃时最近 5 秒内处理过的消息会被重复处理。如果把消息交给其他线程异步处理，自动提交可能在处理完成前提交，导致丢失。
  3. 手动提交：commitSync() 在客户端超时范围内阻塞并重试，超时、权限或组成员变化时仍会抛异常，适合批次结束和关闭前；commitAsync(callback) 不阻塞、不重试（避免旧的提交覆盖新的），适合循环中；常见做法是循环里异步提交，关闭和分区被撤销时同步提交。可以按分区提交精确的偏移量。
  4. 交付语义：先处理后提交 → 至少一次（崩溃时重复）；先提交后处理 → 至多一次（崩溃时丢失）；精确一次需要把结果和偏移量原子地保存：写回 Kafka 时用事务（第 11 课），写到数据库时把偏移量和结果放在同一个数据库事务中，启动时用 seek() 从数据库中的偏移量开始。实际中最常用的是至少一次 + 幂等处理。
  5. auto.offset.reset：组在该分区没有已提交偏移量（新组、或偏移量已过期/超出范围）时从哪里开始：latest（默认，只读新消息）、earliest（从最早保留的消息）、none（抛异常）。Kafka 4.x 还支持 by_duration:PT1H 这类按时长回退的起点。已提交的偏移量在组变为空后保留 offsets.retention.minutes（默认 7 天）。
  6. 重置：组停止后用 kafka-consumer-groups.sh --reset-offsets：--to-earliest、--to-latest、--to-offset、--shift-by -100、--to-datetime、--by-duration，先 --dry-run 查看，再 --execute。
