Helm 与 Kustomize

真实应用有十几个 YAML 文件，还要部署到多个环境，每个环境只差几个值。本课讲两种主流做法：Helm 用模板和 values 生成清单并管理发布版本；Kustomize 在一份基础清单上叠加补丁，kubectl 内置支持。约 55 分钟。

05
Kustomize：base 与 prod overlay。
mkdir -p kz/base kz/prod
kubectl create deploy api --image=nginx:1.27-alpine --dry-run=client -o yaml > kz/base/deploy.yaml
cat > kz/base/kustomization.yaml <<EOT
resources: [deploy.yaml]
EOT
cat > kz/prod/kustomization.yaml <<EOT
resources: [../base]
namePrefix: prod-
labels: [{pairs: {env: prod}}]
images: [{name: nginx, newTag: 1.27.3-alpine}]
replicas: [{name: api, count: 4}]
configMapGenerator: [{name: api-config, literals: [LOG_LEVEL=warn]}]
EOT
kubectl kustomize kz/prod | grep -E "name:|image:|replicas:|env:"
    env: prod
  name: prod-api-config-5k7f2g8m9t
    env: prod
  name: prod-api
  replicas: 4
        image: nginx:1.27.3-alpine
06
应用，并清理 Helm release。
kubectl apply -k kz/prod
helm uninstall demo
configmap/prod-api-config-5k7f2g8m9t created
deployment.apps/prod-api created
release "demo" uninstalled
挑战
给 overlay 加补丁
在上面的 prod overlay 里，给 api 容器加上 requests（cpu 200m、memory 256Mi）和来自 api-config 的环境变量。用补丁实现，不修改 base。之后改了 literals 再 apply，为什么 Pod 会自动滚动更新？
查看参考答案
cat > kz/prod/patch.yaml <> kz/prod/kustomization.yaml
kubectl kustomize kz/prod | grep -A1 configMapRef
        - configMapRef:
            name: prod-api-config-5k7f2g8m9t
补丁按名字匹配 base 中的 Deployment 和容器，只合并写出的字段。补丁里写的是原名 api 和 api-config，Kustomize 会自动把引用改成加了前缀和哈希的名字。configMapGenerator 的名字带内容哈希：literals 变了，名字就变了，Deployment 的 Pod 模板引用也随之变化，于是触发滚动更新。直接修改一个普通 ConfigMap 则不会重启 Pod（第 6 课）。

小结
记住这几点


  1. Helm chart：Chart.yaml（名称、版本）、values.yaml（默认值）、templates/（Go 模板）。helm install 渲染模板并创建一个 release，状态存在所在命名空间的 Secret 中。
  2. 覆盖值：-f values-prod.yaml（多个 -f 时后面的优先）、--set image.tag=1.4.3（优先级最高）。helm template 只渲染不安装，helm diff 插件预览变更。
  3. helm upgrade --install 每次产生新的 revision；helm rollback 回到某个 revision（本身也是一个新 revision）。crds/ 目录里的 CRD 只在首次安装时创建，不会升级，需要单独处理。
  4. Kustomize：base/ 放通用清单，overlays/prod/ 的 kustomization.yaml 引用 base，再加补丁（patches）、改镜像（images）、加前缀、生成 ConfigMap（configMapGenerator 的名字带内容哈希，内容变了会触发滚动更新）。
  5. kubectl apply -k overlays/prod 应用，kubectl kustomize 只渲染。Kustomize 不用模板，输入输出都是合法的 YAML；它不记录发布历史。
  6. 怎么选：分发给别人安装的软件（数据库、网关、监控）通常用 Helm；自己团队的应用在多个环境间差异小时，Kustomize 更直观。两者也可以结合：用 Kustomize 修改 Helm 渲染的结果。
