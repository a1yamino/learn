在你的电脑上练习

kind 自带一个 local-path 的 StorageClass，可以体验动态供应。
01

查看默认 StorageClass。

kubectl get storageclass
NAME                 PROVISIONER             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION
standard (default)   rancher.io/local-path   Delete          WaitForFirstConsumer   false
02

创建 PVC。注意它处于 Pending：WaitForFirstConsumer。

kubectl apply -f - <<'EOF'
apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: data }
spec:
  accessModes: [ReadWriteOnce]
  resources: { requests: { storage: 1Gi } }
EOF
kubectl get pvc data
NAME   STATUS    VOLUME   CAPACITY   ACCESS MODES   STORAGECLASS   AGE
data   Pending                                      standard       2s
03

一个使用它的 Pod，写入数据。

kubectl run writer --image=busybox --overrides='{"spec":{"volumes":[{"name":"d","persistentVolumeClaim":{"claimName":"data"}}],"containers":[{"name":"w","image":"busybox","command":["sh","-c","echo hello > /d/f; sleep 3600"],"volumeMounts":[{"name":"d","mountPath":"/d"}]}]}}'
kubectl wait --for=condition=Ready pod/writer
kubectl get pvc data; kubectl get pv
data   Bound    pvc-3f1e…   1Gi   RWO   standard   40s
NAME        CAPACITY   ACCESS MODES   RECLAIM POLICY   STATUS   CLAIM
pvc-3f1e…   1Gi        RWO            Delete           Bound    default/data
04

删除 Pod，新 Pod 挂同一个 PVC，数据还在。

kubectl delete pod writer
kubectl run reader --rm -it --restart=Never --image=busybox --overrides='{"spec":{"volumes":[{"name":"d","persistentVolumeClaim":{"claimName":"data"}}],"containers":[{"name":"r","image":"busybox","command":["cat","/d/f"],"volumeMounts":[{"name":"d","mountPath":"/d"}]}]}}'
hello

挑战

保住数据

创建一个 reclaimPolicy: Retain 的 StorageClass keep（供应器同样是 rancher.io/local-path，绑定模式 WaitForFirstConsumer），用它申请 PVC 并写入数据。删除 PVC 后，让一个新的 PVC 重新绑定到这个旧 PV，读出原来的数据。

查看参考答案
kubectl apply -f - <<'EOF'
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata: { name: keep }
provisioner: rancher.io/local-path
reclaimPolicy: Retain
volumeBindingMode: WaitForFirstConsumer
EOF
# 用 storageClassName: keep 创建 PVC data，按练习第 3 步写入 hello
kubectl delete pod writer; kubectl delete pvc data
PV=$(kubectl get pv -o jsonpath="{.items[?(@.spec.storageClassName=='keep')].metadata.name}")
kubectl get pv $PV               # STATUS: Released
kubectl patch pv $PV -p '{"spec":{"claimRef":null}}'   # 变回 Available
# 新 PVC，指定 volumeName 绑定到这个 PV
kubectl apply -f - <
pvc-8a2c…   1Gi   RWO   Retain   Released   default/data   keep
persistentvolume/pvc-8a2c… patched
hello
Retain 让 PV 在 PVC 删除后进入 Released 状态，数据保留。它仍记着旧的 claimRef，所以要清掉才能被重新绑定；volumeName 让新 PVC 精确地绑到这个 PV。生产中，重要数据还要有独立于集群的备份（第 26 课 Velero）。

小结

记住这几点

  1. emptyDir 随 Pod 生灭，适合临时文件和容器间共享；hostPath 绑死在某个节点，普通应用不要用。
  2. PVC 是应用的“申请”（要多大、什么访问模式、哪个 StorageClass）；PV 是实际的存储；两者一对一绑定。
  3. StorageClass 让存储动态供应：创建 PVC 时，供应器（CSI 驱动）自动创建云盘或本地卷和对应的 PV。WaitForFirstConsumer 让卷在 Pod 调度后再创建，保证在同一可用区。
  4. 访问模式：RWO（单节点读写，大多数云盘）、RWOP（单 Pod）、RWX（多节点读写，需要 NFS、CephFS 等）、ROX。
  5. 回收策略：Delete（动态供应的默认值，删 PVC 就删数据）和 Retain（保留，手动处理）。重要数据用 Retain，并单独备份。
  6. Deployment 的多个副本共享同一个 RWO PVC 通常行不通；每个副本需要自己的卷时用 StatefulSet（第 17 课）。
