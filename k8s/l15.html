调度深入：亲和性、污点、拓扑分布与优先级

在你的电脑上练习

01

给两个 worker 打上模拟的可用区标签。

kubectl label node learn-worker topology.kubernetes.io/zone=a
kubectl label node learn-worker2 topology.kubernetes.io/zone=b
kubectl get nodes -L topology.kubernetes.io/zone
NAME                  STATUS   ROLES           ZONE
learn-control-plane   Ready    control-plane
learn-worker          Ready    <none>          a
learn-worker2         Ready    <none>          b
02

控制平面节点有污点，普通 Pod 不会放上去。

kubectl describe node learn-control-plane | grep Taints
Taints:             node-role.kubernetes.io/control-plane:NoSchedule
03

requests 太大：Pending，事件写明原因。

kubectl run big --image=nginx:alpine --overrides='{"spec":{"containers":[{"name":"big","image":"nginx:alpine","resources":{"requests":{"cpu":"64"}}}]}}'
kubectl get events --field-selector involvedObject.name=big -o custom-columns=MSG:.message | tail -1
0/3 nodes are available: 1 node(s) had untolerated taint {node-role.kubernetes.io/control-plane: }, 2 Insufficient cpu. preemption: 0/3 nodes are available: 1 Preemption is not helpful for scheduling, 2 No preemption victims found for incoming pod.
04

给 worker2 加污点，新 Pod 全部去 worker。

kubectl delete pod big
kubectl taint node learn-worker2 dedicated=gpu:NoSchedule
kubectl create deployment t --image=nginx:alpine --replicas=4
kubectl get pods -l app=t -o custom-columns=NODE:.spec.nodeName --no-headers | sort | uniq -c
      4 learn-worker
05

拓扑分布约束：去掉污点，副本按可用区均分。

kubectl taint node learn-worker2 dedicated-
kubectl delete deploy t
kubectl apply -f - <<EOT
apiVersion: apps/v1
kind: Deployment
metadata: {name: s}
spec:
  replicas: 4
  selector: {matchLabels: {app: s}}
  template:
    metadata: {labels: {app: s}}
    spec:
      topologySpreadConstraints:
      - maxSkew: 1
        topologyKey: topology.kubernetes.io/zone
        whenUnsatisfiable: DoNotSchedule
        labelSelector: {matchLabels: {app: s}}
      containers: [{name: n, image: nginx:alpine}]
EOT
kubectl get pods -l app=s -o custom-columns=NODE:.spec.nodeName --no-headers | sort | uniq -c
      2 learn-worker
      2 learn-worker2
挑战

专用节点

把 learn-worker2 设成只给 team=ml 的工作负载用：其他 Pod 不能放上去，并且 ml 的 Pod 只能放在它上面。写出节点上的操作和 Pod 模板里需要的字段，并说明只用其中一半会出现什么问题。

查看参考答案
kubectl taint node learn-worker2 team=ml:NoSchedule
kubectl label node learn-worker2 team=ml
spec:
  tolerations:
  - {key: team, operator: Equal, value: ml, effect: NoSchedule}
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          - {key: team, operator: In, values: [ml]}

只有污点和容忍：别人进不来，但 ml 的 Pod 仍可能被放到普通节点（容忍只是“允许”，不是“要求”）。只有标签和亲和性：ml 的 Pod 会去 worker2，但其他 Pod 也能挤占它。两者一起才是“专用”。另外 NoSchedule 不驱逐已在运行的 Pod；要清走已有的，用 NoExecute 或 kubectl drain。

小结

记住这几点

  1. 调度周期：过滤（Filter）排除不满足条件的节点，打分（Score）给剩下的排序，选最高分，然后 绑定（写 nodeName）。没有节点通过过滤 → Pending，事件里写明每类原因的节点数。
  2. 过滤看 requests 而不是实际用量：节点可分配量减去已有 Pod 的 requests 总和不够，就不能放。
  3. nodeSelector / nodeAffinity 是 Pod 主动选节点；污点（taint）是节点拒绝 Pod，只有带对应容忍（toleration）的 Pod 能放上去。专用节点要两者同时用：污点挡住别人，亲和性把自己引过去。
  4. required… 是硬条件（参与过滤），preferred… 是软条件（参与打分）。podAntiAffinity 用于“同一应用的副本不要在一起”。
  5. topologySpreadConstraints 按 topology.kubernetes.io/zone 等标签控制副本分布的最大偏差（maxSkew），比反亲和更灵活，是跨可用区高可用的推荐方式。
  6. PriorityClass：高优先级 Pod 放不下时，调度器可以抢占（驱逐）低优先级 Pod。系统组件用 system-cluster-critical。
