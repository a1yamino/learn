02

满足 restricted 的 Pod（nginx-unprivileged 监听 8080，以非 root 运行）。

kubectl -n secure apply -f - <<EOT
apiVersion: v1
kind: Pod
metadata: {name: good, labels: {app: good}}
spec:
  securityContext: {runAsNonRoot: true, seccompProfile: {type: RuntimeDefault}}
  containers:
  - name: n
    image: nginxinc/nginx-unprivileged:alpine
    securityContext: {allowPrivilegeEscalation: false, capabilities: {drop: [ALL]}}
EOT
kubectl -n secure get pod good

good   1/1     Running   0          6s

放行带 role=client 标签的 Pod。

kubectl -n secure apply -f - <<EOT
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: allow-client}
spec:
  podSelector: {matchLabels: {app: good}}
  ingress:
  - from: [{podSelector: {matchLabels: {role: client}}}]
    ports: [{port: 8080}]
EOT

06

ValidatingAdmissionPolicy：禁止 latest 标签。

kubectl apply -f - <<EOT
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicy
metadata: {name: no-latest}
spec:
  matchConstraints:
    resourceRules: [{apiGroups: [""], apiVersions: [v1], operations: [CREATE, UPDATE], resources: [pods]}]
  validations:
  - expression: "object.spec.containers.all(c, c.image.contains(':') && !c.image.endsWith(':latest'))"
    message: "镜像必须带版本标签，且不能是 latest"
---
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicyBinding
metadata: {name: no-latest}
spec: {policyName: no-latest, validationActions: [Deny]}
EOT
kubectl run x --image=nginx
The pods "x" is invalid: : ValidatingAdmissionPolicy 'no-latest' with binding 'no-latest' denied request: 镜像必须带版本标签，且不能是 latest
挑战

限制出站

给 secure 命名空间里 app=good 的 Pod 加 Egress 限制：只能访问同命名空间 app=db 的 5432 端口。写出策略后发现它连 db 的 Service 名都解析不了，为什么？怎么修？

查看参考答案
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: good-egress}
spec:
  podSelector: {matchLabels: {app: good}}
  policyTypes: [Egress]
  egress:
  - to: [{podSelector: {matchLabels: {app: db}}}]
    ports: [{port: 5432}]
  - to:
    - namespaceSelector: {matchLabels: {kubernetes.io/metadata.name: kube-system}}
      podSelector: {matchLabels: {k8s-app: kube-dns}}
    ports: [{port: 53, protocol: UDP}, {port: 53, protocol: TCP}]
kubectl -n secure exec good -- nslookup db
Name:   db.secure.svc.cluster.local
Address: 10.96.33.8

只写第一条规则时，Pod 的 Egress 被选中，只剩到 db:5432 的流量被允许；发往 kube-system 中 CoreDNS（53 端口）的 DNS 查询也被拦截，所以名字解析失败。第二条规则放行 DNS。注意 namespaceSelector 和 podSelector 写在同一个列表项里表示“且”；分成两项（各带一个 -）表示“或”，会放行 kube-system 的所有 Pod 以及本命名空间所有带 kube-dns 标签的 Pod，这是常见错误。

小结

记住这几点

  1. securityContext：runAsNonRoot、allowPrivilegeEscalation: false、readOnlyRootFilesystem、capabilities.drop: [ALL]、seccompProfile: RuntimeDefault。这些对应 Docker 第 19 课的容器安全设置。
  2. Pod Security Admission（内置）按命名空间标签执行三个级别：privileged（不限制）、baseline（禁止明显的提权，如 privileged、hostPath、hostNetwork）、restricted（要求上面那组加固设置）。模式有 enforce、audit、warn。
  3. NetworkPolicy 不存在时一切互通。一旦某个 Pod 在 Ingress（或 Egress）方向被任何策略选中，该方向就变成“只允许策略列出的流量”。策略是叠加的，没有拒绝规则。
  4. 常见做法：每个命名空间先放一条默认拒绝策略，再按需放行；限制 Egress 时别忘了放行 DNS（kube-system 的 53 端口）。策略由 CNI 执行，Flannel 等不支持时会被静默忽略。
  5. 准入控制在认证授权之后、写入 etcd 之前运行：先变更（mutating，如注入 sidecar、默认值），再校验（validating）。可以用 webhook，也可以用内置的 ValidatingAdmissionPolicy（CEL 表达式，无需部署服务）。
  6. 策略引擎 Kyverno、OPA Gatekeeper 用 CRD 写规则：禁止 latest 标签、要求 requests、只允许指定仓库的镜像等。
