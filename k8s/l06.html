ConfigMap 与 Secret

在你的电脑上练习

两种方式使用配置，亲手验证更新行为。
01

从字面值和文件创建 ConfigMap。

echo "max_conn = 100" > app.conf
kubectl create configmap app --from-literal=LOG_LEVEL=info --from-file=app.conf
kubectl get configmap app -o yaml | grep -A3 "^data"
data:
  LOG_LEVEL: info
  app.conf: |
    max_conn = 100
02

创建 Secret，然后看它是怎么存的。

kubectl create secret generic db --from-literal=password=s3cr3t
kubectl get secret db -o jsonpath="{.data.password}"; echo
kubectl get secret db -o jsonpath="{.data.password}" | base64 -d; echo
czNjcjN0
s3cr3t
03

一个 Pod 同时用环境变量和文件两种方式读取。

cat > cfg.yaml <<'EOF'
apiVersion: v1
kind: Pod
metadata: { name: cfg }
spec:
  containers:
  - name: app
    image: busybox
    command: ["sh","-c","sleep 3600"]
    envFrom: [{ configMapRef: { name: app } }]
    env:
    - name: DB_PASSWORD
      valueFrom: { secretKeyRef: { name: db, key: password } }
    volumeMounts: [{ name: conf, mountPath: /etc/app }]
  volumes:
  - name: conf
    configMap: { name: app }
EOF
kubectl apply -f cfg.yaml && kubectl wait --for=condition=Ready pod/cfg
kubectl exec cfg -- sh -c 'echo $LOG_LEVEL $DB_PASSWORD; cat /etc/app/LOG_LEVEL; echo'
info s3cr3t
info
04

修改 ConfigMap。

kubectl patch configmap app -p '{"data":{"LOG_LEVEL":"debug"}}'
sleep 70
kubectl exec cfg -- sh -c 'echo env=$LOG_LEVEL; echo file=$(cat /etc/app/LOG_LEVEL)'
env=info
file=debug

挑战

配置变更触发滚动更新

用 Kustomize（kubectl 内置）的 configMapGenerator 为一个 Deployment 生成 ConfigMap。修改配置值后重新 apply，确认：生成了新名字的 ConfigMap、Deployment 自动滚动更新、可以用 rollout undo 回到旧配置。

查看参考答案
mkdir kz && cd kz
cat > kustomization.yaml <<'EOF'
resources: [deploy.yaml]
configMapGenerator:
- name: app
  literals: [LOG_LEVEL=info]
EOF
kubectl create deployment web --image=busybox --dry-run=client -o yaml -- sleep 3600 > deploy.yaml
# 在 deploy.yaml 的容器下加入：envFrom: [{ configMapRef: { name: app } }]
kubectl apply -k . && kubectl get cm | grep app-
sed -i.bak "s/LOG_LEVEL=info/LOG_LEVEL=debug/" kustomization.yaml
kubectl apply -k . && kubectl rollout status deploy web
kubectl get cm | grep app-
kubectl rollout undo deploy web
kubectl exec deploy/web -- printenv LOG_LEVEL
app-g7hk2m9c5f   1      3s
configmap/app-5c8b6tf2d4 created
deployment.apps/web configured
deployment "web" successfully rolled out
app-5c8b6tf2d4   1      5s
app-g7hk2m9c5f   1      40s
info

名字里的哈希由内容计算。内容变了 → 名字变了 → Deployment 的 Pod 模板引用了新名字 → 模板变化 → 滚动更新（第 4 课）。旧 ConfigMap 仍在，所以 undo 后旧 ReplicaSet 引用的旧配置依然有效。这比原地修改 ConfigMap 更可控。

小结

记住这几点

  1. ConfigMap 存非敏感配置，Secret 存敏感数据。两者都可以作为环境变量或挂载为文件使用。
  2. 环境变量只在容器启动时读取，之后修改 ConfigMap 不会生效，需要重启 Pod（kubectl rollout restart）。
  3. 挂载为卷的文件会在约一分钟内自动更新（kubelet 同步周期），但 subPath 挂载不会更新。应用还需要自己重新读取文件。
  4. Secret 默认只是 base64 编码，不是加密。保护它靠：RBAC 限制读取、etcd 静态加密、不要提交到 git（用 Sealed Secrets、External Secrets 等）。
  5. 常见做法：不可变的配置版本（immutable: true + 名字带哈希，Kustomize 自动生成），修改配置 = 新名字 = 触发滚动更新，可回滚。
