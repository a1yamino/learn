在你的电脑上练习

在 kind 集群里分别创建四种工作负载。
01

创建 headless Service 和 StatefulSet。

kubectl apply -f - <<EOT
apiVersion: v1
kind: Service
metadata: {name: db}
spec: {clusterIP: None, selector: {app: db}, ports: [{port: 80}]}
---
apiVersion: apps/v1
kind: StatefulSet
metadata: {name: db}
spec:
  serviceName: db
  replicas: 3
  selector: {matchLabels: {app: db}}
  template:
    metadata: {labels: {app: db}}
    spec: {containers: [{name: n, image: nginx:alpine, volumeMounts: [{name: data, mountPath: /usr/share/nginx/html}]}]}
  volumeClaimTemplates:
  - metadata: {name: data}
    spec: {accessModes: [ReadWriteOnce], resources: {requests: {storage: 100Mi}}}
EOT
kubectl rollout status sts/db; kubectl get pods,pvc -l app=db -o name
pod/db-0
pod/db-1
pod/db-2
persistentvolumeclaim/data-db-0
persistentvolumeclaim/data-db-1
persistentvolumeclaim/data-db-2

04

DaemonSet：每个 worker 一个（控制平面有污点）。

kubectl create -f - <<EOT
apiVersion: apps/v1
kind: DaemonSet
metadata: {name: agent}
spec:
  selector: {matchLabels: {app: agent}}
  template:
    metadata: {labels: {app: agent}}
    spec: {containers: [{name: a, image: busybox, command: [sleep, "3600"]}]}
EOT
kubectl get pods -l app=agent -o custom-columns=NODE:.spec.nodeName --no-headers
learn-worker
learn-worker2
05

Job：5 次完成，并发 2。

kubectl apply -f - <<EOT
apiVersion: batch/v1
kind: Job
metadata: {name: batch}
spec:
  completions: 5
  parallelism: 2
  template:
    spec:
      restartPolicy: Never
      containers: [{name: w, image: busybox, command: [sh, -c, "sleep 3; echo done"]}]
EOT
kubectl wait --for=condition=Complete job/batch --timeout=60s; kubectl get job batch
job.batch/batch condition met
NAME    STATUS     COMPLETIONS   DURATION   AGE
batch   Complete   5/5           11s        12s
06

CronJob：每分钟一次，不允许并发。

kubectl create cronjob tick --image=busybox --schedule="*/1 * * * *" -- date
kubectl patch cronjob tick -p '{"spec":{"concurrencyPolicy":"Forbid"}}'
sleep 70; kubectl get jobs -l batch.kubernetes.io/cronjob-name=tick 2>/dev/null || kubectl get jobs
NAME            STATUS     COMPLETIONS   DURATION   AGE
tick-29351234   Complete   1/1           4s         12s
挑战

失败重试与超时

写一个 Job：命令以 70% 概率失败（[ $((RANDOM%10)) -lt 3 ]），最多重试 4 次，总时长不超过 60 秒，完成 1 小时后自动删除。失败的 Pod 应该留下来方便查日志还是被替换？restartPolicy 选哪个，两种选择下 backoffLimit 计数有什么区别？

查看参考答案
apiVersion: batch/v1
kind: Job
metadata: {name: flaky}
spec:
  backoffLimit: 4
  activeDeadlineSeconds: 60
  ttlSecondsAfterFinished: 3600
  template:
    spec:
      restartPolicy: Never
      containers:
      - name: w
        image: bash
        command: [bash, -c, "[ $((RANDOM%10)) -lt 3 ]"]
kubectl get pods -l job-name=flaky
flaky-4xk2p   0/1   Error       0   40s
flaky-9tqzr   0/1   Error       0   30s
flaky-c7m1d   0/1   Completed   0   10s

Never：每次失败都创建新 Pod，旧的失败 Pod 留下，可以逐个看日志；backoffLimit 按失败的 Pod 数计。OnFailure：在同一个 Pod 里重启容器，日志只剩最近一次，计数按容器重启次数；Pod 不会堆积。重试间隔指数增长（10s、20s、40s…），所以 activeDeadlineSeconds 可能先到，到期后 Job 失败，原因为 DeadlineExceeded。需要按退出码区分可重试和不可重试的错误时，用 podFailurePolicy。

小结

记住这几点

  1. StatefulSet：副本名固定为 名字-0、-1、-2，默认按序号依次创建、倒序删除；配合 headless Service 每个副本有稳定的 DNS 名（web-0.web.ns.svc）；volumeClaimTemplates 给每个副本一个自己的 PVC，Pod 重建后挂回同一个。
  2. 缩容不会删除 PVC（默认），再扩容时数据还在。persistentVolumeClaimRetentionPolicy 可以改变这个行为。StatefulSet 只给身份，不负责数据复制：主从、选主是应用或 Operator 的事。
  3. DaemonSet：每个（匹配的）节点运行一个 Pod，新节点加入自动补上。用于日志采集、监控代理、CNI、CSI node 插件。通常需要容忍各种污点。
  4. Job：运行 Pod 直到成功 completions 次，parallelism 控制并发，backoffLimit 限制失败重试，activeDeadlineSeconds 限制总时长。Pod 的 restartPolicy 只能是 OnFailure 或 Never。Indexed 模式给每个 Pod 一个序号。
  5. CronJob：按 cron 表达式创建 Job。concurrencyPolicy（Allow / Forbid / Replace）决定上一次没跑完时怎么办；timeZone 指定时区；startingDeadlineSeconds 处理错过的调度。
  6. ttlSecondsAfterFinished 自动清理已完成的 Job；CronJob 用 successfulJobsHistoryLimit 保留历史。
