自动扩缩容：HPA、VPA 与节点扩缩

负载变化时，Kubernetes 可以在三个层面自动调整：Pod 的数量（HPA）、Pod 的资源大小（VPA）、节点的数量（Cluster Autoscaler、Karpenter）。本课讲它们的算法、相互关系和常见的配置错误。约 50 分钟。

在你的电脑上练习

kind 默认没有 metrics-server，先安装（kind 的 kubelet 使用自签名证书，需要 --kubelet-insecure-tls）。
01

安装 metrics-server。

kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl -n kube-system patch deploy metrics-server --type=json -p '[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--kubelet-insecure-tls"}]'
kubectl -n kube-system rollout status deploy/metrics-server; sleep 30; kubectl top nodes
NAME                  CPU(cores)   CPU(%)   MEMORY(bytes)   MEMORY(%)
learn-control-plane   142m         1%       712Mi           9%
learn-worker          31m          0%       245Mi           3%
02

部署一个带 requests 的应用。

kubectl create deployment php --image=registry.k8s.io/hpa-example
kubectl set resources deploy php --requests=cpu=200m
kubectl expose deploy php --port 80
deployment.apps/php created
deployment.apps/php resource requirements updated
service/php exposed
03

创建 HPA。

kubectl autoscale deploy php --cpu-percent=50 --min=1 --max=8
kubectl get hpa php
NAME   REFERENCE        TARGETS       MINPODS   MAXPODS   REPLICAS
php    Deployment/php   cpu: 0%/50%   1         8         1

挑战

更快扩容、更慢缩容

流量突增时上面的 HPA 每次只能翻倍（默认每 15 秒最多 100% 或 4 个 Pod，取大者）。改写为 autoscaling/v2：扩容时每 15 秒最多增加 4 倍、无稳定窗口；缩容时 10 分钟稳定窗口，每分钟最多减少 1 个 Pod。并解释为什么副本数达到 max 后 CPU 仍然超标也不会继续扩。

查看参考答案
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: {name: php}
spec:
  scaleTargetRef: {apiVersion: apps/v1, kind: Deployment, name: php}
  minReplicas: 1
  maxReplicas: 8
  metrics:
  - type: Resource
    resource: {name: cpu, target: {type: Utilization, averageUtilization: 50}}
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 0
      policies: [{type: Percent, value: 300, periodSeconds: 15}]
    scaleDown:
      stabilizationWindowSeconds: 600
      policies: [{type: Pods, value: 1, periodSeconds: 60}]
kubectl describe hpa php | grep ScalingLimited
  ScalingLimited  True  TooManyReplicas  the desired replica count is more than the maximum replica count

增加 300% 即变为 4 倍。maxReplicas 是硬上限：条件 ScalingLimited 会显示 TooManyReplicas。这时要么提高上限，要么检查瓶颈是否根本不在这个服务（例如数据库），否则加副本也没用。

小结

记住这几点

  1. HPA 公式：期望副本 = ceil(当前副本 × 当前指标 / 目标指标)。CPU 利用率是相对 requests 计算的，没有 requests 的 Pod 无法按 CPU 扩缩。
  2. HPA 每 15 秒计算一次；比值在 ±10% 容差内不调整；缩容默认有 5 分钟稳定窗口，防止抖动。behavior 字段可以控制扩缩速度。
  3. 指标来源：metrics-server（CPU、内存）、custom metrics（如 Prometheus Adapter 提供的 QPS）、external metrics（如队列长度）。KEDA 基于事件扩缩，可以缩到 0。
  4. VPA 根据历史用量推荐或自动修改 requests。不要让 VPA 和 HPA 同时基于 CPU 工作：一个改分母，一个改副本数，会互相干扰。
  5. 节点扩缩：Pod 因资源不足 Pending → Cluster Autoscaler / Karpenter 添加节点；节点长时间利用率低且 Pod 能挪走 → 删除节点。它们看的也是 requests，不是实际用量。
  6. 扩容链条有延迟：指标采集 + HPA 周期 + 调度 + 新节点启动（分钟级）+ 镜像拉取 + 应用启动。突发流量需要预留余量或提前扩容。
