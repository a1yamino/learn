在你的电脑上练习

继续使用第 2 课的 kind 集群（kind create cluster --name learn --config kind.yaml）。
01

一个双容器 Pod：nginx 提供页面，另一个容器每 5 秒写入页面内容。两者共享一个 emptyDir 卷。

cat > two.yaml <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: two
  labels: { app: two }
spec:
  volumes:
  - name: html
    emptyDir: {}
  containers:
  - name: web
    image: nginx:alpine
    volumeMounts: [{ name: html, mountPath: /usr/share/nginx/html }]
  - name: writer
    image: busybox
    command: ["sh","-c","while true; do date > /out/index.html; sleep 5; done"]
    volumeMounts: [{ name: html, mountPath: /out }]
EOF
kubectl apply -f two.yaml && kubectl wait --for=condition=Ready pod/two
kubectl get pod two
pod/two created
pod/two condition met
NAME   READY   STATUS    RESTARTS   AGE
two    2/2     Running   0          9s

从 writer 容器访问 localhost:80：它和 nginx 共享网络。

挑战

原生 sidecar 与日志

写一个 Pod：主容器 busybox 每秒往 /logs/app.log 追加一行；一个原生 sidecar（initContainers 里 restartPolicy: Always）用 tail -F 把它输出到标准输出。用 kubectl logs 从 sidecar 读到日志。再说明：为什么 sidecar 要写在 initContainers 里？

查看参考答案
apiVersion: v1
kind: Pod
metadata: { name: logdemo }
spec:
  volumes: [{ name: logs, emptyDir: {} }]
  initContainers:
  - name: shipper
    image: busybox
    restartPolicy: Always
    command: ["sh","-c","touch /logs/app.log; tail -F /logs/app.log"]
    volumeMounts: [{ name: logs, mountPath: /logs }]
  containers:
  - name: app
    image: busybox
    command: ["sh","-c","i=0; while true; do echo line $i >> /logs/app.log; i=$((i+1)); sleep 1; done"]
    volumeMounts: [{ name: logs, mountPath: /logs }]
kubectl apply -f logdemo.yaml; sleep 5; kubectl logs logdemo -c shipper --tail 2
line 3
line 4

写在 initContainers 里并设 restartPolicy: Always（Kubernetes 1.29 起默认开启）：它先于主容器启动，主容器启动时它已就绪，不会丢掉最早的日志；Pod 结束时它最后停止；对 Job 来说，主容器完成后 sidecar 不会阻止 Pod 结束。普通的第二个容器做不到这些顺序保证。

小结

记住这几点

  1. Pod 是一组共享网络命名空间（同一个 IP、同一个 localhost）和卷的容器，总是被调度到同一个节点。
  2. 一个 Pod 通常只有一个主容器。只有必须共享网络或文件、必须一起扩缩容的辅助进程才放进同一个 Pod（sidecar：日志收集、代理）。
  3. init 容器按顺序运行并成功退出后，主容器才启动。原生 sidecar 是 restartPolicy: Always 的 init 容器，会和主容器一起运行。
  4. 阶段：Pending → Running → Succeeded / Failed。容器崩溃后按 restartPolicy 重启，间隔指数增长，表现为 CrashLoopBackOff。
  5. Pod 是一次性的：被删除或节点故障后不会自己回来，IP 也会变。生产中几乎不直接创建 Pod，而是用 Deployment 等控制器（第 4 课）。
