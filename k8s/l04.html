Deployment：滚动更新与回滚

Deployment 是运行无状态服务的标准方式。本课讲 Deployment、ReplicaSet、Pod 三层关系，滚动更新如何在不停机的情况下替换所有 Pod，maxSurge 和 maxUnavailable 怎么取值，以及回滚和暂停。约 45 分钟。

01

部署 v1。--record 已弃用，用注解记录变更原因。

kubectl create deployment web --image=nginx:1.26-alpine --replicas=4
kubectl annotate deployment web kubernetes.io/change-cause="v1 nginx 1.26"
kubectl rollout status deployment web

挑战

零中断更新

用 YAML 管理 web：4 副本，maxUnavailable: 0、maxSurge: 1，nginx 带一个 readinessProbe（HTTP GET /）。在另一个终端用 kubectl port-forward 不可行（只连一个 Pod），改为在集群里运行一个循环请求的 Pod，持续请求 Service（先 kubectl expose deployment web --port 80）。更新镜像，统计失败请求数。

查看参考答案
spec:
  replicas: 4
  strategy:
    rollingUpdate: { maxSurge: 1, maxUnavailable: 0 }
  template:
    spec:
      containers:
      - name: nginx
        image: nginx:1.26-alpine
        readinessProbe:
          httpGet: { path: /, port: 80 }
          periodSeconds: 2
kubectl apply -f web.yaml && kubectl expose deployment web --port 80
kubectl run probe --image=busybox -- sh -c 'ok=0; bad=0; while true; do if wget -qO- -T1 web >/dev/null; then ok=$((ok+1)); else bad=$((bad+1)); fi; echo "ok=$ok bad=$bad"; sleep 0.2; done'
kubectl set image deployment web nginx=nginx:1.27-alpine && kubectl rollout status deployment web
kubectl logs probe --tail 1
ok=412 bad=0

maxUnavailable: 0 保证任何时刻至少 4 个就绪 Pod；新 Pod 只有通过 readinessProbe 才会接收流量。真实应用还要处理关闭：收到 SIGTERM 后停止接收新请求、处理完已有请求再退出（第 9 课会讲 preStop 和优雅终止）。

小结

记住这几点

  1. Deployment 管理 ReplicaSet，ReplicaSet 管理 Pod。修改 Pod 模板（镜像、环境变量…）会创建一个新的 ReplicaSet；只改副本数不会。
  2. 滚动更新：逐步扩大新 ReplicaSet、缩小旧 ReplicaSet。maxSurge 是允许多出的 Pod 数，maxUnavailable 是允许不可用的 Pod 数。
  3. 新 Pod 只有就绪（readiness，第 9 课）后才算可用，滚动才继续。新版本起不来，滚动会卡住，旧 Pod 仍在服务。
  4. 旧 ReplicaSet 保留（revisionHistoryLimit，默认 10），所以 kubectl rollout undo 能快速回滚。
  5. strategy: Recreate 先删光旧 Pod 再建新的，会中断服务，只用于不能同时运行两个版本的应用。
  6. progressDeadlineSeconds：超时未完成，Deployment 标记为失败，rollout status 返回非 0，CI 据此判断。
