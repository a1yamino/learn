Service：服务发现与负载均衡

Pod 会被替换，IP 会变。Service 给一组 Pod 一个稳定的名字和虚拟 IP，并把流量分发给它们。本课讲标签选择器与 EndpointSlice、集群 DNS、四种 Service 类型，以及就绪状态如何影响流量。约 45 分钟。

挑战

Headless 与 Pod 直连

为 api 再建一个 headless Service api-h（clusterIP: None，同样的选择器）。分别 nslookup api 和 api-h，对比结果，并说明哪些场景需要 headless。

查看参考答案
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: Service
metadata: { name: api-h }
spec:
  clusterIP: None
  selector: { app: api }
  ports: [{ port: 8080 }]
EOF
kubectl run c --rm -it --image=busybox --restart=Never -- sh -c "nslookup api | tail -2; echo ---; nslookup api-h | grep Address | tail -3"
Name:	api.default.svc.cluster.local
Address: 10.96.142.37
---
Address: 10.244.2.6
Address: 10.244.1.9
Address: 10.244.2.5

普通 Service 返回一个虚拟 IP，由 kube-proxy 负载均衡；headless 直接返回所有就绪 Pod 的 IP，由客户端自己选择。需要 headless 的场景：数据库集群要直连特定成员（配合 StatefulSet 得到 db-0.db 这样的稳定名字）、客户端自己做负载均衡（如 gRPC 长连接）、服务发现组件需要成员列表。

小结

记住这几点

  1. Service 通过标签选择器找到 Pod。匹配且就绪的 Pod 的 IP 写进 EndpointSlice；不就绪的 Pod 不接收流量。
  2. ClusterIP（默认）：一个只在集群内可达的虚拟 IP。它不属于任何网卡，由每个节点上的 kube-proxy 规则转发（第 14 课）。
  3. DNS：web（同命名空间）、web.shop、web.shop.svc.cluster.local。
  4. NodePort：每个节点的 30000–32767 端口转发到 Service。LoadBalancer：再由云平台创建外部负载均衡器指向它。外部 HTTP 流量通常用 Ingress / Gateway（第 8 课）。
  5. Headless（clusterIP: None）：没有虚拟 IP，DNS 直接返回各 Pod 的 IP，用于 StatefulSet（第 17 课）。
  6. port 是 Service 的端口，targetPort 是容器端口，可以用端口名。
