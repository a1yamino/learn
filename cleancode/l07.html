对象与数据结构：数据抽象与迪米特法则

对象把数据藏在行为后面，数据结构把数据暴露出来、没有有意义的行为。两者各有所长：用对象时，添加新类型容易、添加新操作难；用数据结构加函数时，添加新操作容易、添加新类型难。本课讲数据抽象（不只是加上 getter/setter）、对象与数据结构的反对称性、迪米特法则与“火车失事”式调用链、混合体的问题、数据传输对象，以及 Python 中 dataclass、NamedTuple、property 的恰当用法。约 45 分钟。

之后：从构造时就检查余额非负，并在存取操作中保持它。下例只演示单线程内存对象；真实账户还需金额精度、并发和事务控制。
cat > bank.py <<'EOF'
class InsufficientFunds(Exception):
    pass

class Account:
    def __init__(self, opening_balance=0):
        if not opening_balance >= 0:
            raise ValueError("初始余额必须非负")
        self._balance = opening_balance

    @property
    def balance(self):
        return self._balance

    def deposit(self, amount):
        self._require_positive(amount)
        self._balance += amount

    def withdraw(self, amount):
        self._require_positive(amount)
        if amount > self._balance:
            raise InsufficientFunds(f"余额 {self._balance}，需要 {amount}")
        self._balance -= amount

    @staticmethod
    def _require_positive(amount):
        if not amount > 0:
            raise ValueError("金额必须为正")
EOF
python3 -c "
from bank import *
a = Account(50)
try:
    a.withdraw(80)
except InsufficientFunds as e:
    print('拒绝:', e)
print(a.balance)"
拒绝: 余额 50，需要 80

03
反对称性：数据 + match 函数。新增一个操作只需新函数。
cat > shapes.py <<'EOF'
import math
from dataclasses import dataclass

@dataclass(frozen=True)
class Square:
    side: float

@dataclass(frozen=True)
class Circle:
    radius: float

def area(shape):
    match shape:
        case Square(side=s):
            return s * s
        case Circle(radius=r):
            return math.pi * r * r
    raise TypeError(shape)

def bounding_box(shape):  # 新操作：不改动已有代码
    match shape:
        case Square(side=s):
            return (s, s)
        case Circle(radius=r):
            return (2 * r, 2 * r)
    raise TypeError(shape)
EOF
python3 -c "
from shapes import *
for s in [Square(2), Circle(1)]:
    print(type(s).__name__, round(area(s), 2), bounding_box(s))"
Square 4 (2, 2)
Circle 3.14 (2, 2)
挑战
选择组织方式
你在写一个支付系统，需要支持：信用卡、支付宝、微信支付，并且每年会接入 1–2 种新的支付方式；每种支付方式需要“扣款、退款、查询状态”三个操作，这三个操作多年来很少变化。另一边，你在写一个规则引擎的表达式求值器：节点类型（数字、加、乘、变量）几乎固定，但经常要添加新的操作（求值、打印、化简、类型检查）。两者分别该怎样组织？
查看参考答案
  • 支付方式：面向对象 / 多态。变化的维度是“类型”，操作稳定。定义 PaymentMethod 协议（charge、refund、status），每种支付方式一个类；接入新方式时新增一个类，不改动已有代码（开闭原则，第 12 课）。
  • 表达式求值器：数据结构 + 函数。节点是不可变的 dataclass，每个操作是一个 match 函数；新增“化简”只需新增一个函数。这正是编译器常用的组织方式（或访问者模式）。
两种选择没有绝对的好坏，关键是预测哪一种变化更频繁，让那种变化变得便宜。

小结
记住这几点


  1. 数据抽象：接口应表达数据的本质，而不是它的存储方式。tank.percent_fuel_remaining() 比 tank.get_gallons_of_gasoline() 抽象层次更高。机械地给每个字段加 getter/setter 并没有隐藏任何东西。
  2. 反对称性：过程式（数据结构 + 函数）让添加新函数容易，添加新数据类型要改所有函数；面向对象让添加新类型容易，添加新操作要改所有类。根据哪一种变化更常见来选择。
  3. 迪米特法则：方法只应调用自身、参数、自己创建的对象、自己的字段的方法，不要和“陌生人”说话。ctx.options.scratch_dir.absolute_path 让调用方依赖了整条链的结构。
  4. 告诉，不要问：与其取出内部数据再做决定（问），不如让对象自己去做（告诉）：ctx.create_scratch_file(name)。但对纯数据结构（DTO、配置、JSON）链式访问是可以的——它们本来就公开结构。
  5. 避免混合体：一半是对象（有重要行为）、一半是数据结构（公开字段被外部随意修改）的类，同时得到两者的缺点。
  6. Python 工具：@dataclass(frozen=True)、NamedTuple 适合数据结构与值对象；需要保持不变量时把字段设为私有，通过有意义的方法修改；@property 用来表达派生值，而不是包装每个字段。
