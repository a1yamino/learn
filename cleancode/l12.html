03
何时应用，何时不必
每条原则都有成本：额外的抽象、间接层和文件。


原则值得应用的信号可以暂缓的情况


OCP同一个分支链已经第二次因新类型被修改；有第三方需要扩展你的代码（插件）只有一两种情况，且很少变化


LSP始终遵守：违反它的继承一定会产生 bug—（不确定时用组合代替继承）


ISP使用者只用了接口中很少的方法；实现类被迫写空方法接口本来就小


DIP业务规则需要在没有基础设施的情况下测试；细节可能被替换小脚本、一次性工具；与框架深度绑定的薄层（如简单的 CRUD 视图）


# Python 中的 ISP + DIP：使用者声明自己需要的最小接口
from typing import Protocol

class OrderFinder(Protocol):
    def orders_in(self, month: str) -> list[Order]: ...

def monthly_revenue(orders: OrderFinder, month: str) -> Decimal:
    return sum(o.total for o in orders.orders_in(month))

cat > exporters.py <<'EOF'
import json

EXPORTERS = {}

def exporter(name):
    def register(fn):
        EXPORTERS[name] = fn
        return fn
    return register

@exporter("csv")
def to_csv(rows):
    return "\n".join(",".join(map(str, r)) for r in rows)

@exporter("json")
def to_json(rows):
    return json.dumps(rows)

def export(rows, fmt):
    try:
        return EXPORTERS[fmt](rows)
    except KeyError:
        raise ValueError(f"不支持的格式 {fmt!r}，可选：{sorted(EXPORTERS)}") from None
EOF

from exporters import exporter

@exporter("tsv")   # 新格式：新文件，不修改 exporters.py
def to_tsv(rows):
    return "\n".join("\t".join(map(str, r)) for r in rows)
EOF

02
LSP：一套契约测试，运行在每个子类型上。
cat > shapes.py <<'EOF'
class Rectangle:
    def __init__(self, w, h):
        self.w, self.h = w, h
    def set_width(self, w):
        self.w = w
    def area(self):
        return self.w * self.h

class Square(Rectangle):
    def __init__(self, side):
        super().__init__(side, side)
    def set_width(self, w):
        self.w = self.h = w
EOF
cat > test_contract.py <<'EOF'
import unittest
from shapes import Rectangle, Square

class RectangleContract(unittest.TestCase):
    def make(self):
        return Rectangle(2, 3)

    def test_area_after_set_width(self):
        r = self.make()
        h = r.h
        r.set_width(10)
        self.assertEqual(r.area(), 10 * h)

class SquareContract(RectangleContract):
    def make(self):
        return Square(3)

unittest.main(argv=["x", "-v"], exit=False)
EOF
python3 test_contract.py 2>&1 | grep -E "\.\.\.|AssertionError"
test_area_after_set_width (__main__.RectangleContract.test_area_after_set_width) ... ok
test_area_after_set_width (__main__.SquareContract.test_area_after_set_width) ... FAIL
AssertionError: 100 != 30
挑战
修复 LSP
给出两种消除上面 Square/Rectangle 问题的设计，并说明各自适合的场景。
查看参考答案
  1. 不可变值对象：去掉会修改自身的 set_width，改为 with_width(w)，并规定它总是返回一个新的 Rectangle（宽为 w、高不变）。Square(3).with_width(10) 得到 Rectangle(10, 3)——不再是正方形，但契约对两者都成立，因为没有对象被“就地改形”。适合几何、金额这类值。
  2. 不继承，共享接口：Rectangle 与 Square 都实现 Shape 协议（area()），彼此没有继承关系；需要修改尺寸的代码只接受 Rectangle。适合两者行为确实不同的情况。
判断依据：继承表达的是“行为上可替换”，而不是现实中的“是一种”。

小结
记住这几点


  1. 开闭原则（OCP）：添加新行为时，通过新增代码（新类、新函数、新注册项）完成，而不是修改已有的、经过测试的代码。实现手段：多态、策略对象、注册表、插件。
  2. 里氏替换原则（LSP）：凡是使用父类型的地方，换成子类型都应当正确工作。经典反例：Square 继承 Rectangle 后，设置宽度会意外改变高度。子类不应加强前置条件、削弱后置条件，或抛出父类未声明的异常（如 NotImplementedError）。
  3. 接口隔离原则（ISP）：使用者只依赖它需要的方法。一个巨大的 Repository 接口让只读的报表模块也依赖写方法。Python 中用小的 Protocol 表达“我需要什么”。
  4. 依赖倒置原则（DIP）：业务规则不应依赖数据库、框架、HTTP 这些细节；两者都依赖抽象，并且抽象由高层（使用者）定义。依赖注入是实现它的常用手段（下一课）。
  5. 原则是工具，不是目标：为“可能的扩展”提前建立抽象层会增加复杂度（YAGNI：你不会需要它）。常见的做法是：第一次直接写；第二次出现变化时，引入抽象（“三次法则”的变体）。
  6. Python 的特点：鸭子类型与 Protocol 让接口很轻；函数是一等公民，很多“策略模式”只需要传一个函数。
