Clean Code · 第 17 课

重构手法：提取、内联、移动与以多态取代条件

重构是在不改变外部行为的前提下改善代码的内部结构，每一步都很小、可以随时停下、测试始终是绿的。本课练习最常用的手法：提取函数 / 内联函数、提取变量 / 内联变量、改名、引入参数对象、移动函数、拆分阶段、以卫语句取代嵌套条件、以多态取代条件、以查表取代条件。重点是“小步”：每一步之后都运行测试并提交。约 55 分钟。

03
“两顶帽子”与提交节奏
重构与功能开发交替进行，但不同时进行。


时刻帽子做法


准备添加功能，发现结构不便重构先让修改变得容易（“make the change easy, then make the easy change”——Kent Beck）


结构合适了功能写失败的测试，实现


功能完成，代码有点乱重构测试保护下清理


提交建议：重构的提交与功能的提交分开。评审者看到“仅重构”的提交时，只需确认行为未变；看到功能提交时，diff 很小、很专注。


编辑器的自动重构：PyCharm 与 VS Code（Pylance / Rope）支持改名、提取方法 / 变量、内联、移动、修改签名。它们基于语法树而非文本，能同时更新所有引用。动态语言中自动重构并不总是 100% 安全（如 getattr 动态访问），所以测试仍然必要。

第 1 步：创建类层次与工厂，旧函数委托给对象。测试仍然通过。
cat > birds.py <<'EOF'
class Bird:
    def __init__(self, data):
        self._data = data
    @property
    def plumage(self):
        return "unknown"
    @property
    def speed(self):
        return None

class European(Bird):
    @property
    def plumage(self):
        return "average"
    @property
    def speed(self):
        return 35

class African(Bird):
    @property
    def plumage(self):
        return "tired" if self._data["coconuts"] > 2 else "average"
    @property
    def speed(self):
        return 40 - 2 * self._data["coconuts"]

class NorwegianBlue(Bird):
    @property
    def plumage(self):
        return "scorched" if self._data["voltage"] > 100 else "beautiful"
    @property
    def speed(self):
        return 0 if self._data["nailed"] else 10 + self._data["voltage"] / 10

BIRD_TYPES = {"european": European, "african": African, "norwegian_blue": NorwegianBlue}

def create_bird(data):
    return BIRD_TYPES.get(data["kind"], Bird)(data)

def plumage(data):
    return create_bird(data).plumage

def speed(data):
    return create_bird(data).speed
EOF

挑战
设计重构步骤
下面的函数既解析又计算，并且对类型有条件分支。写出一个由小步组成的重构计划（每一步都能保持测试通过）：
def price(order_text, products):
    # 格式："SKU-数量"，如 "kettle-3"
    sku, qty = order_text.split("-")
    qty = int(qty)
    p = products[sku]
    base = p["base_price"] * qty
    if p["category"] == "food":
        discount = 0
    elif p["category"] == "electronics":
        discount = max(qty - p["discount_threshold"], 0) * p["base_price"] * 0.1
    else:
        discount = max(qty - p["discount_threshold"], 0) * p["base_price"] * p["discount_rate"]
    return base - discount
查看参考答案
  1. 写特征测试，覆盖三种品类与阈值两侧。
  2. 拆分阶段：提取 parse_order(text) -> OrderLine(sku, qty)，price 先调用它。测试，提交。
  3. 提取函数：discount_for(product, qty)，把条件链移进去。测试，提交。
  4. 以卫语句取代条件：if category == "food": return 0 提前返回。测试，提交。
  5. 如果品类会继续增加，或别处也有按品类的分支：以多态 / 查表取代条件——DISCOUNT_RATES = {"electronics": 0.1}，其他品类使用产品自身的 discount_rate。测试，提交。
  6. 最后改名：price → price_order，p → product。
每一步都是机械的、可单独回退的。重构计划的好坏不在于终点，而在于每一步之间测试是否始终是绿的。

小结
记住这几点


  1. 重构的定义：不改变可观察行为，只改结构。功能修改和重构要分开做（“两顶帽子”）：戴着重构的帽子时不加功能，反之亦然。
  2. 小步：每一步只做一个机械的变换，运行测试，必要时提交。出错时只需回退最后一小步。现代编辑器的自动重构（改名、提取、内联、移动）比手工更安全。
  3. 提取与内联是一对：提取函数给一段代码一个名字；当名字并没有比代码本身更清楚，或者想重新组织一组函数时，先内联再重新提取。
  4. 以卫语句取代嵌套条件：先处理特殊情况并立即返回，主逻辑不必缩进在多层 if 中。
  5. 以多态 / 查表取代条件：按类型的条件分支在多处出现时，用多态（每种类型一个类）；只是映射数据时，用一个 dict 更简单。
  6. 拆分阶段：一段代码同时做两件按顺序发生的事（解析然后计算），把它拆成两个阶段，中间用一个数据结构连接。
