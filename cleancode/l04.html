参数数量与测试成本
每增加一个参数，需要考虑的组合就成倍增加。


参数个数例子说明


0report.render()最容易理解与测试


1is_valid(email)、parse(text)、on_click(event)常见的三种形态：问一个问题、转换一个值、处理一个事件


2Point(x, y)、assert_equal(expected, actual)有自然顺序时没问题；没有自然顺序时，调用处容易写反


3transfer(source, target, amount)需要有充分理由；考虑参数对象或关键字参数


更多create(a, b, c, d, e, f)几乎总是缺少一个概念（对象）


Python 的工具：关键字参数让调用处自解释；* 之后的参数只能用关键字传递；@dataclass 可以快速定义参数对象。不要为了“减少参数”而改用 **kwargs 吞下一切——那只是把参数藏了起来。

sent = []

def make_invoice(customer, items, discount, send, lines=[]):
    total = 0
    for name, price in items:
        lines.append(f"{name}: {price}")
        total += price
    total = total * (1 - discount)
    lines.append(f"total: {total:.2f}")
    if send:
        sent.append(customer)
    return lines

02
可变默认参数让 bob 的发票里出现了 ann 的行。重构：参数对象、拆掉标识参数、返回新值。
cat > invoice.py <<'EOF'
from dataclasses import dataclass

@dataclass(frozen=True)
class LineItem:
    name: str
    price: float

@dataclass(frozen=True)
class Invoice:
    customer: str
    items: tuple[LineItem, ...]
    discount: float = 0.0

    def total(self):
        return sum(i.price for i in self.items) * (1 - self.discount)

    def lines(self):
        return [f"{i.name}: {i.price}" for i in self.items] + [f"total: {self.total():.2f}"]

class Mailer:
    def __init__(self):
        self.sent = []

    def send(self, invoice):
        self.sent.append(invoice.customer)
EOF
python3 -c "
from invoice import *
ann = Invoice('ann', (LineItem('pen', 10),))
bob = Invoice('bob', (LineItem('ink', 20),), discount=0.1)
print(ann.lines()); print(bob.lines())
mailer = Mailer(); mailer.send(bob); print(mailer.sent)"
['pen: 10', 'total: 10.00']
['ink: 20', 'total: 18.00']
['bob']

挑战
设计一个接口
你要写一个搜索订单的函数。需求：可以按客户、状态、日期范围（开始和结束）过滤，可以选择排序字段和方向，可以分页（页码、每页条数），可以选择是否包含已删除订单。写出函数签名，并说明你的选择。
查看参考答案
@dataclass(frozen=True)
class DateRange:
    start: date
    end: date

@dataclass(frozen=True)
class Page:
    number: int = 1
    size: int = 50

def search_orders(
    *,
    customer_id: str | None = None,
    status: OrderStatus | None = None,
    placed_within: DateRange | None = None,
    sort_by: str = "placed_at",
    descending: bool = True,
    page: Page = Page(),
    include_deleted: bool = False,
) -> list[Order]: ...
  • 全部为仅限关键字参数：9 个维度没有自然顺序，调用处必须写名字，如 search_orders(status=PAID, page=Page(2))。
  • DateRange、Page 是总是成对出现的概念，组成参数对象，也可以在别处复用并单独校验（start ≤ end）。
  • include_deleted 是标识参数，但它不改变函数做的事（仍然是“搜索”），只是过滤条件之一，以关键字形式保留是合理的。
  • 参数很多时，也可以定义一个 OrderQuery 对象，让函数只接受一个参数：search_orders(query)。

小结
记住这几点


  1. 参数越少越好：每个参数都是读者必须理解、测试必须覆盖的维度。三个以上的参数通常说明一些参数应该组成一个对象（Point(x, y)、DateRange(start, end)）。
  2. 标识参数是坏味道：render(page, True) 中的 True 是什么？它说明函数做了两件事。拆成 render_for_print(page) 与 render_for_screen(page)，或至少要求关键字参数。
  3. 仅限关键字参数（Python 的 *）让调用处必须写出名字：定义 def transfer(source, target, amount, *, notify=False): ...，调用 transfer(a, b, 100, notify=True)。裸 * 写在定义处，不是调用处。
  4. 避免隐藏的副作用：check_password() 内部顺便初始化会话，就制造了时间耦合——只有在“可以初始化会话”的时候才能调用它。副作用要么移出去，要么写进名字。
  5. 命令查询分离（CQS）：set(attr, value) 既修改又返回成功与否，导致 if set("name", "x") 这种含混的代码。要么做事（命令，返回 None），要么回答问题（查询，无副作用）。例外：pop() 这类约定俗成的操作。
  6. 不修改传入的参数：输出参数让读者困惑“它会被改吗”。返回新值；Python 中尤其要警惕可变默认参数 def f(items=[])，它在多次调用之间共享。
