代码坏味道（上）：命名、函数与重复

“坏味道”是表面上的征兆，提示更深层的设计问题，它们本身不一定是错误。本课整理与命名、函数、重复相关的一组：神秘的名字、过长函数、过长参数列表、标识参数、死函数、重复代码、魔法数、基本类型偏执、数据泥团、长长的 if/elif 链、注释过多、临时字段。每个坏味道都给出识别方法和对应的重构手法。这些名字来自《代码整洁之道》第 17 章与 Fowler 的《重构》，两者高度重合。约 45 分钟。

坏味道识别常用手法


神秘的名字需要读实现才知道是什么改名（函数、变量、字段）


过长函数混合多个抽象层级；有“段落注释”提取函数；以查询取代临时变量；分解条件


过长参数列表≥ 4 个参数；同几个参数总一起传引入参数对象；保持对象完整；移除标识参数


重复代码改一处必须改另一处提取函数；上移方法；命名常量


基本类型偏执str/float 表示领域概念；格式与校验散落以对象取代基本类型（值对象）


数据泥团几个数据总是成群出现提取类


重复的 switch同样的类型分支出现在多处以多态取代条件；查表


死代码无调用者；不可达分支删除


注释（作为除臭剂）大段注释解释“这一段在做什么”提取函数；改名；引入断言

值对象：基于 Decimal，不可变，带币种，舍入与格式化集中在一处。
cat > money.py <<'EOF'
from dataclasses import dataclass
from decimal import Decimal, ROUND_HALF_UP

CENT = Decimal("0.01")

@dataclass(frozen=True)
class Money:
    amount: Decimal
    currency: str = "CNY"

    @classmethod
    def of(cls, value, currency="CNY"):
        return cls(Decimal(str(value)).quantize(CENT, ROUND_HALF_UP), currency)

    def __add__(self, other):
        self._require_same_currency(other)
        return Money(self.amount + other.amount, self.currency)

    def times(self, factor):
        return Money.of(self.amount * Decimal(str(factor)), self.currency)

    def __str__(self):
        symbol = {"CNY": "¥", "USD": "$"}.get(self.currency, self.currency + " ")
        return f"{symbol}{self.amount:,.2f}"

    def _require_same_currency(self, other):
        if other.currency != self.currency:
            raise ValueError(f"不能把 {other.currency} 加到 {self.currency}")
EOF

挑战
诊断一段代码
列出下面代码中的坏味道（至少 5 个）及对应手法：
def proc(o, flag, d1, d2):
    # 计算
    t = 0
    for i in o["items"]:
        t += i["p"] * i["q"]
    if o["type"] == 2:
        t = t * 0.95
    if flag:
        print("debug", t)
    # 检查日期
    if d1 > d2:
        return -1
    return round(t, 2)
查看参考答案
  • 神秘的名字：proc、o、t、d1/d2 → 改名。
  • 标识参数：flag 控制调试输出 → 删除，用日志级别控制。
  • 数据泥团：d1, d2 总是一起出现，是一个时间段 → DateRange，并在构造时校验 start ≤ end（异常而不是 -1）。
  • 魔法数：2（某种客户类型）、0.95 → 枚举与命名常量。
  • 基本类型偏执：dict 表示订单、float 表示金额 → Order、LineItem、Money。
  • 返回码：-1 与金额共用返回值 → 异常。
  • 段落注释（“# 计算”“# 检查日期”）→ 提取函数 subtotal(order)、DateRange。

小结
记住这几点


  1. 坏味道是提示，不是规则：它告诉你“值得看一眼”，是否修改取决于这段代码的变化频率和阅读频率。
  2. 神秘的名字、过长函数、过长参数列表：最常见的三个。对应手法：改名；提取函数；引入参数对象或保持对象完整（传 order 而不是 order.id, order.total, order.status）。
  3. 重复代码与魔法数：同一知识出现在多处。提取函数、命名常量、提升到共同的位置。
  4. 基本类型偏执：用 str、int、float 表示领域概念（金额、电话、货币代码、坐标）。校验和格式化逻辑因此散落各处。引入值对象：Money、PhoneNumber。
  5. 数据泥团：总是一起出现的几个数据（start_date, end_date；street, city, zipcode）。删除其中一个会让其他失去意义？那它们就是一个对象。
  6. 死代码与注释过多：没人调用的函数、永远为假的分支、注释掉的代码——删掉。需要大段注释解释的代码，先尝试用提取函数和改名让它自解释。
