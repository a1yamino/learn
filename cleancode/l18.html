遗留代码：特征测试与接缝

Michael Feathers 把遗留代码定义为“没有测试的代码”。要安全地修改它，首先要把它放进测试里，但它往往难以测试：直接连接数据库、读当前时间、调用外部服务。本课讲遗留代码修改算法（找到修改点 → 找到测试点 → 解除依赖 → 写测试 → 修改与重构），特征测试（记录现有行为，而不是“应有”的行为），接缝（不修改代码就能替换行为的位置），以及几种安全地解除依赖的手法：参数化、提取并覆盖、包装方法、萌芽方法 / 萌芽类、快照（golden master）测试。约 50 分钟。

03
特征测试的写法
让测试告诉你代码现在做什么。


  1. 写一个你知道会失败的断言：self.assertEqual(format_price(1234.5), "???")。
    2. 

  2. 运行，失败消息会告诉你实际值：AssertionError: '1,234.50 元' != '???'。
    3. 

  3. 把实际值填进去，测试变绿。这就是一个特征测试。
    4. 

  4. 为边界值重复：0、负数、很大的数、None。


如果实际行为看起来是错误的（例如负数被格式化成 "-0.00"），先记录它，在测试名中写明（test_negative_currently_formats_as_zero），再与业务方确认是否修复。在测试中固定下来的“bug”至少不会在重构中被意外改变。


快照测试是特征测试的批量版：把一批输入的输出保存为文件，之后与之比较。

查看参考答案
  • 汇率（HTTP）：参数接缝 run(self, fetch_rates=fetch_rates_from_api)，或构造函数注入一个 RateSource。
  • 产品（ORM）：注入 products 可迭代对象与 save 函数；或在第一步用 mock.patch。
  • 当前时间：日志里的时间不影响结果，可以不处理。
最小修改：用萌芽方法把计算提取为纯函数，并为它写测试：
def usd_price(price_cny, cny_per_usd):
    return round(price_cny / cny_per_usd, 2)
run() 中只改一行，改为调用 usd_price。I/O 仍在旧代码中，但最容易出错的计算已经有了测试；之后再逐步把 I/O 依赖改为注入。

小结
记住这几点


  1. 遗留代码 = 没有测试的代码。修改它的困境：要重构需要测试，要写测试需要先重构。出路是先做最小、最安全的结构修改（通常可借助编辑器自动完成），只为让测试成为可能。
  2. 特征测试：不问“应该输出什么”，而是问“现在输出什么”，并把它固定下来。哪怕现有行为看起来像 bug，也先记录；是否修复是另一个决定（可能有调用方依赖它）。
  3. 接缝：程序中可以不编辑该处代码就改变行为的地方。Python 中最常用的是对象接缝（传入替身）与参数接缝（给函数加一个带默认值的参数），以及测试时的 unittest.mock.patch（链接期接缝的类比）。
  4. 萌芽方法 / 萌芽类：新功能写在一个新的、经过测试的函数或类里，只在旧代码中加一行调用。旧代码不必先完全进入测试。
  5. 包装方法：需要在旧行为前后添加行为时，把旧方法改名，用原名写一个新方法调用它并加上新行为。
  6. 快照测试（golden master）：对复杂输出（报表、HTML）先保存当前输出作为基准，之后每次运行与之比对。适合在大规模重构前快速建立安全网。
