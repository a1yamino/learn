类：单一职责与内聚

类是比函数更大的组织单位。本课讲类的组织顺序与封装；“类应当短小”中的“短小”指的是职责而不是行数；单一职责原则（SRP）——一个类只应有一个引起它变化的原因，或者说只对一类“使用者”负责；内聚（方法使用了多少字段）如何指引拆分；为修改而组织（把变化隔离在新类中）。练习把一个“上帝类”按变化原因拆开。约 45 分钟。

03
SRP 的常见误解
“只做一件事”是函数的规则；SRP 讨论的是变化与人。


误解澄清


每个类只能有一个方法SRP 关心变化原因，不关心方法个数。Order 可以有十个方法。


拆得越细越好过度拆分会让一个变化需要同时修改五个类（“散弹式修改”，第 15 课）。拆分的边界应与变化的边界一致。


SRP 是关于代码的它关于组织：谁会要求修改它？两个不同的团队要求修改同一个类，就会产生冲突与意外。


书中用 SQL 生成器举例：一个 Sql 类包含 create()、insert()、select()……每新增一种语句都要修改它。重构为 Sql 抽象类与 CreateSql、SelectSql 等子类后，新增语句只需新增一个类，已有类不受影响。在 Python 中，同样的思想也可以用一组函数或一个注册表实现——重点是变化被隔离。

import ast, sys

tree = ast.parse(open(sys.argv[1]).read())
for cls in [n for n in tree.body if isinstance(n, ast.ClassDef)]:
    print(cls.name)
    for fn in [n for n in cls.body if isinstance(n, ast.FunctionDef) and n.name != "__init__"]:
        fields = sorted({a.attr for a in ast.walk(fn)
                         if isinstance(a, ast.Attribute) and isinstance(a.value, ast.Name)
                         and a.value.id == "self" and not a.attr.startswith("__")})
        print(f"  {fn.name:<18} {' '.join(fields)}")
EOF
02
一个“上帝类”。
cat > employee.py <<'EOF'
class Employee:
    def __init__(self, name, rate, hours, db):
        self.name, self.rate, self.hours, self.db = name, rate, hours, db

    def calculate_pay(self):
        return self.rate * min(self.hours, 40) + self.overtime()

    def overtime(self):
        return self.rate * 1.5 * max(0, self.hours - 40)

    def report_hours(self):
        return self.format_row()

    def format_row(self):
        return f"{self.name:<8}{self.hours:>4}h"

    def save(self):
        self.db[self.name] = (self.rate, self.hours)

    def load(self):
        self.rate, self.hours = self.db[self.name]
EOF

03
按变化原因拆开：数据、计算（财务）、报表（运营）、存储（技术）。
cat > employee.py <<'EOF'
from dataclasses import dataclass

STANDARD_WEEK_HOURS = 40
OVERTIME_MULTIPLIER = 1.5

@dataclass(frozen=True)
class Employee:
    name: str
    rate: float
    hours: float

class PayCalculator:
    def pay(self, e):
        regular = min(e.hours, STANDARD_WEEK_HOURS)
        overtime = max(0, e.hours - STANDARD_WEEK_HOURS)
        return e.rate * (regular + overtime * OVERTIME_MULTIPLIER)

class HourReporter:
    def row(self, e):
        return f"{e.name:<8}{e.hours:>4}h"

class EmployeeRepository:
    def __init__(self, db):
        self._db = db

    def save(self, e):
        self._db[e.name] = (e.rate, e.hours)

    def load(self, name):
        rate, hours = self._db[name]
        return Employee(name, rate, hours)
EOF

小结
记住这几点


  1. 短小的度量是职责：如果无法用 25 个词左右、不用“和”“或”“如果”描述一个类，它很可能承担了多个职责。Manager、Processor、Super 这类名字常常意味着职责模糊。
  2. 单一职责原则（SRP）：一个模块应当只有一个引起它变化的原因。Martin 后来的表述更精确：一个模块只对一个“角色”（一类利益相关者）负责——财务改的计算规则和运营改的报表格式不应在同一个类里互相影响。
  3. 许多小类，而不是几个大类：系统的复杂度是固定的；问题是你希望把工具放在一个个贴好标签的小抽屉里，还是全扔进一个大抽屉。
  4. 内聚：类的方法越多地使用同一组字段，内聚越高。如果一部分方法只用字段 a、b，另一部分只用 c、d，那里就藏着两个类。
  5. 拆分长函数常常会揭示新的类：提取方法时如果发现要传很多参数，或某几个局部变量总是一起出现，它们可能属于一个新类。
  6. 为修改而组织：新增一种 SQL 语句不应修改已有的语句类；每种变化落在一个新类里，旧实现通常无需修改，但新增实现仍需契约验证，相关调用路径仍需回归检查（这引出下一课的开闭原则）。
