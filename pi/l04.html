Provider 抽象、模型目录与凭据

pi-ai 内置 42 家提供方、约 1600 个聊天模型，却只用十来种 API 协议实现。秘诀是把三件事分开：Provider（谁：id、baseUrl、怎样鉴权、有哪些模型）、Api（怎么说话：openai-completions、anthropic-messages……的请求构造与流解析）、Model（目录里的一条记录：上下文窗口、价格、能力）。本课还会读凭据解析的规则：存储的凭据优先于环境变量，OAuth 令牌在过期前自动刷新。约 45 分钟。

  readonly id: string;
  readonly name: string;

  readonly baseUrl?: string;
  readonly headers?: ProviderHeaders;

   * Required: at least one of `apiKey`/`oauth`. Every provider has auth

if (stored) {
  if (stored.type === "oauth" && provider.auth.oauth) {

      credentials,
      provider.id,
      provider.auth.oauth,
      stored,

接入自己的服务
用 createProvider 写一个 provider：id myllm，baseUrl http://localhost:8080/v1，使用 openai-completions 协议，环境变量 MYLLM_API_KEY，一个模型 tiny（上下文 8192）。把它注册到 builtinModels() 返回的集合中，并验证 checkAuth。

import { createProvider, envApiKeyAuth } from "@earendil-works/pi-ai";
import { openAICompletionsApi } from "@earendil-works/pi-ai/api/openai-completions.lazy";
const myllm = createProvider({
  id: "myllm", name: "My LLM", baseUrl: "http://localhost:8080/v1",
  auth: { apiKey: envApiKeyAuth("My LLM key", ["MYLLM_API_KEY"]) },
  models: [{ id: "tiny", name: "tiny", api: "openai-completions", provider: "myllm",
    baseUrl: "http://localhost:8080/v1", reasoning: false, input: ["text"],
    cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
    contextWindow: 8192, maxTokens: 2048 }],
  api: openAICompletionsApi(),
});
models.setProvider(myllm);
process.env.MYLLM_API_KEY = "x";
console.log(await models.checkAuth("myllm"));
// { source: "MYLLM_API_KEY", type: "api_key" }
对比 groq.ts：形状完全一样。真实使用时更简单的办法是在 ~/.pi/agent/models.json 中声明（见 docs/models.md），无需写代码。模型对象的确切字段以 types.ts 中的 Model 类型为准；类型检查会提示缺少的字段。注意 openAICompletionsApi 来自子路径 api/openai-completions.lazy：协议实现按需懒加载，不用的协议（和它的 SDK）不会被导入。

小结
记住这几点


  1. Provider 接口（models.ts）：id、name、baseUrl、auth（apiKey 和/或 oauth）、getModels()、stream / streamSimple，可选 refreshModels（动态目录）、filterModels、图片与分类器。
  2. Provider ≠ Api：Groq、Cerebras、OpenRouter 等都复用 openAICompletionsApi()；一个新的 OpenAI 兼容服务只需十几行：id、baseUrl、环境变量名、模型列表。
  3. 模型目录：由 scripts/generate-models.ts 生成到 providers/data/*.json 与 *.models.ts，带上下文窗口、最大输出、价格、输入模态、是否推理模型。用户可在 models.json 中增加自定义提供方或模型。
  4. Models 集合：持有所有 provider，负责解析凭据并把请求委派给拥有该模型的 provider。getModels 列出全部，getAvailable 只列出已配置凭据的。
  5. 凭据解析顺序：调用方显式传入的 apiKey → 存储的凭据（auth.json，OAuth 或 API key）→ 环境变量等“环境凭据”。存储的凭据“拥有”该 provider：它存在时不会悄悄回退到环境变量。
  6. OAuth：剩余有效期不足 5 分钟就在凭据存储的锁内刷新并立即持久化（双重检查），避免多个进程同时刷新而作废 refresh token。auth.json 的 key 还可以写成 !命令，从密钥管理器读取。
