会话：JSONL 树、分支与恢复

pi 把每次对话保存为一个 JSONL 文件，但它不是线性日志，而是一棵树：每个条目有 id 与 parentId，“当前位置”是一个叶子指针。回到早先的某一步换个方向，只需把叶子指针移回去再追加——旧的分支原样保留在同一个文件里。本课阅读 session-manager.ts，亲手构造一棵会话树。约 50 分钟。

private _hasConversation(): boolean {
  return this.fileEntries.some(
    (e) => e.type === "message" && (e.message.role === "user" || e.message.role === "assistant"),
  );
}

_persist(entry: SessionEntry): void {
  if (!this.persist || !this.sessionFile) return;

  if (!this.flushed) {
    if (!this._hasConversation()) return;
    const fd = openSync(this.sessionFile, "wx");
    try {
      for (const e of this.fileEntries) {
        writeFileSync(fd, `${JSON.stringify(e)}\n`);
      }
    } finally {
      closeSync(fd);
    }
    this.flushed = true;
  } else {
    appendFileSync(this.sessionFile, `${JSON.stringify(entry)}\n`);
  }
}

private _appendEntry(entry: SessionEntry): void {
  this.fileEntries.push(entry);
  this.byId.set(entry.id, entry);
  this.leafId = entry.id;
  this._persist(entry);
}

/** Append a message as child of current leaf, then advance leaf. Returns entry id.
 * Does not allow writing CompactionSummaryMessage and BranchSummaryMessage directly.
 * Reason: we want these to be top-level entries in the session, not message session entries,
 * so it is easier to find them.
 * These need to be appended via appendCompaction() and appendBranchSummary() methods.
 */
appendMessage(message: Message | CustomMessage | BashExecutionMessage): string {
  const entry: SessionMessageEntry = {
    type: "message",
    id: generateId(this.byId),
    parentId: this.leafId,
    timestamp: new Date().toISOString(),
    message,
  };
  this._appendEntry(entry);
  return entry.id;
}

getBranch(fromId?: string): SessionEntry[] {
  const path: SessionEntry[] = [];
  const startId = fromId ?? this.leafId;
  let current = startId ? this.byId.get(startId) : undefined;
  while (current) {
    path.push(current);
    current = current.parentId ? this.byId.get(current.parentId) : undefined;
  }
  path.reverse();
  return path;
}

branch(branchFromId: string): void {
  if (!this.byId.has(branchFromId)) {
    throw new Error(`Entry ${branchFromId} not found`);
  }
  this.leafId = branchFromId;
}

小结
记住这几点


  1. 位置：~/.pi/agent/sessions/--<cwd 路径>--/<时间戳>_<id>.jsonl。第一行是 session 头（version 3、cwd 等），之后每行一个条目。旧版本文件加载时自动迁移。
  2. 条目类型：message（任意 AgentMessage）、model_change、thinking_level_change、usage、compaction、context_edit、branch_summary、custom（扩展的私有状态，不进上下文）、custom_message（扩展注入、进上下文）、label、session_info。
  3. 追加即前进：每个 appendXxx 都以当前叶子为父创建条目，并把叶子移到新条目。常规对话追加不改写已有分支；加载旧版本会话迁移时会调用 _rewriteFile()，因此这不是绝对的不可变存储。
  4. 延迟落盘：只有在出现第一条 user 或 assistant 消息时才创建文件（一次性写入之前缓存的条目），之后逐行 append。打开 pi 不说话就退出不会留下空会话。
  5. 分支：branch(id) 只是移动叶子指针；branchWithSummary 还会为被放弃的路径写一条摘要；getTree() 返回整棵树。界面上对应 /tree（在树中切换）、/fork（从某条用户消息新建会话文件）、/clone。
  6. 构建上下文：buildSessionContext() 从叶子走到根，得到当前路径；遇到压缩条目时用摘要替换更早的部分；应用 context_edit；同时恢复路径上最后的模型与思考级别。其他分支对模型不可见。
  7. 恢复：pi -c 继续最近的会话，pi -r / /resume 选择会话；SessionManager.open(path) 读取文件，叶子指向最后一个条目。
