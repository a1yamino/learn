pi · 第 15 课

扩展系统：工具、命令与事件钩子

pi 的核心刻意保持很小，几乎所有“额外”的能力——权限确认、子 agent、计划模式、MCP、自定义 UI——都应该由扩展实现。扩展就是一个导出默认函数的 TypeScript 文件，函数接收 ExtensionAPI，可以注册工具、命令、快捷键、提供方，订阅三十多种生命周期事件，并在会话中保存自己的状态。本课写一个小小的“guard”扩展，覆盖最常用的五种能力。约 55 分钟。

private _installAgentToolHooks(): void {
  this.agent.beforeToolCall = (context) => this._beforeToolCall(context);
  this.agent.afterToolCall = (context) => this._afterToolCall(context);
}

/** `tool_call` handlers. `parentToolCallId` is set for calls another tool made. */
private async _beforeToolCall(
  { toolCall, args }: BeforeToolCallContext,
  parentToolCallId?: string,
): Promise<BeforeToolCallResult | undefined> {
  const runner = this._extensionRunner;
  if (!runner.hasHandlers("tool_call")) {
    return undefined;
  }

  try {
    return await runner.emitToolCall({
      type: "tool_call",
      toolName: toolCall.name,
      toolCallId: toolCall.id,
      ...(parentToolCallId ? { parentToolCallId } : {}),
      input: args as Record<string, unknown>,
    });
  } catch (err) {
    if (err instanceof Error) {
      throw err;
    }
    throw new Error(`Extension failed, blocking execution: ${String(err)}`);
  }
}

01
写脚本并运行。
cat > scratch/l15.ts <<'EOF'
import { fauxAssistantMessage, fauxToolCall } from "@earendil-works/pi-ai/compat";
import { fauxSession } from "./faux-session.ts";

// 一个项目扩展：注册工具、注册命令、拦截危险命令、改写输入、保存状态
const extension = `
import { Type } from "typebox";
export default function (pi) {
  let calls = 0;
  pi.registerTool({
    name: "today", label: "today", description: "返回今天的日期",
    parameters: Type.Object({}),
    async execute() { calls++; return { content: [{ type: "text", text: "2026-10-22" }], details: undefined }; },
  });
  pi.registerCommand("stats", {
    description: "显示扩展统计",
    handler: async (_args, ctx) => { console.log("[/stats] today 被调用", calls, "次；当前模型", ctx.model?.id); },
  });
  pi.on("tool_call", async (event) => {
    if (event.toolName === "bash" && /\\brm\\s+-rf\\b/.test(event.input.command)) return { block: true, reason: "guard 扩展：禁止 rm -rf" };
  });
  pi.on("input", async (event) => {
    if (event.text.startsWith("!!")) return { action: "transform", text: "请用一句话回答：" + event.text.slice(2) };
  });
  pi.on("agent_settled", async () => { pi.appendEntry("guard-stats", { calls }); });
}`;

const { session } = await fauxSession([
  fauxAssistantMessage([fauxToolCall("today", {}), fauxToolCall("bash", { command: "rm -rf build" })], { stopReason: "toolUse" }),
  fauxAssistantMessage("今天是 2026-10-22，删除被拒绝了。"),
], { files: { ".pi/extensions/guard.ts": extension } });

console.log("活动工具:", session.agent.state.tools.map((t) => t.name).join(", "));
await session.prompt("!!今天几号？顺便清理 build");
for (const m of session.messages as any[]) {
  if (m.role === "user") console.log("user       ", m.content[0].text);
  if (m.role === "toolResult") console.log("toolResult ", m.toolName, m.isError ? "(错误)" : "", m.content[0].text);
}
await session.prompt("/stats");
const custom = session.sessionManager.getEntries().filter((e: any) => e.type === "custom");
console.log("custom 条目:", JSON.stringify(custom.map((e: any) => ({ customType: e.customType, data: e.data }))));
console.log("/stats 产生了发给模型的消息吗？", session.messages.some((m: any) => m.role === "user" && JSON.stringify(m.content).includes("stats")));
session.dispose();
EOF

权限确认扩展
写一个扩展：对 bash 工具，命令匹配 git push|npm publish|rm -rf 时调用 ctx.ui.confirm() 询问用户，拒绝则 block。在 print 模式（没有交互 UI）下应该怎么处理才安全？
查看参考答案
export default function (pi) {
  const risky = /\b(git push|npm publish|rm -rf)\b/;
  pi.on("tool_call", async (event, ctx) => {
    if (event.toolName !== "bash" || !risky.test(event.input.command)) return;
    if (!ctx.hasUI) return { block: true, reason: "非交互模式下禁止高风险命令" };
    const ok = await ctx.ui.confirm("允许执行？", event.input.command);
    if (!ok) return { block: true, reason: "用户拒绝" };
  });
}
没有 UI 时默认拒绝（fail closed）：print/JSON 模式常用于脚本和 CI，无人值守时宁可阻止。注意正则只是启发式，git  push、sh -c 包装、别名都可能绕过；它防的是模型的失误，不是恶意。确切的 API（例如 ctx.hasUI）以 extensions/types.ts 中的 ExtensionContext 为准；examples/extensions 中有完整的权限示例可参考。

小结
记住这几点


  1. 加载：~/.pi/agent/extensions/、项目 .pi/extensions/（需信任）、pi 包、pi --extension ./x.ts。通过 jiti 直接加载 TypeScript，无需编译；typebox、@earendil-works/pi-* 等导入被映射到 pi 自带的模块（virtual modules），扩展不需要自己安装它们。
  2. 注册：registerTool（与内置工具同样的形状，可设置 exposure：direct / model-only / codemode / deferred / hidden）、registerCommand、registerShortcut、registerFlag、registerProvider、registerToolRenderer。
  3. 事件：输入（input 可改写或消费）、before_agent_start（改提示段落、工具）、context（每次请求前过滤消息）、提供方请求/响应、tool_call（可 block）、tool_result（可改写）、turn_end、agent_before_settle、agent_settled、会话事件（start、switch、fork、compact、shutdown）等。
  4. 与循环的连接：AgentSession 把 Agent 的 beforeToolCall/afterToolCall 钩子接到扩展的 tool_call/tool_result 事件上——第 7 课看到的钩子正是扩展的入口。处理器抛错会阻止工具执行（失败即关闭）。
  5. 状态与消息：appendEntry 写 custom 条目（持久化、不进上下文）；sendMessage 注入自定义消息（进上下文）；sendUserMessage 以用户身份发送。
  6. UI：ctx.ui 提供 notify、confirm、select、input、自定义组件等；在 print/RPC 模式下有对应的降级或协议实现。
  7. 生命周期纪律：工厂函数中不要启动进程、定时器；在 session_start 中启动，在 session_shutdown 中清理。reload 会替换整个扩展运行时。
