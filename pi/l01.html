pi 是什么：极简 agent harness 与 monorepo 地图

pi 是 Mario Zechner（badlogic）开源的编码 agent。它的定位是“极简、可扩展的 agent harness”：只提供构建编码 agent 所必需的内核——统一的模型接口、agent 循环、少量强大的工具、会话与上下文管理——其余能力（子 agent、计划模式、沙箱……）都交给扩展。正因为小，它是学习“编码 agent 是怎样构建的”最好的起点。本课介绍整门课的方法（固定提交、读真实代码、用 faux 模型离线练习），画出 monorepo 的包结构与依赖方向，并找到 CLI 的入口。约 45 分钟。

packages/coding-agent/src/main.ts  L112–123 ↗
function resolveAppMode(parsed: Args, stdinIsTTY: boolean, stdoutIsTTY: boolean): AppMode {
  if (parsed.mode === "rpc") {
    return "rpc";
  }
  if (parsed.mode === "json") {
    return "json";
  }
  if (parsed.print || !stdinIsTTY || !stdoutIsTTY) {
    return "print";
  }
  return "interactive";
}

第一个程序：用 faux 模型驱动真实的 Agent。模型被“脚本化”：第一次回复调用 add 工具，第二次给出答案。
mkdir -p scratch && cat > scratch/hello.ts <<'EOF'
import { Type } from "@earendil-works/pi-ai";
import { fauxAssistantMessage, fauxText, fauxToolCall, registerFauxProvider, streamSimple } from "@earendil-works/pi-ai/compat";
import { Agent } from "@earendil-works/pi-agent-core";

const faux = registerFauxProvider();
faux.setResponses([
  fauxAssistantMessage([fauxText("我来算一下。"), fauxToolCall("add", { a: 2, b: 3 })], { stopReason: "toolUse" }),
  fauxAssistantMessage("结果是 5。"),
]);

const add = {
  name: "add", label: "add", description: "两数相加",
  parameters: Type.Object({ a: Type.Number(), b: Type.Number() }),
  execute: async (_id: string, p: { a: number; b: number }) =>
    ({ content: [{ type: "text" as const, text: String(p.a + p.b) }], details: {} }),
};

const agent = new Agent({
  streamFn: streamSimple,
  initialState: { systemPrompt: "你是助手", model: faux.getModel(), thinkingLevel: "off", tools: [add] },
});
agent.subscribe((e) => { if (e.type !== "message_update") console.log("事件", e.type); });
await agent.prompt("2+3=?");
for (const m of agent.state.messages) console.log(m.role.padEnd(10), JSON.stringify(m.content).slice(0, 70));
EOF

挑战
读入口
在 packages/coding-agent/src/main.ts 中找到：① --offline 标志在哪里被处理、它影响了什么；② 从标准输入读取内容时（echo "..." | pi），交互模式会变成什么模式。给出行号。
查看参考答案
  1. 约第 579 行：const offlineMode = args.includes("--offline") || isTruthyEnvFlag(process.env.PI_OFFLINE)。之后它决定是否在启动时刷新模型目录（例如第 940 行附近，RPC 模式下 if (!offlineMode && appMode === "rpc") 才会后台刷新），避免离线环境中等待网络。
  2. 约第 896–900 行：读到标准输入内容且原本是 interactive 时，appMode = "print"。（另外 resolveAppMode 在 stdin 不是 TTY 时本来就会返回 print。）
读源码的技巧：先用 grep -n 找标识符，再读周围 30 行；不要只看搜索片段就下结论（这也是仓库 AGENTS.md 的要求）。

小结
记住这几点


  1. pi 的定位：一个最小但完整的编码 agent 内核。README 明言它刻意不内置子 agent 和计划模式，鼓励用扩展、技能、提示模板与包来定制。这让它成为理解编码 agent 本质的理想样本；Codex 课程会在同样的骨架上看一个更“全功能”的实现。
  2. 三层核心包：pi-ai（统一的 LLM API：消息、流式事件、provider）→ pi-agent-core（agent 循环与工具执行，与具体应用无关）→ pi-coding-agent（编码工具、会话、压缩、扩展、TUI 与 CLI）。依赖只朝一个方向。
  3. 周边包：pi-tui（差分渲染的终端 UI 库）、pi-mcp（独立的 MCP 客户端）、pi-codemode（只能调用注入工具的沙箱 JS 执行）、pi-durable/pi-env/chord（持久化运行时与远程执行环境，本课程只简单提及）。
  4. 入口：packages/coding-agent/src/cli.ts 调用 main()；main.ts 解析参数、决定运行模式（interactive / print / json / rpc），通过 SDK 创建 agent 会话，然后把会话交给对应模式。“The SDK does the heavy lifting”——CLI 只是 SDK 的一个使用者。
  5. 学习方法：本课程所有代码摘录都链接到固定提交 db77405 的源码行；练习使用仓库自带的 faux provider（脚本化的假模型），无需 API key、无需联网即可驱动真实的 agent 循环。
  6. 源码约定值得一读：仓库根目录的 AGENTS.md 是写给编码 agent 的开发规则（也约束了人类贡献者）：只用可擦除的 TypeScript 语法（Node 可直接运行 .ts）、测试用 faux provider、不在代码中写死按键……这些约定在后面的课里会反复出现。
