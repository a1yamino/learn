工具调用：参数校验、并行执行与钩子

模型在一条回复里可能请求多个工具。agent 循环要回答一连串问题：工具存在吗？参数合法吗？可以执行吗（权限钩子）？并行还是顺序？执行抛异常怎么办？结果要不要改写？本课精读 agent-loop.ts 中从 executeToolCalls 到 finalizeExecutedToolCall 的全过程，以及 validateToolArguments。约 55 分钟。

async function executeToolCalls(
  currentContext: AgentContext,
  assistantMessage: AssistantMessage,
  config: AgentLoopConfig,
  signal: AbortSignal | undefined,
  emit: AgentEventSink,
): Promise<ExecutedToolCallBatch> {
  const toolCalls = assistantMessage.content.filter((c) => c.type === "toolCall");
  const hasSequentialToolCall = toolCalls.some(
    (tc) => currentContext.tools?.find((t) => t.name === tc.name)?.executionMode === "sequential",
  );
  if (config.toolExecution === "sequential" || hasSequentialToolCall) {
    return executeToolCallsSequential(currentContext, assistantMessage, toolCalls, config, signal, emit);
  }
  return executeToolCallsParallel(currentContext, assistantMessage, toolCalls, config, signal, emit);
}

一个确认钩子
写一个 beforeToolCall：对 sh 工具，命令中含有 git push 时阻止并返回 “需要人工确认”，其他命令放行。如果模型在同一条回复中请求了 git status 和 git push，两个工具的结果分别是什么？下一次模型请求会发生吗？
查看参考答案
beforeToolCall: async ({ toolCall, args }) =>
  toolCall.name === "sh" && /\bgit push\b/.test((args as any).cmd)
    ? { block: true, reason: "需要人工确认" }
    : undefined,
结果：git status 正常执行；git push 得到 isError 结果“需要人工确认”。下一次模型请求会发生（模型看到被拒绝，可以向用户解释）。只有当批次中所有结果都带 terminate:true（可以在 block 时设置 terminate:true）时，循环才会停下。注意：钩子拿到的是校验后的参数；真正的权限系统还要考虑命令的各种变形（git  push、别名、sh -c），这是第 19 课和 Codex 的 execpolicy 要面对的问题。

小结
记住这几点


  1. 工具的形状（AgentTool）：name、label、description、parameters（TypeBox/JSON Schema）、execute(id, args, signal, onUpdate)，可选 prepareArguments（兼容旧参数形状）与 executionMode。
  2. 准备阶段（prepareToolCall）：查找工具（找不到 → “Tool X not found”）→ prepareArguments → validateToolArguments（先按 schema 做类型转换，如 "300"→300，再校验；失败 → “Validation failed…”，附上收到的参数）→ beforeToolCall 钩子（可 block，附 reason）。任何一步失败都直接产生错误结果，不执行。
  3. 执行阶段：execute 抛出的异常被捕获为错误结果；执行中可通过 onUpdate 推送部分结果（tool_execution_update 事件，例如 bash 的实时输出）。
  4. 收尾阶段：afterToolCall 钩子可以替换 content、details、isError——例如审计、脱敏、追加提示。
  5. 并行是默认：各工具按顺序做准备（因此 beforeToolCall 依次被调用），然后并发执行；结果消息按原始顺序发出。配置 toolExecution:"sequential"，或批次中任一工具声明 executionMode:"sequential"，则整批顺序执行。
  6. 提前终止：只有当批次中每个结果都带 terminate:true 时，循环才在这批之后停止（不再请求模型）。
  7. runToolCall：工具调用其他工具（例如 codemode 脚本）时走同一条路径，所以权限钩子同样生效。
