bash 工具：进程、输出截断与中止

bash 是编码 agent 最强大的工具：编译、测试、git、包管理都靠它。pi 的实现（core/tools/bash.ts，442 行）要解决的是进程管理的老问题：合并 stdout/stderr、保留输出的尾部（错误通常在最后）、把完整输出存到临时文件、超时与中止时杀掉整棵进程树、执行中流式推送输出给界面。注意 pi 默认不做任何沙箱：命令以你的用户权限直接运行。约 50 分钟。

cat > pi-mono/scratch/l11.ts <<'EOF'
import { mkdtempSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { createBashTool } from "@earendil-works/pi-coding-agent";

const dir = mkdtempSync(join(tmpdir(), "l11-"));
const bash = createBashTool(dir);
const short = (t: string) => t.replace(/\/tmp\/[^\s\]]+/g, "<临时文件>");

async function run(title: string, args: any, opts: { abortAfter?: number; updates?: boolean } = {}) {
  const ac = new AbortController();
  if (opts.abortAfter) setTimeout(() => ac.abort(), opts.abortAfter);
  let n = 0;
  const t = performance.now();
  try {
    const r: any = await bash.execute("id", args, ac.signal, opts.updates ? () => { n++; } : undefined);
    const lines = r.content[0].text.split("\n");
    console.log(`== ${title}${r.isError ? "（isError）" : ""}`);
    console.log("  " + (lines.length > 5 ? [lines[0], "  …", ...lines.slice(-3)] : lines).map(short).join("\n  "));
    if (r.structuredContent) console.log(`  structured: exit_code=${r.structuredContent.exit_code} truncated=${r.structuredContent.truncated}`);
  } catch (e) {
    console.log(`== ${title}（抛出）\n  ` + short((e as Error).message).split("\n").join("\n  "));
  }
  console.log(`  用时约 ${Math.round((performance.now() - t) / 100) / 10}s` + (opts.updates ? `，收到部分输出更新 ${n > 1 ? "多" : n} 次` : ""));
}

await run("成功", { command: "echo hi; echo err >&2" });
await run("非零退出码", { command: "ls /nope" });
await run("大量输出", { command: "seq 1 5000" });
await run("超时", { command: "echo start; sleep 5", timeout: 1 });
await run("中止（含子进程）", { command: "sleep 30 & sleep 30; echo never" }, { abortAfter: 300 });
await run("流式更新", { command: "for i in 1 2 3; do echo $i; sleep 0.3; done" }, { updates: true });
EOF

用 spawnHook 加一层保护
使用 createBashTool(dir, { spawnHook })：把每条命令包装成 timeout 60 bash -c <原命令> 并设置环境变量 PI_AGENT=1。再思考：这能算沙箱吗？
查看参考答案
const bash = createBashTool(dir, {
  spawnHook: (ctx) => ({
    ...ctx,
    command: `timeout 60 bash -c ${JSON.stringify(ctx.command)}`,
    env: { ...ctx.env, PI_AGENT: "1" },
  }),
});
await bash.execute("1", { command: "echo $PI_AGENT" }); // 1
这不是沙箱：命令仍以你的用户权限运行，可以读写任何你能访问的文件、访问网络。spawnHook 只是改写“怎么启动”。真正的隔离需要操作系统机制——把命令放进容器（pi 文档 containerization.md 的做法），或像 Codex 那样用 Seatbelt/Landlock 限制文件系统与网络。JSON.stringify 在这里只是演示用的引号处理，并不是可靠的 shell 转义。

小结
记住这几点


  1. 参数：command 与可选的 timeout（秒，默认无超时，有上限）。命令在 cwd 中通过 shell 执行；非 Windows 平台以 detached 方式启动，使其成为独立进程组。
  2. 输出：stdout 与 stderr 按到达顺序合并；OutputAccumulator 保留最后 2000 行或 50KB（truncateTail，与 read 相反），被截断时完整输出写入临时文件，并提示 [Showing lines 3001-5000 of 5000. Full output: …]。
  3. 退出码：非 0 时结果标记 isError 并附 Command exited with code N；被信号杀死时按 shell 惯例使用 128+信号值。
  4. 超时与中止：都调用 killProcessTree 杀掉整个进程组（包括后台子进程），然后抛出带已收集输出的错误：Command timed out after N seconds 或 Command aborted。
  5. 流式更新：通过 onUpdate 推送部分输出（有节流），TUI 因此能实时显示命令输出；还会生成 structuredContent（output、exit_code、wall_time_seconds），供 codemode 等程序化调用者使用。
  6. 可定制：commandPrefix（如先 source 某个环境）、spawnHook（改写命令/cwd/env，例如包一层容器或沙箱）、可替换的 operations（远程执行）。
