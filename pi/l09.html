pi · 第 9 课

编码工具集：read、write、ls、grep、find

pi 默认只给模型四个工具：read、bash、edit、write；另有只读的 grep、find、ls 可按需启用。每个工具都是一个普通的 ToolDefinition：TypeBox 参数、写给模型看的描述、一个 execute。真正的工程细节在于输出给模型的文字：截断规则、“如何继续”的提示、错误信息——它们决定了模型能否高效地自己往下走。本课阅读 read、write、grep、find、ls 的实现并逐个调用它们。约 50 分钟。

同一文件的修改串行化：
packages/coding-agent/src/core/tools/file-mutation-queue.ts  L28–61 ↗
/**
 * Serialize file mutation operations targeting the same file.
 * Operations for different files still run in parallel.
 */
export async function withFileMutationQueue<T>(filePath: string, fn: () => Promise<T>): Promise<T> {
  const registration = registrationQueue.then(async () => {
    const key = await getMutationQueueKey(filePath);
    const currentQueue = fileMutationQueues.get(key) ?? Promise.resolve();

    let releaseNext!: () => void;
    const nextQueue = new Promise<void>((resolveQueue) => {
      releaseNext = resolveQueue;
    });
    const chainedQueue = currentQueue.then(() => nextQueue);
    fileMutationQueues.set(key, chainedQueue);

    return { key, currentQueue, chainedQueue, releaseNext };
  });
  registrationQueue = registration.then(
    () => undefined,
    () => undefined,
  );

  const { key, currentQueue, chainedQueue, releaseNext } = await registration;
  await currentQueue;
  try {
    return await fn();
  } finally {
    releaseNext();
    if (fileMutationQueues.get(key) === chainedQueue) {
      fileMutationQueues.delete(key);
    }
  }
}

const [read, write, ls, grep, find] = [createReadTool, createWriteTool, createLsTool, createGrepTool, createFindTool].map((f) => f(dir));

async function call(tool: any, args: any) {
  try {
    const r = await tool.execute("id", args);
    const t = r.content.map((c: any) => c.text).join("");
    const lines = t.split("\n");
    const shown = lines.length > 6 ? [...lines.slice(0, 2), `  …(${lines.length - 4} 行)…`, ...lines.slice(-2)] : lines;
    console.log(`> ${tool.name}(${JSON.stringify(args)})\n  ` + shown.join("\n  "));
  } catch (e) { console.log(`> ${tool.name}(${JSON.stringify(args)})\n  抛出: ${(e as Error).message}`); }
}

await call(write, { path: "build/out.js", content: "const add = 1;\n" });
await call(read, { path: "big.txt" });
await call(read, { path: "big.txt", offset: 10, limit: 3 });
await call(read, { path: "nope.txt" });
await call(ls, { path: "." });
await call(grep, { pattern: "add", path: "." });
await call(find, { pattern: "**/*.ts" });
// 变成 git 仓库后，ripgrep 才会遵守 .gitignore
(await import("node:child_process")).execSync("git init -q --template=", { cwd: dir });
console.log("-- git init 之后 --");
await call(grep, { pattern: "add", path: "." });

小结
记住这几点


  1. 工具集：createCodingTools = read、bash、edit、write（默认）；createReadOnlyTools = read、grep、find、ls；所有工具都可以指定 cwd，并可替换底层 operations（例如通过 SSH 操作远程机器）。
  2. read：参数 path、offset（从 1 开始）、limit。文本输出最多 2000 行或 50KB；被截断时附上 [Showing lines 1-2000 of 2500. Use offset=2001 to continue.]；单行超过 50KB 时建议改用 bash 的 sed。图片作为附件返回，可自动缩放；当前模型不支持图片时会附注说明。
  3. write：自动创建父目录；通过 withFileMutationQueue 对同一文件（按 realpath）的修改串行化，不同文件仍并行——并行工具执行（第 7 课）不会让两次写入交错。
  4. grep：调用 ripgrep（--json --hidden --no-config），默认最多 100 条匹配，长行截断到 500 字符，结果附“如何获取更多”的提示。遵守 .gitignore（ripgrep 只在 git 仓库内应用 .gitignore）。
  5. find：调用 fd 按 glob 查找，默认最多 1000 条。ls：列目录，目录名带 /，包含点文件。
  6. 外部二进制：ensureTool("rg"|"fd") 先找系统中的，找不到就下载到 ~/.pi/agent/bin；离线模式下跳过下载。
  7. 系统提示贡献：每个工具都带 promptSnippet 与 promptGuidelines（如“Use read to examine files instead of cat or sed.”），被拼进系统提示的 tools 段（第 12 课）。
