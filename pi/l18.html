运行模式：交互、print/JSON、RPC 与 SDK

同一个 AgentSession 可以挂在四种“外壳”上：交互式 TUI、一次性的 print 模式（纯文本或 JSON 事件流）、通过 stdin/stdout 交换 JSONL 的 RPC 模式，以及直接在你的程序里 createAgentSession() 的 SDK。本课用一个离线的 faux 扩展驱动真实的 pi CLI，亲眼看三种模式的输出。约 40 分钟。

function resolveAppMode(parsed: Args, stdinIsTTY: boolean, stdoutIsTTY: boolean): AppMode {
  if (parsed.mode === "rpc") {
    return "rpc";
  }
  if (parsed.mode === "json") {
    return "json";
  }
  if (parsed.print || !stdinIsTTY || !stdoutIsTTY) {
    return "print";
  }
  return "interactive";
}

function toPrintOutputMode(appMode: AppMode): Exclude<Mode, "rpc"> {
  return appMode === "json" ? "json" : "text";
}

RPC 的 prompt 命令：
packages/coding-agent/src/modes/rpc/rpc-mode.ts  L394–414 ↗
case "prompt": {
  // Start prompt handling immediately, but emit the authoritative response only after
  // prompt preflight succeeds. Queued and immediately handled prompts also count as success.
  let preflightSucceeded = false;
  void session
    .prompt(command.message, {
      images: command.images,
      streamingBehavior: command.streamingBehavior,
      source: "rpc",
      preflightResult: (disposition) => {
        preflightSucceeded = true;
        output(success(id, "prompt", { disposition }));
      },
    })
    .catch((e) => {
      if (!preflightSucceeded) {
        output(error(id, "prompt", e.message));
      }
    });
  return undefined;
}

05
在你的电脑上练习
先写一个只注册 faux 模型的扩展（这样不需要 API key），再用 -e 加载它运行真正的 pi CLI。注意 print 模式会读取管道输入，因此用 </dev/null 关闭 stdin。需要先在 pi-mono 根目录执行过 npm run build。


01
faux 扩展。
cat > pi-mono/scratch/faux-ext.ts <<'EOF'
// 课程练习用扩展：为 pi CLI 注册一个离线的 faux 模型（无需 API key）
import { fauxAssistantMessage, fauxToolCall, registerFauxProvider } from "@earendil-works/pi-ai/compat";

export default function (pi: any) {
  const faux = registerFauxProvider();
  faux.setResponses([
    fauxAssistantMessage([fauxToolCall("bash", { command: "echo 来自 bash 的输出" })], { stopReason: "toolUse" }),
    fauxAssistantMessage("完成：bash 输出了一行文字。"),
  ]);
  pi.registerProvider("faux", {
    baseUrl: "http://localhost:0", apiKey: "faux-key", api: faux.api,
    models: faux.models.map((m: any) => ({ id: m.id, name: m.name, reasoning: false, input: ["text"],
      cost: m.cost, contextWindow: m.contextWindow, maxTokens: m.maxTokens })),
  });
}
EOF
02
三种模式。
cat > pi-mono/scratch/l18.sh <<'EOF'
#!/bin/bash
# 同一个 AgentSession，三种运行模式（用 faux 扩展离线运行，无需 API key）
CLI="node $PWD/../packages/coding-agent/dist/cli.js"
EXT="$PWD/faux-ext.ts"
export HOME=$(mktemp -d); cd "$(mktemp -d)"
PI="$CLI --no-session -e $EXT --model faux/faux-1"

echo "== 1. print 模式（-p）：只打印最后的回答"
$PI -p "运行一个命令" </dev/null

echo "== 2. json 模式：每个事件一行 JSON（这里只列出事件类型）"
$PI --mode json -p "运行一个命令" </dev/null | grep -o '^{"type":"[a-z_]*"' | cut -d'"' -f4 | tr '\n' ' '; echo

echo "== 3. rpc 模式：stdin 发命令，stdout 收响应和事件"
(echo '{"id":"1","type":"prompt","message":"运行一个命令"}'; sleep 2
 echo '{"id":"2","type":"get_last_assistant_text"}'; sleep 1) \
 | $PI --mode rpc | grep '"type":"response"'
EOF
cd pi-mono/scratch && bash l18.sh

挑战
RPC 中途 steer
修改 RPC 部分：faux 的第一条响应改为调用 bash 执行 sleep 1；在发送 prompt 后 0.3 秒发送 {"type":"steer","message":"改为列出文件"}。观察 steer 的响应和后续事件中出现的用户消息。
查看参考答案
(echo '{"id":"1","type":"prompt","message":"开始"}'; sleep 0.3
 echo '{"id":"2","type":"steer","message":"改为列出文件"}'; sleep 3) \
 | $PI --mode rpc | grep -E '"response"|"role":"user"' | cut -c1-120
steer 立即得到 success 响应；消息进入转向队列，在当前工具调用结束后、下一次模型调用之前注入（第 2、8 课的机制），所以你会在 tool_execution_end 之后看到这条用户消息。faux 的响应列表需要多准备一条，供 steer 之后的那次调用使用。

小结
记住这几点


  1. 模式选择：resolveAppMode —— 显式 --mode rpc → RPC；有 -p、--mode json，或 stdin/stdout 不是终端 → print；否则交互。管道输入的内容会作为首条消息并切换到 print。
  2. print 模式（print-mode.ts，173 行）：发出初始消息，等待 agent 结束；text 模式只打印最后一条助手文本，json 模式把每个会话事件写成一行 JSON（先输出会话头）。
  3. RPC 模式（rpc-mode.ts）：每行一个命令 {id,type,…}，响应 {id,type:"response",command,success,data}，事件同时流出。命令有 prompt/steer/follow_up/abort、模型与思考级别、compact、bash、会话 fork/clone/切换、get_state/get_messages 等。rpc-client.ts 提供类型化客户端，IDE 插件可直接用。
  4. prompt 的响应时机：RPC 在预检通过后才回复 success（disposition: started/queued…），而不是在 agent 结束时；结束靠事件 agent_end/agent_settled 判断。
  5. SDK：createAgentSession() 返回同一个 AgentSession；前面各课的 faux-session 就是 SDK 用法。
  6. 扩展也能注册模型提供方：pi.registerProvider()，本课的 faux 扩展就是例子。
