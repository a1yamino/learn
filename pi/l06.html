挑战
实现“最多 N 个 turn”
用 finishTurn 实现一个上限：第 3 个 turn 结束时停止运行，即使模型还想调用工具。用“无限调用工具”的脚本化模型（准备 10 条工具调用回复）验证模型只被请求 3 次。
查看参考答案
let turns = 0;
await run("上限 3", Array.from({ length: 10 }, (_, i) => call(String(i))), {
  finishTurn: async () => (++turns >= 3 ? { action: "end" } : undefined),
});
// == 上限 3：模型请求 3 次
//    新消息: system, user, assistant(toolUse), toolResult ×3 组
finishTurn 在工具结果已经发出之后、turn_end 之前调用；返回 {action:"end"} 时循环发出 agent_end 并返回，不读任何队列。返回 undefined 保持正常调度。注意转录仍然一致：最后一个工具调用有对应的结果。

小结
记住这几点


  1. 入口：runAgentLoop(prompts, context, config, emit, signal, streamFn) 发出 agent_start、turn_start 和提示消息，然后进入 runLoop。runAgentLoopContinue 从现有上下文继续（最后一条不能是 assistant）。
  2. 内层循环条件：hasMoreToolCalls || pendingMessages.length > 0。每圈：（非首圈）prepareNextTurn 钩子 → 把排队的消息写入上下文 → prepareRequest 钩子 → streamAssistantResponse → 执行工具 → finishTurn 钩子 → turn_end → 读 steering 队列。
  3. 硬退出：stopReason 为 error 或 aborted 时立即 turn_end + agent_end 并返回，不执行任何工具。
  4. 截断保护：stopReason 为 length 时，消息中的所有工具调用都被判为失败（可能带着被截断的参数，例如 rm -rf /tm），模型在下一轮看到错误结果。
  5. 外层循环：内层结束（没有工具调用、没有 steering）时读 follow-up 队列；有就作为 pending 继续；finishTurn 返回 continue 时额外跑一个只基于上下文的 turn；否则退出并发出 agent_end。
  6. streamAssistantResponse：transformContext（AgentMessage 层面的变换，如裁剪）→ convertToLlm（过滤/转换自定义消息）→ 每次请求重新解析 API key（应对过期令牌）→ 把 partial 消息放进上下文并随事件不断替换 → done/error 时换成最终消息并发出 message_end。
  7. 工具声明：declareToolChanges 比较“转录中已声明的工具”与 context.tools，差异作为 system 消息（toolsAdded/toolsRemoved）插入。所以练习输出的新消息里第一条是 system。
