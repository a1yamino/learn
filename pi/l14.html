上下文压缩（compaction）

长时间工作的 agent 迟早会撑满上下文窗口。pi 的办法是压缩：用模型把较早的对话总结成一份结构化的“检查点”，保留最近的若干消息原文，之后发给模型的就是“系统提示 + 摘要 + 近期消息”。原始消息仍完整留在会话文件里。本课阅读 core/compaction/compaction.ts（1104 行），并用 faux 模型扮演“摘要器”，亲眼看到压缩时发出的请求。约 55 分钟。

export function shouldCompact(contextTokens: number, contextWindow: number, settings: CompactionSettings): boolean {
  if (!settings.enabled) return false;
  return contextTokens > contextWindow - settings.reserveTokens;
}

import { fauxAssistantMessage } from "@earendil-works/pi-ai/compat";
import { fauxSession } from "./faux-session.ts";

const long = (s: string) => s + "。" + "细节".repeat(2000);
const brief = (m: any) => m.role === "compactionSummary" ? `compactionSummary  ${m.summary.replace(/\n+/g, " ").slice(0, 70)} …` : `${m.role.padEnd(18)} ${(typeof m.content === "string" ? m.content : m.content.map((c: any) => c.text ?? "").join("")).replace(/(细节)+/g, "细节…").slice(0, 40)}`;
const seen: string[] = [];
const summarizer = (ctx: any) => {
  const last = ctx.messages.at(-1);
  const text = typeof last.content === "string" ? last.content : last.content.map((c: any) => c.text).join("");
  seen.push(text.replace(/(细节)+/g, "细节…"));
  return fauxAssistantMessage(seen.length === 1 ? "## Goal\n实现数据库层\n## Progress\n### Done\n- [x] src/db.ts" : "## 本轮前半部分\n用户要求加连接池");
};
const { session } = await fauxSession([
  fauxAssistantMessage(long("第一轮：已创建 src/db.ts")),
  fauxAssistantMessage(long("第二轮：已为 db.ts 添加连接池")),
  fauxAssistantMessage(long("第三轮：测试通过")),
  // 接下来两个回复给“摘要器”：一次总结更早的历史，一次总结被切开的那一轮的前半部分
  summarizer, summarizer,
  fauxAssistantMessage("好的，接着写文档。"),
], { settings: { compaction: { keepRecentTokens: 1500 } } });

for (const p of ["建一个数据库模块", "加连接池", "跑测试"]) await session.prompt(p);
console.log("压缩前发给模型的消息数:", session.messages.length);

const r = await session.compact("重点保留文件路径");
console.log("tokensBefore:", r.tokensBefore, "| firstKeptEntryId 存在:", !!r.firstKeptEntryId);
seen.forEach((t, i) => console.log(`摘要请求 ${i + 1}：\n  ` + t.split("\n").filter(Boolean).slice(0, 5).join("\n  ").slice(0, 300)));

await session.prompt("继续");
console.log("\n压缩后转录：");
for (const m of session.messages) console.log("  " + (m.role === "system" ? "system" : brief(m)));
const types = session.sessionManager.getEntries().map((e) => e.type);
console.log("\n会话文件条目:", types.join(", "));
session.dispose();

挑战
为什么序列化成文本？
摘要请求把整段对话变成一条用户消息里的 <conversation>[User]: … [Assistant]: … 文本，而不是把原消息原样作为多轮对话发给模型。列出两个原因。再思考：摘要中为什么特别要求“保留确切的文件路径、函数名和错误信息”？
查看参考答案
原因：①避免模型“继续对话”——如果以原始多轮形式发送，最后一条是 assistant 或工具结果，模型倾向于接着干活而不是总结；变成一段待总结的材料，任务就清楚了。②摆脱协议约束——原始消息包含工具调用/结果配对、thinking 签名等，换个模型（摘要可能用便宜的模型）就需要转换，有的 API 还会拒绝；纯文本对任何模型都有效。另外也禁用了提示缓存写入，因为这种一次性请求不会被复用。
精确信息：压缩后 agent 要继续工作，它会根据摘要去 read 文件、重跑命令、搜索错误。“修改了数据库模块”无法行动，“修改了 src/db.ts 的 createPool()，错误 ECONNREFUSED 127.0.0.1:5432”可以直接行动。

小结
记住这几点


  1. 何时触发：contextTokens > contextWindow − reserveTokens（reserve 默认 16384）。在多轮运行中，工具结果追加后、下一次模型请求前检查（通过 prepareNextTurn 钩子）；新的用户提示前也检查。也可以手动 /compact [指令]。
  2. 溢出恢复：提供方报“上下文溢出”或过早的 length 停止时，可触发一次“压缩后重试”。
  3. 切点：从最新往回累加估算的 token，直到达到 keepRecentTokens（默认 20000）。可以在 user、assistant、bash 执行、自定义消息处切开，永远不在工具结果处切开（结果必须跟着它的调用）。
  4. 切开的一轮：如果切点落在某个用户消息开启的一轮中间，会生成两份摘要：更早历史的摘要 + 这一轮前半部分的摘要，然后合并。
  5. 摘要格式：固定的 Markdown 结构——Goal、Constraints & Preferences、Progress（Done / In Progress / Blocked）、Key Decisions、Next Steps、Critical Context，要求保留确切的文件路径、函数名和错误信息。再次压缩时使用“更新摘要”提示，把旧摘要放在 <previous-summary> 中增量更新。/compact 的指令以 “Additional focus:” 追加。
  6. 持久化：追加一个 compaction 条目（summary、firstKeptEntryId、tokensBefore、usage、details 中累计的读/改文件列表）。构建上下文时，最新的压缩条目之前、firstKeptEntryId 之前的消息被摘要替代。
  7. 扩展可接管：session_before_compact 事件允许扩展取消压缩或提供自己的摘要。
