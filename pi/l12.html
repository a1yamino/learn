系统提示、上下文文件与技能

模型对你的项目一无所知，它知道的一切都来自上下文。pi 的系统提示由 core/system-prompt.ts 拼装成若干命名段落：preamble、tools、rules、docs、addendum、project_context、skills、cwd。本课阅读它的构造方式，看 AGENTS.md 如何从全局目录和祖先目录逐级收集，以及“技能”如何做到渐进披露：系统提示里只放名字和描述，完整说明在需要时才被读取。约 50 分钟。

export function formatSkillsForPrompt(skills: Skill[], fileReadTool: "read" | "bash" | "indirect" = "read"): string {
  const visibleSkills = skills.filter((s) => !s.disableModelInvocation);

  if (visibleSkills.length === 0) {
    return "";
  }

  const lines = [
    "\n\nThe following skills provide specialized instructions for specific tasks.",
    fileReadTool === "read"
      ? "Use the read tool to load a skill's file when the task matches its description."
      : fileReadTool === "bash"
        ? "Use bash to load a skill's file when the task matches its description."
        : "Load a skill's file when the task matches its description.",
    "When a skill file references a relative path, resolve it against the skill directory (parent of SKILL.md / dirname of the path) and use that absolute path in tool commands.",
    "",
    "<available_skills>",
  ];

  for (const skill of visibleSkills) {
    lines.push("  <skill>");
    lines.push(`    <name>${escapeXml(skill.name)}</name>`);
    lines.push(`    <description>${escapeXml(skill.description)}</description>`);
    lines.push(`    <location>${escapeXml(skill.filePath)}</location>`);
    lines.push("  </skill>");
  }

  lines.push("</available_skills>");

  return lines.join("\n");
}

挑战
估算上下文成本
一个项目有 40 个技能，平均描述 300 字符。①它们在每次请求中大约占多少 token（按 4 字符/token 粗算，加上标签）？②为什么 pi 不把技能正文直接放进系统提示？③如果你有一个只想手动触发的危险技能（例如“发布到生产”），应该怎么配置？
查看参考答案
① 每个技能的 name+description+location+标签约 450–500 字符 → 约 120 token；40 个约 5000 token，每次请求都要付出（提示缓存可以降低成本但不能降低占用）。
② 渐进披露：正文可能有数千 token，且大多数任务用不上；只放描述，让模型在需要时用 read 加载，成本只在使用时发生。这也是描述必须写清楚“何时使用”的原因。
③ 在 frontmatter 中设置 disable-model-invocation: true：它不会出现在系统提示里，这只影响技能目录的可见性，用户仍可用 /skill:deploy-prod 显式展开；模型若通过其他途径获得路径，仍可能读取正文或执行其中命令。危险操作还需要独立授权与隔离，不能把这个标记当权限控制。

小结
记住这几点


  1. 分段的系统提示：buildSystemPromptSections 返回有序的段落；除 preamble 外每段都用同名标签包裹（如 <rules>…</rules>），这样后续的 system 消息可以按名字替换某一段（第 3 课的 sections 机制），模型也能把更新对应到原文。
  2. tools 与 rules：tools 段列出每个工具的 promptSnippet；rules 段合并各工具的 promptGuidelines、扩展提供的规则，以及固定的“Be concise…”等，去重。只有 bash 而没有 grep/find/ls 时，会加上“Use bash for file operations like ls, rg, find”。
  3. 替换与追加：.pi/SYSTEM.md 或全局 SYSTEM.md 替换默认的 preamble、tools、rules、docs 四段（project_context、skills、cwd 仍然保留）；APPEND_SYSTEM.md 作为 addendum 追加。扩展可以强制给出完整的系统提示。
  4. 上下文文件：先加载全局目录（~/.pi/agent）中的，再从 cwd 一直向上到根目录，每个目录取第一个存在的 AGENTS.override.md / AGENTS.md / CLAUDE.md，越靠近根的越靠前。每个文件包在 <project_instructions path=…> 中。处理了 git worktree 嵌套时的重复。
  5. 技能：遵循 Agent Skills 规范的 SKILL.md（frontmatter 必须有 name 与 description）。系统提示只列出 name、description、location，并告诉模型“任务匹配时用 read 加载”。来源：全局与项目的 skills/、~/.agents/skills 与项目祖先目录的 .agents/skills、pi 包。disable-model-invocation: true 的技能不出现在提示中，用户可显式调用；这不是访问控制。
  6. /skill:name：用户显式调用时，AgentSession 读取 SKILL.md 正文，包装成 <skill name location>References are relative to … 块放进用户消息。
  7. 信任：项目目录中的 .pi/ 资源（技能、扩展、设置、SYSTEM.md）只在项目被信任时加载；交互模式首次进入一个项目时会询问。SDK 默认信任。
