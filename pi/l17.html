pi-tui：差分渲染的终端界面

pi 的交互界面不使用 React/Ink 之类的框架，而是自己的 pi-tui 包（约 2 万行）。它的核心思想非常朴素：每个组件把自己渲染成字符串数组（每个字符串一行），TUI 把所有组件的行拼起来，与上一帧逐行比较，只把变化的那段重新写到终端，并用“同步输出”转义序列包起来，避免闪烁。流式输出时每秒几十次重绘，靠的就是这一点。约 45 分钟。

挑战
一个自定义组件
写一个 ProgressBar 组件：render(width) 返回一行 [#####-----] 50%，进度条长度随 width 变化且永远不超过 width。把它加进上面的 TUI，每 100ms 更新一次进度，观察每次写入的字节数。
查看参考答案
class ProgressBar {
  constructor(public pct = 0) {}
  invalidate() {}
  render(width: number): string[] {
    const label = ` ${this.pct}%`;
    const inner = Math.max(0, width - 2 - label.length);
    const done = Math.round((inner * this.pct) / 100);
    return [`[${"#".repeat(done)}${"-".repeat(inner - done)}]${label}`];
  }
}
const bar = new ProgressBar(); tui.addChild(bar);
for (let p = 0; p <= 100; p += 10) { bar.pct = p; tui.renderNow(); show(`${p}%`); }
每次更新只有进度条那一行变化，写入几十字节；与全屏重绘（几百到几千字节）相比，在慢速 SSH 连接上差别非常明显。注意宽度计算使用字符数仅在纯 ASCII 时成立，含中文时应使用 visibleWidth。

小结
记住这几点


  1. Component 接口：render(width): string[]，可选 handleInput、handleMouse、invalidate。组件必须保证每行可见宽度不超过 width（超过会直接报错并写崩溃日志），工具函数 visibleWidth、truncateToWidth 处理 ANSI 与 CJK 宽字符。
  2. 两种渲染器：TuiMainScreen（主屏幕，输出进入终端回滚历史，pi 默认）与 TuiAltScreen（备用屏幕，应用自己管理滚动）。
  3. 差分：doRender 计算新行，与 previousLines 比较得到 firstChanged/lastChanged，把光标移到第一处变化，清除并重写只在该区间内的行。没有变化就什么也不写。
  4. 何时整屏重绘：首次渲染、终端宽度变化（换行方式变了）、高度变化、内容缩短到需要清屏、变化发生在视口之上（已滚出屏幕的部分无法原地修改）。
  5. 同步输出：每次写入都包在 ESC[?2026h … ESC[?2026l（CSI 2026）之间，支持的终端会原子地显示整帧。
  6. 其余：编辑器组件（多行、历史、kill ring、撤销、自动补全斜杠命令与路径）、Markdown 渲染、覆盖层（选择器、对话框）、Kitty/iTerm2 内联图片、括号粘贴模式。
