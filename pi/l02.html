一次对话的生命周期：从输入到回复

在深入每一层之前，先完整地跟踪一次请求：用户在编辑器里按下回车，文本经过扩展命令、输入钩子、技能与提示模板展开，进入 AgentSession；会话检查模型与凭据后启动一次 agent 运行；agent 循环构造请求、流式接收模型回复、执行工具、把结果写回上下文，直到模型不再调用工具；每条完成的消息通过事件被持久化到会话文件，并被渲染到终端。本课建立这张“全景图”，并写一个后续各课都会用到的练习工具 faux-session.ts。约 50 分钟。

注意顺序：先通知扩展，再通知公共订阅者（例如 TUI），最后持久化。循环本身完全不知道“会话文件”的存在——这正是 agent-core 可以被其他应用复用的原因。
与 Codex 对照：Codex 把这条通路做成了显式的提交队列 / 事件队列协议：界面提交 Op（如 UserInput），核心发出 Event，二者可以在不同进程甚至不同机器上。见 Codex 第 2 课 · 一次 turn 的生命周期。

01
scratch/faux-session.ts：注册 faux provider，把它登记到 ModelRuntime（这样会话的凭据检查能通过），再用 SDK 的 createAgentSession 创建会话。工作目录是一个临时目录。
cat > pi-mono/scratch/faux-session.ts <<'EOF'
// 课程练习用的小工具：用 faux 模型创建一个真实的 AgentSession（无需 API key）。
import { type FauxResponseStep, registerFauxProvider } from "@earendil-works/pi-ai/compat";
import { type CreateAgentSessionOptions, createAgentSession, ModelRuntime, SessionManager, SettingsManager } from "@earendil-works/pi-coding-agent";
import { mkdirSync, mkdtempSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { dirname, join } from "node:path";

export async function fauxSession(
  responses: FauxResponseStep[],
  options: { files?: Record<string, string>; settings?: object; extra?: Partial<CreateAgentSessionOptions> } = {},
) {
  const dir = mkdtempSync(join(tmpdir(), "pi-course-"));
  for (const [name, text] of Object.entries(options.files ?? {})) {
    mkdirSync(dirname(join(dir, name)), { recursive: true });
    writeFileSync(join(dir, name), text);
  }
  const faux = registerFauxProvider();
  faux.setResponses(responses);
  const model = faux.getModel();
  const modelRuntime = await ModelRuntime.create({ authPath: join(dir, ".auth.json"), modelsPath: null, allowModelNetwork: false });
  modelRuntime.registerProvider(model.provider, {
    baseUrl: model.baseUrl, apiKey: "faux-key", api: faux.api,
    models: faux.models.map((m) => ({ id: m.id, name: m.name, api: m.api, reasoning: m.reasoning, input: m.input,
      cost: m.cost, contextWindow: m.contextWindow, maxTokens: m.maxTokens, baseUrl: m.baseUrl })),
  });
  const { session } = await createAgentSession({
    cwd: dir, agentDir: join(dir, ".pi-agent"), model, thinkingLevel: "off", modelRuntime,
    sessionManager: SessionManager.inMemory(dir), settingsManager: SettingsManager.inMemory(options.settings ?? {}),
    ...options.extra,
  });
  return { session, dir, faux };
}

export function show(messages: readonly any[]) {
  for (const m of messages) {
    const c = m.role === "system"
      ? `sections=${Object.keys(m.sections ?? {}).join(",")} tools=${(m.toolsAdded ?? []).map((t: any) => t.name).join(",")}`
      : typeof m.content === "string" ? m.content : JSON.stringify(m.content ?? "");
    console.log(m.role.padEnd(11), c.replace(/\s+/g, " ").slice(0, 90));
  }
}

import { fauxAssistantMessage, fauxToolCall } from "@earendil-works/pi-ai/compat";
import { fauxSession, show } from "./faux-session.ts";

const { session } = await fauxSession(
  [fauxAssistantMessage([fauxToolCall("read", { path: "hello.txt" })], { stopReason: "toolUse" }), fauxAssistantMessage("文件里写着：你好，pi")],
  { files: { "hello.txt": "你好，pi\n" } },
);
session.subscribe((e) => {
  if (e.type === "tool_execution_start") console.log(`[工具开始] ${e.toolName} ${JSON.stringify(e.args)}`);
  if (e.type === "turn_end") console.log(`[turn_end] 本轮工具结果 ${e.toolResults.length} 个`);
  if (e.type === "agent_settled") console.log("[agent_settled]");
});
await session.prompt("读一下 hello.txt");
show(session.messages);
session.dispose();

挑战
steer 与 followUp
修改 l02.ts：在收到第一个 tool_execution_start 事件时调用 session.steer("另外也看看 notes.txt")，并为 faux 模型多准备一条回复。预测并验证：转录中这条 user 消息出现在哪里？如果改用 session.followUp(...) 呢？
查看参考答案
steer：消息在当前 turn 的工具执行完成之后、下一次模型调用之前进入转录。顺序是：system、user、assistant(read)、toolResult、user(另外也看看…)、assistant(…)。
followUp：等 agent 本来要停下（模型回复没有工具调用、也没有 steering 消息）时才进入，因此出现在最终回复之后，并触发新的一轮：…、assistant(文件里写着…)、user(另外也看看…)、assistant(…)。
对应的代码在 agent-loop.ts 的 runLoop：内层循环每个 turn 结束后读取 getSteeringMessages()；外层循环在要退出前读取 getFollowUpMessages()（第 6 课逐行讲解）。别忘了给 faux 模型准备足够的回复，否则会报 “No more faux responses queued”。

小结
记住这几点


  1. 三个层次的对象：AgentSession（coding-agent：输入处理、会话持久化、压缩、扩展、重试）包着 Agent（agent-core：状态与事件）；Agent 运行 runLoop（agent-core：循环本身）；循环通过 streamFn 调用 pi-ai。
  2. 输入处理顺序（AgentSession.prompt）：扩展命令（/name，立即执行，不进入模型）→ 输入事件（扩展可拦截或改写）→ 技能命令 /skill:name 展开 → 提示模板展开 → 若正在运行则按 steer / followUp 排队 → 校验模型和凭据 → 启动运行。
  3. 一次运行 = 若干个 turn：每个 turn 是“一次模型回复 + 执行它请求的全部工具”。模型的回复里有工具调用，就需要下一个 turn 把结果交给模型；没有工具调用（也没有排队的消息）时，运行结束。
  4. 事件驱动：循环只发出事件（agent_start、turn_start、message_start/update/end、tool_execution_*、turn_end、agent_end），界面渲染、会话持久化、扩展钩子都是事件的订阅者。AgentSession 在 message_end 时把完成的消息追加到会话。
  5. agent_end 与 agent_settled：agent_end 表示一次底层运行结束；之后可能还有自动重试、自动压缩或排队的消息。agent_settled 才表示 pi 不会再自动继续。
  6. 系统消息也是消息：pi 把系统提示与工具声明作为转录中的第一条 system 消息（带命名的 sections 与 toolsAdded），后续的变化以新的系统消息追加——第 3 课详述。
