挑战
设计一个文章系统的键
需要：文章内容与作者、点赞（每人只能赞一次，要能判断自己是否赞过）、按点赞数的热门榜、每篇文章的最近 50 条评论 id、首页“最新发布”列表。为每一项给出键名、类型和关键命令。
查看参考答案
post:{id}                Hash   HSET post:1001 title … author 42 created 1761100000
post:{id}:likers         Set    SADD post:1001:likers 42   → 返回 1 表示新点赞，0 表示已赞过
                                SISMEMBER post:1001:likers 42
posts:hot                ZSet   ZINCRBY posts:hot 1 1001（只在 SADD 返回 1 时执行）
                                ZRANGE posts:hot 0 9 REV WITHSCORES
post:{id}:comments       List   LPUSH post:1001:comments c9001; LTRIM post:1001:comments 0 49
posts:latest             ZSet   ZADD posts:latest 1761100000 1001（分数为发布时间）
                                ZRANGE posts:latest +inf -inf BYSCORE REV LIMIT 0 20
点赞用 Set 保证去重，SADD 的返回值告诉你是不是第一次赞，再决定是否给排行榜加分（两步之间的原子性可以用第 10 课的 Lua 保证）。点赞数可以直接用 SCARD，不必单独存。“最新发布”用以时间戳为分数的 ZSet 而不是 List，可以按时间范围分页，也可以删除任意一篇（ZREM O(log N)，List 删除中间元素是 O(N)）。热门文章的点赞者集合可能很大，不要用 SMEMBERS 取全部。

小结
记住这几点


  1. String：二进制安全，最大 512 MB。用于缓存序列化对象、计数器（INCR、INCRBY 原子自增）、分布式锁（SET key val NX PX 30000）。
  2. List：按插入顺序的双端列表，两端 LPUSH/RPUSH/LPOP/RPOP 是 O(1)，按下标访问中间元素是 O(N)。用于简单队列（BLPOP 阻塞等待）、最近 N 条记录（LPUSH + LTRIM）。
  3. Hash：一个键下的字段—值映射。存对象的各个属性，可以单独读写某个字段（HSET、HGET、HINCRBY）。Redis 7.4+ 支持为单个字段设置过期（HEXPIRE）。
  4. Set：无序、不重复。成员判断 SISMEMBER O(1)；交并差 SINTER/SUNION/SDIFF 用于共同好友、标签筛选。Sorted Set（ZSet）：每个成员带一个 double 分数，按分数有序，ZADD/ZINCRBY O(log N)，ZRANGE … REV、ZRANK 用于排行榜和按时间排序的索引。
  5. 键名用冒号分层：业务:对象:id[:字段]，如 shop:product:1001。保持简短但可读；键名本身也占内存。TYPE key 查看类型，对错误类型执行命令会返回 WRONGTYPE。
  6. 看文档时注意每个命令的复杂度：HGETALL、SMEMBERS、LRANGE 0 -1、ZRANGE 0 -1 都是 O(N)。元素多的集合用 HSCAN/SSCAN/ZSCAN 分批遍历。
