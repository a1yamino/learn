Redis 是什么：内存数据库、单线程与许可证

Redis 是一个把数据放在内存里、通过网络提供命令的键值数据库，最常见的用途是缓存，也常用作计数器、排行榜、队列和分布式锁。本课讲它为什么快、一条命令从客户端到返回经历了什么、和关系型数据库的分工，并说明 2024 年以来 Redis 与 Valkey 的许可证变化，最后在 Docker 里启动本课程使用的环境。约 40 分钟。

命令、返回值和 RESP 协议相同，所以应用代码通常只需要改连接地址；Valkey 为了兼容，在 redis_version 字段中报告 7.2.4，真实版本在 valkey_version。客户端库（redis-py、Jedis、Lettuce、go-redis 等）都可以直接连接 Valkey，Valkey 也提供了自己的客户端 Valkey GLIDE。
差异主要在 Redis 7.4 / 8 之后新增的功能：Redis 8 内置的 JSON、搜索、时间序列、向量集合等在 Valkey 中需要另外的模块或不存在；Valkey 也有自己独有的改进。许可证方面：只是把 Redis 当作服务内部使用，三种许可通常都没有影响；如果你修改了 Redis 源码并作为网络服务提供给他人，选择 AGPLv3 就需要公开修改后的源码；把 Redis 作为托管服务出售则受 RSALv2/SSPLv1 的限制。对这些有顾虑的团队会选择 BSD 许可的 Valkey。具体以法务意见为准。

小结
记住这几点


  1. Redis 把所有数据放在内存中，读写一个键通常在微秒级完成；持久化（第 9 课）只是把内存数据保存到磁盘，用于重启后恢复。
  2. 执行命令的主线程是单线程的：命令一条接一条地执行，单条命令天然是原子的，不需要锁。代价是一条慢命令（如对百万元素的集合做 SMEMBERS、KEYS *）会阻塞其他所有客户端。
  3. 客户端与服务器使用 RESP 文本协议通过 TCP（默认端口 6379）通信。延迟大部分花在网络往返上，所以批量操作要用 Pipeline（第 3 课）。
  4. Redis 不是关系型数据库的替代品：没有 SQL、没有复杂查询，内存成本高，默认持久化可能丢失最近的写入。典型分工是数据库存权威数据，Redis 存热点数据和需要极低延迟的结构。
  5. 许可证：Redis 7.2 及以前为 BSD-3-Clause；7.4 改为 RSALv2 / SSPLv1 双许可（不是 OSI 开源许可）；Redis 8 起增加 AGPLv3 选项，成为三选一（RSALv2 / SSPLv1 / AGPLv3），并把 JSON、搜索、时间序列、概率结构等模块并入 Redis Open Source。
  6. Valkey 是 2024 年 3 月从 Redis 7.2.4 分叉、由 Linux 基金会托管的项目，保持 BSD-3-Clause，命令和协议与 Redis 兼容，许多云厂商的托管服务已转向它。本课程以 Redis 8（Docker 镜像 redis:8.10）为准，绝大多数内容同样适用于 Valkey；只在两者不同之处单独说明。
