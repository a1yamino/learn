挑战
写一个原子的“转账”脚本
两个账户余额存在 acct:{ledger}:u1 和 acct:{ledger}:u2（字符串）。写一个 Lua 脚本：从 KEYS[1] 转 ARGV[1] 到 KEYS[2]，余额不足返回错误，不能出现负数；说明为什么键名里用了花括号，以及为什么用 MULTI/EXEC 做不到同样的事。
查看参考答案
local max = 9007199254740991  -- 示例只接受 53 位内的非负整数
local function integer(s)
  if not s or not string.match(s, "^%d+$") then return nil end
  if s ~= "0" and string.sub(s, 1, 1) == "0" then return nil end
  local n = tonumber(s)
  if n > max then return nil end
  return n
end
local amt = integer(ARGV[1])
local bal = integer(redis.call("GET", KEYS[1]) or "0")
local dest = integer(redis.call("GET", KEYS[2]) or "0")
if KEYS[1] == KEYS[2] or not amt or amt == 0 or not bal or not dest then
  return redis.error_reply("bad account or amount")
end
if bal < amt then return redis.error_reply("insufficient") end
if dest > max - amt then return redis.error_reply("balance overflow") end
redis.call("DECRBY", KEYS[1], ARGV[1])
redis.call("INCRBY", KEYS[2], ARGV[1])
return bal - amt
调用：EVAL "…" 2 acct:{ledger}:u1 acct:{ledger}:u2 30。示例先读取两边余额并校验金额、整数格式和目标上限，避免目标账户类型错误、非整数或溢出造成先扣后报错。Lua 原子执行不等于出错会回滚；生产账户还需持久化账本和幂等约束。花括号是哈希标签：Cluster 只用 {} 里的部分计算槽，保证两个键在同一节点，否则脚本报 CROSSSLOT（第 15 课）。本例两键共享标签 {ledger}；不能把不同用户 ID 分别放进标签后误以为同槽。集中所有账户也会造成热点，应按业务选择账本分组或数据库事务。MULTI/EXEC 里的命令在 EXEC 时才执行，无法根据余额决定是否扣减；用 WATCH 可以实现，但冲突时要重试，而脚本一次往返就完成。

小结
记住这几点


  1. MULTI 之后的命令进入队列，EXEC 时一次性按顺序执行，期间不会插入其他客户端的命令。但 Redis 事务没有回滚：某条命令运行时出错（如对字符串做 LPUSH），其余命令照样执行；只有入队时的语法错误会让整个事务被放弃。
  2. 事务里不能根据读到的值做判断，因为命令在 EXEC 时才执行。“读—判断—写”用 WATCH：EXEC 前被 WATCH 的键被其他客户端修改，EXEC 返回 nil，客户端重试（乐观锁）。
  3. EVAL script numkeys key… arg… 在服务器端原子地执行 Lua 脚本，可以在脚本内读、判断、写，一次往返。脚本执行期间整个服务器被它占用，所以脚本必须短；超过 busy-reply-threshold（默认 5 秒）后其他客户端收到 BUSY，只能 SCRIPT KILL（未写入时）或 SHUTDOWN NOSAVE。
  4. 所有用到的键都要通过 KEYS 传入，不要在脚本里拼键名：这是 Cluster 能把脚本路由到正确节点的前提（键必须在同一个槽）。EVALSHA 用 SHA1 调用已缓存的脚本，省去传输脚本正文；脚本缓存在重启或 SCRIPT FLUSH 后丢失，客户端要处理 NOSCRIPT。
  5. Redis 7 的 Functions：FUNCTION LOAD 加载一个库，函数有名字，会随 RDB/AOF 持久化并复制到副本，用 FCALL 调用。适合作为服务器端的“存储过程”长期使用；临时脚本仍可用 EVAL。只读函数可声明 no-writes 标志，用 FCALL_RO 在副本上执行。
  6. 选择：简单的批量写用 MULTI/EXEC（或 pipeline）；需要条件判断且冲突少用 WATCH；需要原子的“读—判断—写”优先用 Lua/Functions。
