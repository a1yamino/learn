Cluster：槽、重定向与扩缩容

单个 Redis 的内存和写入能力有上限。Redis Cluster 把键空间切成 16384 个槽分布到多个主节点上，每个主节点有自己的副本。本课讲键如何映射到槽、客户端如何处理 MOVED 和 ASK、哈希标签与多键操作的限制、节点间如何用 gossip 发现故障并自动切换，以及迁移槽的过程。约 65 分钟。

挑战
为购物车和排行榜设计键
电商要把 Redis 迁到 6 主 Cluster。现有键：cart:<uid>（哈希）与 cart_ver:<uid>（字符串），需要在一个 Lua 脚本里同时修改；全站排行榜 rank:global（ZSET，2000 万成员，每秒 3 万次 ZINCRBY）；按日期的 pv:<yyyymmdd>:<page> 有时需要 MGET 同一天所有页面。给出新的键名和理由，指出哪个设计有热点风险以及如何处理。
查看参考答案
  • cart:{<uid>} 和 cart_ver:{<uid>}：用用户 ID 作哈希标签，脚本中的两个键同槽；不同用户分散在所有槽，没有热点。
  • pv:{<yyyymmdd>}:<page> 能让 MGET 生效，但同一天的所有 PV 计数集中在一个槽 = 一个节点，当天写入全部打到这个节点，形成热点。更好的做法：不加标签，客户端按槽分组并行 MGET（多数客户端库会自动拆分），或者把同一天的数据放进一个哈希 pv:<day> 并按 hash(page) % 16 分成 16 个分片键。
  • rank:global 是一个 2000 万成员的大 key，只能在一个节点上：可以先在应用里按 uid % N 拆分成 rank:global:0..N-1（分布在不同节点），写入分散；查询 Top 100 时每个分片取 Top 100 再在应用中合并。第 19、21 课会再讨论。

小结
记住这几点


  1. slot = CRC16(key) mod 16384。每个主节点负责一部分槽，例如三主时 0–5460、5461–10922、10923–16383。键名中有 {…} 时只用花括号里的内容计算，这就是哈希标签。
  2. 客户端可以连接任意节点。如果键不在该节点，返回 MOVED 3999 10.0.0.2:6379；智能客户端缓存“槽 → 节点”映射（用 CLUSTER SHARDS 获取），收到 MOVED 后更新，所以正常情况下一次往返就到对的节点。
  3. 多键命令（MGET、事务、Lua、SUNIONSTORE…）要求所有键在同一个槽，否则报 CROSSSLOT。用哈希标签把需要一起操作的键放在一起，例如 cart:{u42} 和 cart:{u42}:items；但不要用同一个标签装太多数据，否则形成热点槽。Cluster 只有 db 0。
  4. 迁移槽：源节点标记 MIGRATING、目标节点标记 IMPORTING，逐批 MIGRATE 键。迁移期间请求的键已经搬走时，源节点返回 ASK，客户端只对这一次请求先发 ASKING 再访问目标节点，不更新缓存的映射；全部完成后槽归属改变，此后返回 MOVED。redis-cli --cluster reshard/rebalance 自动完成这些步骤（Redis 8.2 起还有更快的原子槽迁移）。
  5. 节点之间通过集群总线（端口 +10000）用 gossip 交换状态。某节点被多数主节点在 cluster-node-timeout 内标记为 PFAIL 后升级为 FAIL，它的副本发起选举，获得多数主节点投票后接管槽。无需 Sentinel。
  6. 默认 cluster-require-full-coverage yes：任何槽没有可用节点时整个集群拒绝服务；设为 no 则其他槽继续工作。复制仍是异步的，故障切换时同样可能丢失最近的写入。
