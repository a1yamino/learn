03
逐条执行 1 万次与 Pipeline 对比。
python3 - <<'PY'
import redis, time
r = redis.Redis()
t = time.perf_counter()
for i in range(10000): r.set(f"k:{i}", i)
print("loop", round(time.perf_counter() - t, 3))
t = time.perf_counter()
p = r.pipeline(transaction=False)
for i in range(10000): p.set(f"k:{i}", i)
p.execute()
print("pipeline", round(time.perf_counter() - t, 3))
PY
loop 0.912
pipeline 0.041

挑战
给“商品列表页”减少往返
列表页显示 20 个商品，现在的代码对每个商品依次执行：HGETALL product:{id}、GET stock:{id}、ZSCORE rating {id}，共 60 次往返，耗时约 20 ms。改写它，并说明为什么不用 MULTI/EXEC。
查看参考答案
p = r.pipeline(transaction=False)
for pid in ids:
    p.hgetall(f"product:{pid}")
    p.get(f"stock:{pid}")
    p.zscore("rating", pid)
res = p.execute()
items = [res[i:i+3] for i in range(0, len(res), 3)]
60 次往返变成 1 次，耗时降到 1 ms 左右（服务器执行 60 条命令只需几十微秒）。这里只需要减少往返，不需要原子性：几个值是否在同一瞬间读取对展示没有影响，所以用非事务 Pipeline。MULTI/EXEC（第 10 课）会额外保证中间不插入其他客户端的命令，但同样是一次往返，并没有更快，在 Cluster 模式下还要求所有键在同一个槽。在 Cluster 中，客户端会把 Pipeline 按节点拆分后并行发送。进一步可以把库存合并进商品 Hash 的字段，减少命令数。

小结
记住这几点


  1. RESP：命令以数组发送，如 *3\r\n$3\r\nSET\r\n$1\r\nk\r\n$1\r\nv\r\n；回复有简单字符串 +OK、错误 -ERR、整数 :1、块字符串 $5、数组 *2。RESP3（HELLO 3）增加了 map、set、推送等类型。
  2. 一次命令的耗时 ≈ 网络往返（同机房约 0.1–0.5 ms）+ 执行时间（微秒级）。循环执行 1000 次 GET 就是 1000 次往返。
  3. 批量命令（MGET/MSET/HMGET）把多次读写合并成一条；Pipeline 把多条任意命令连续发出、最后一次性读取回复，往返从 N 次降到 1 次。Pipeline 不是事务：中间的命令可能与其他客户端的命令交错，也可能部分失败。
  4. 连接池：建立 TCP 连接（和 TLS 握手、AUTH）比执行命令贵得多。阻塞式客户端（redis-py、Jedis）每个并发请求占用一个连接，池大小要覆盖并发度；Lettuce 等可以在少量连接上多路复用；go-redis 默认使用连接池。注意 maxclients（默认 10000）。
  5. 设置超时：连接超时和读写超时（几十到几百毫秒）。Redis 卡顿时没有超时的客户端会耗尽应用线程。阻塞命令（BLPOP、XREAD BLOCK）的读超时要大于阻塞时间，并使用独立的连接。
  6. 客户端缓存（Redis 6+）：CLIENT TRACKING on 后，服务器记住每个连接读过的键，键被修改时推送失效消息，客户端在本地内存缓存热点值，命中时完全不经过网络。
