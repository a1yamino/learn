存储引擎：日志结构与 LSM 树

第 4 章的第一部分。数据库最朴素的实现是一个只追加的文件——写入极快，读取却要扫描全部。本课从这里出发：加上内存中的哈希索引（Bitcask 模式）、分段与压缩合并，再把段文件改成按键排序的 SSTable，得到 LSM 树：内存表、刷盘、多层合并、布隆过滤器，以及分层合并与大小分级合并两种策略的取舍。练习里你会写出一个 30 行的日志结构键值存储。约 60 分钟。

01
保存为 kv.py：只追加日志 + 内存哈希索引 + 压缩。
import os
LOG = "data.log"
index = {}                      # 键 → 文件中的字节偏移量

def put(k, v):
    with open(LOG, "ab") as f:
        index[k] = f.tell()
        f.write(f"{k},{v}\n".encode())

def get(k):
    if k not in index: return None
    with open(LOG, "rb") as f:
        f.seek(index[k])
        return f.readline().decode().rstrip("\n").split(",", 1)[1]

def compact():
    global index
    live = {k: get(k) for k in index}
    os.remove(LOG); index = {}
    for k, v in live.items(): put(k, v)

if os.path.exists(LOG): os.remove(LOG)
for i in range(1000):
    put(f"user{i % 10}", f"visits={i}")
print("get user3 =", get("user3"))
print("日志大小", os.path.getsize(LOG), "字节，键数", len(index))
compact()
print("压缩后", os.path.getsize(LOG), "字节；get user3 =", get("user3"))

03
保存为 merge.py：合并三个 SSTable（带墓碑）。
import heapq
# 三个 SSTable：每个都按键排序；编号越大越新
seg1 = [("apple", 1), ("cat", 1), ("dog", 1)]
seg2 = [("apple", 2), ("bird", 2), ("dog", None)]      # None 表示删除（墓碑）
seg3 = [("cat", 3), ("eel", 3)]
merged = {}
for k, v, age in heapq.merge(*[[(k, v, -i) for k, v in s] for i, s in enumerate([seg1, seg2, seg3])], key=lambda t: (t[0], t[2])):
    if k not in merged: merged[k] = v                  # 同一个键只保留最新的
out = [(k, v) for k, v in merged.items() if v is not None]
print(out)
[('apple', 2), ('bird', 2), ('cat', 3), ('eel', 3)]

挑战
给 kv.py 加上 SSTable
把练习 1 的 kv.py 改造成一个小 LSM：① 写入先进内存中的 dict（内存表），超过 100 个键时按键排序写成 seg-N.sst；② 为每个段在内存中保存稀疏索引（每 10 个键记一个偏移量）；③ 读取时先查内存表，再从新到旧查各个段；④ 实现 compact()，把所有段合并成一个。写出关键代码，并说明崩溃时内存表中的数据如何不丢。
查看参考答案
import bisect, glob, os
mem, segs, next_seg = {}, [], 0   # segs: [(文件名, [(键, 偏移量), ...]), ...]，旧的在前

def flush():
    global mem, next_seg
    name = f"seg-{next_seg}.sst"; next_seg += 1; sparse = []
    with open(name, "wb") as f:
        for i, k in enumerate(sorted(mem)):
            if i % 10 == 0: sparse.append((k, f.tell()))
            f.write(f"{k},{mem[k]}\n".encode())
    segs.append((name, sparse)); mem = {}
    open("wal.log", "w").close()             # 内存表已持久化，清空 WAL

def put(k, v):
    with open("wal.log", "a") as w: w.write(f"{k},{v}\n")   # 先写 WAL
    mem[k] = v
    if len(mem) > 100: flush()

def get(k):
    if k in mem: return mem[k]
    for name, sparse in reversed(segs):         # 从新到旧
        i = bisect.bisect_right([s[0] for s in sparse], k) - 1
        if i < 0: continue
        with open(name, "rb") as f:
            f.seek(sparse[i][1])
            for line in f:                      # 扫描候选块；遇到下一个更大的键即停止
                kk, v = line.decode().rstrip("\n").split(",", 1)
                if kk == k: return v
                if kk > k: break
    return None

def compact():
    global segs
    if mem: flush()                           # 先持久化待写数据，不能在合并时丢掉它的 WAL
    if not segs: return
    old_segs = segs.copy()
    merged = {}
    for name, _ in segs:                        # 旧 → 新，新值覆盖旧值
        for line in open(name):
            k, v = line.rstrip("\n").split(",", 1); merged[k] = v
    mem.update(merged); flush()               # 新段写完后才删除旧段
    segs = segs[-1:]
    for name, _ in old_segs: os.remove(name)
这段关键代码演示单进程的查找、刷盘和合并：合并先刷出尚未刷盘的写入，新段写完后才删除旧段，段编号持续递增，避免覆盖仍有效的段。它尚未实现可直接运行的崩溃恢复。真实恢复需要先读取持久化的段清单、重建稀疏索引和下一段编号，再重放 WAL；确认持久性还需要 fsync、原子切换并持久化段清单，最后才能安全截断 WAL、回收旧段。仅关闭 Python 文件不等于已抗断电持久化。墓碑也只能在确认不存在更旧值和仍需该版本的快照后清理。

小结
记住这几点


  1. 只追加的日志：写入就是在文件末尾追加一行，顺序写非常快；读取要从头扫描，O(n)。索引是从主数据派生出来的额外结构，用来加速读取——但每个索引都会拖慢写入，所以数据库不会默认索引一切。
  2. 哈希索引：在内存里保存“键 → 文件偏移量”的哈希表，读取一次寻址即可（Bitcask 的做法）。前提是所有键都放得进内存；不支持范围查询。为了不让日志无限增长，把日志切成段，对旧段做压缩（只保留每个键的最新值）并合并；删除用一条特殊的墓碑记录表示。崩溃恢复要重建哈希表（可以保存快照加速）。
  3. SSTable（排序字符串表）：段内的键按顺序排列。好处：合并多个段就像归并排序，简单高效；不需要把所有键放进内存，稀疏索引（每隔几 KB 记一个键）就够了，块还可以压缩；天然支持范围查询。
  4. LSM 树的写路径：写入先进内存表（memtable，有序结构如跳表），同时追加到预写日志（WAL）以防崩溃；内存表达到阈值后作为新的 SSTable 写到磁盘。读路径：依次查内存表、最新的段、较旧的段……为了避免为不存在的键读遍所有段，每个 SSTable 带一个布隆过滤器，能确定地回答“不在这里”。后台不断合并段，丢弃不再需要的旧值；墓碑只有在确认不会让更旧值复活、且没有快照仍需旧版本时才能清理。RocksDB、Cassandra、ScyllaDB、HBase 都是 LSM 结构。
  5. 合并策略：大小分级（size-tiered）把大小相近的段合并成更大的段，写放大小，但空间占用和读放大较大；分层（leveled）把键范围切成小文件分到多层，每层大小递增，读和空间更省，写放大更大。写放大还会消耗 SSD 寿命。
  6. 同样的思想在你学过的系统里随处可见：Redis 的 AOF 只追加并定期重写（Redis 课程），Kafka 的分区就是分段的追加日志，日志压缩只保留每个键的最新值（Kafka 第 12 课）。
