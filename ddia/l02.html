01
保存为 lat.py 并运行：一万个正常请求加 50 个极慢请求。
import random, statistics
random.seed(42)
lat = [random.lognormvariate(3, 0.6) for _ in range(10000)]   # 毫秒
lat += [random.uniform(500, 2000) for _ in range(50)]          # 少量极慢请求
lat.sort()
def pct(p): return lat[int(len(lat) * p / 100) - 1]
print(f"平均  {statistics.mean(lat):7.1f} ms")
for p in (50, 95, 99, 99.9):
    print(f"p{p:<5} {pct(p):7.1f} ms")

02
保存为 fan.py 并运行：尾延迟放大。
import random
random.seed(7)
def slow_rate(n):   # 页面并行调用 n 个后端，每个后端 1% 的概率很慢
    slow = sum(1 for _ in range(100000) if any(random.random() < 0.01 for _ in range(n)))
    return slow / 100000
for n in (1, 10, 100):
    print(f"调用 {n:3} 个后端：页面变慢的概率 {slow_rate(n):.1%}")

挑战
为一个短视频应用设计首页 Feed
数据：日活 5000 万，平均每人关注 150 个账号，每天发布 500 万条视频；粉丝数中位数 30，最大 8000 万；首页 Feed 读取约 5 万次/秒。要求：p99 < 300 ms。请：① 估算纯写时扇出每天的写入量；② 设计混合方案及阈值；③ 写出 SLO 并说明如何正确测量 p99。
查看参考答案
  1. 平均粉丝数 = 平均关注数 = 150（每条关注边对应一个粉丝），纯扇出约 500 万 × 150 = 7.5 亿次写入/天（约 8700 次/秒），但偏斜使峰值极高：一个 8000 万粉丝的账号发一条就是 8000 万次写入。
  2. 粉丝数 < 某阈值（如 10 万）的账号写时扇出到粉丝时间线（Redis 列表或专用存储，只保留最近 N 条 ID）；超过阈值的账号不扇出，读取 Feed 时取“我关注的名人”的最近内容（通常只有几个到几十个）与预计算时间线归并。还可以只为近期活跃的粉丝扇出，不活跃用户登录时再重建。
  3. SLO：“滚动 30 天内，99% 的 Feed 请求在客户端测得的响应时间 < 300 ms；可用性 ≥ 99.9%”。测量：在客户端或网关记录每个请求的耗时，按时间窗口写入直方图（HdrHistogram / t-digest），合并直方图后再算百分位；不要对各机器的 p99 求平均；同时监控各下游的 p99，以发现尾延迟放大。

小结
记住这几点


  1. 数据模型：users、posts(user_id, text, ts)、follows(follower, followee)。首页时间线 = 我关注的所有人最近的帖子，按时间倒序。
  2. 方案一：读时合并（pull）。打开首页时执行“查我关注的人 → 取他们的最新帖子 → 归并排序”。写很便宜，读很贵：关注 200 人的用户每次刷新都要查 200 个人的帖子。读远多于写时（首页刷新量可能是发帖量的数百倍），数据库扛不住。
  3. 方案二：写时扇出（push，物化时间线）。每个用户有一个预先算好的时间线缓存；发帖时把帖子 ID 写入每个粉丝的时间线。读变成一次按键读取，写的代价与粉丝数成正比。时间线是派生数据（第 1 课），可以从 posts 和 follows 重建。
  4. 名人问题：粉丝 1 亿的账号发一条帖子要写 1 亿次。混合方案：普通用户写时扇出；名人的帖子不扇出，读时单独查询再合并。这里描述负载的关键参数不是平均粉丝数，而是粉丝数的分布——偏斜的分布决定了架构。
  5. 描述性能：响应时间是客户端看到的总时长（含排队、网络）；延迟是请求等待处理的时间。响应时间是一个分布，要看百分位：p50（中位数）代表典型体验，p95/p99/p999 是尾延迟。平均值会被少数极端值拉偏，也不对应任何真实用户的体验。最慢的请求往往来自数据最多的用户——也就是最有价值的用户。
  6. 尾延迟放大：一个页面并行调用 100 个后端，每个后端只有 1% 的请求慢，页面变慢的概率却高达 1 − 0.99100 ≈ 63%。排队放大尾延迟：少数慢请求占住处理能力，后面的请求排队等待（队头阻塞），所以要在客户端测量。SLO 示例：“99% 的首页请求在 200 ms 内完成，月可用性 99.9%”；SLA 是附带赔偿条款的合同。计算百分位要用直方图（HdrHistogram、t-digest），不能把各机器的百分位求平均。
