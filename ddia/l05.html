02
从“中国”出发，沿 within 边反向走任意步。
WITH RECURSIVE r(id, d) AS (
  SELECT 1, 0
  UNION
  SELECT e.tail, d + 1 FROM edges e JOIN r ON e.head = r.id WHERE e.label = 'within'
)
SELECT v.name, d FROM r JOIN vertices v USING (id) ORDER BY d, v.id;

03
完整查询：出生在中国境内、住在东京都境内的人。
WITH RECURSIVE
 in_china(id) AS (SELECT id FROM vertices WHERE name = '中国'
   UNION SELECT e.tail FROM edges e JOIN in_china ON e.head = in_china.id WHERE e.label = 'within'),
 in_tokyo(id) AS (SELECT id FROM vertices WHERE name = '东京都'
   UNION SELECT e.tail FROM edges e JOIN in_tokyo ON e.head = in_tokyo.id WHERE e.label = 'within')
SELECT p.name FROM vertices p
 JOIN edges b ON b.tail = p.id AND b.label = 'born_in' JOIN in_china ON b.head = in_china.id
 JOIN edges l ON l.tail = p.id AND l.label = 'lives_in' JOIN in_tokyo ON l.head = in_tokyo.id
ORDER BY p.name;

事件溯源的最小例子：事件表 + 派生视图。
CREATE TABLE cart_events(seq serial, cart int, type text, sku text);
INSERT INTO cart_events(cart,type,sku) VALUES (1,'added','A'),(1,'added','B'),(1,'removed','A');
SELECT sku FROM cart_events WHERE cart = 1 GROUP BY sku HAVING sum(CASE type WHEN 'added' THEN 1 ELSE -1 END) > 0;

 B
挑战
选择数据模型
为下列三个功能各选一种数据模型并说明理由：① 支付风控：“这笔交易的设备、IP、收货地址，与已知欺诈账户之间是否在 3 步以内相连”；② 移动端首页：一次请求取回用户信息、最近 5 个订单和每个订单的商品缩略图；③ 购物车：要求能回答“用户在下单前删除过哪些商品”。
查看参考答案
  1. 图模型（图数据库或 SQL/PGQ、递归 CTE）：账户、设备、IP、地址是顶点，使用关系是边；问题是有界深度的路径查询 (t)-[*..3]-(:Account {fraud:true})，用连接表达会非常繁琐且慢。
  2. GraphQL（API 层）+ 关系库：客户端声明需要的嵌套 JSON 结构，服务端解析器从订单表、商品表取数并处理 N+1（DataLoader 批量）。GraphQL 不负责存储，只是查询接口。
  3. 事件溯源：记录 ItemAdded、ItemRemoved、QuantityChanged 事件；当前购物车是派生视图，而“下单前删除过的商品”可以从事件中直接回答——如果只存当前状态，这个信息就丢失了。

小结
记住这几点


  1. 属性图：顶点和边都有唯一 ID、标签和属性；每条边有起点和终点。任何顶点之间都可以连边，可以沿边双向遍历，不同类型的事物可以放在同一张图里（人、地点、事件）。社交关系、知识图谱、路网、欺诈检测都适合。
  2. Cypher（Neo4j 等）用 ASCII 箭头描述模式：(p:Person)-[:BORN_IN]->()-[:WITHIN*0..]->(:Location {name:'中国'})，*0.. 表示沿 WITHIN 边走任意步。它是声明式的：只描述要找什么，由查询优化器决定怎么找。
  3. SQL 中的图查询：把顶点和边存成两张表，可变长度路径用 WITH RECURSIVE 表达。能做到，但比 Cypher 冗长得多——不同的数据模型适合不同的用例。SQL:2023 新增了属性图查询（SQL/PGQ）。三元组（主语、谓语、宾语）是另一种图表示，查询语言为 SPARQL。Datalog 用规则组合出新事实，规则可以递归，适合复杂的推理。
  4. GraphQL 名字里有 Graph，但它不是图数据库查询语言：它让客户端声明需要的 JSON 结构，由服务端解析器取数，故意不支持任意递归，以免客户端发起代价过高的查询。
  5. 事件溯源与 CQRS：把所有变化记录为不可变事件（记录系统），再由事件派生出多个为读取优化的视图（物化视图）。写模型与读模型分开（CQRS），读视图可以随时从事件重建，新需求只需新建一个视图。事件要用过去时、描述业务事实；纠错用补偿事件而不是修改历史。Kafka 课程第 22 课有完整的动手练习。
  6. DataFrame、矩阵与数组：数据科学与机器学习常用的模型（pandas、Spark DataFrame），按行列操作，适合把关系数据转成特征矩阵；多维数组用于科学计算与地理数据。
