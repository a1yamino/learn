03
保存为 mr.py：用 Python 模拟 MapReduce（map → 按键分区并排序 → reduce）。
from collections import defaultdict
from itertools import groupby
lines = open("access.log").read().splitlines()

def mapper(line):                       # 输入一行，输出若干 (键, 值)
    parts = line.split()
    yield parts[6], int(parts[9])       # (URL, 字节数)

def reducer(url, values):               # 同一个键的所有值
    vs = list(values); yield url, len(vs), sum(vs) // len(vs)

R = 3                                   # 3 个 reducer
partitions = defaultdict(list)          # shuffle：按键哈希分区，再按键排序
for line in lines:
    for k, v in mapper(line):
        partitions[sum(map(ord, k)) % R].append((k, v))
for r in range(R):
    part = sorted(partitions[r])
    for k, group in groupby(part, key=lambda kv: kv[0]):
        for url, n, avg in reducer(k, (v for _, v in group)):
            print(f"reducer {r}: {url:<12} 请求 {n:6}  平均 {avg} 字节")

import duckdb
print(duckdb.sql("""
  WITH logs AS (
    SELECT split_part(column0, ' ', 1) AS ip, split_part(column0, ' ', 7) AS url
    FROM read_csv('access.log', delim='\t', header=false, columns={'column0': 'VARCHAR'}))
  SELECT u.team, count(*) AS n
  FROM logs l JOIN 'users.csv' u
    ON regexp_replace(l.ip, '\\.[0-9]+$', '') = u.subnet
  GROUP BY u.team ORDER BY n DESC
"""))

挑战
设计一个每日推荐结果的批处理流水线
输入：对象存储上的用户行为日志（每天 2 TB，Parquet）、商品表（PostgreSQL，500 万行）、用户表（2 亿行）。输出：每个用户的前 50 个推荐商品，供线上接口按 user_id 读取（p99 < 10 ms）。请设计：① 数据如何进入批处理；② 主要的连接与聚合步骤及连接算法；③ 结果如何交付给线上服务；④ 作业失败或结果错误时如何处理。
查看参考答案
  1. 商品表、用户表每天通过 CDC 或快照导出为对象存储上的 Parquet（Iceberg 表），与行为日志放在同一处；批处理只读这些不可变的输入。
  2. 行为日志 ⋈ 商品表：商品表约几 GB，广播哈希连接，大表无需洗牌；按 user_id 聚合用户画像需要洗牌（按 user_id 分区）；用户特征 ⋈ 用户表：两边都很大，按 user_id 做排序—合并或分区哈希连接（若两表已按相同方式分桶则无需洗牌）；热门商品/超级用户可能倾斜，开启倾斜连接优化。候选召回与打分可调用批量推理。
  3. 作业输出按 user_id 分区的键值文件（例如 RocksDB SST、或线上 KV 存储支持的批量导入格式），写到新的版本目录；校验通过后原子切换线上服务读取的版本指针。不要逐条 PUT 到线上库。
  4. 输入不可变、作业确定性，失败就整体重跑；结果错误时把指针切回前一天的版本，修复代码后重跑。保留最近几个版本。用工作流编排器管理依赖与重试，输出数据质量检查（行数、空值率、与昨天的分布差异）作为切换前的关卡。

小结
记住这几点


  1. Unix 哲学：cat log | awk | sort | uniq -c | sort -rn | head 几秒钟就能分析几 GB 日志。要点：每个程序只做一件事；统一的接口（文本行）使得程序可以任意组合；输入不可变，可以反复试验；sort 会自动把放不下内存的数据溢写到磁盘并归并——排序比内存中的哈希聚合更能扩展到大数据。
  2. 分布式存储：HDFS 等分布式文件系统把文件切块、复制到多台机器；今天更常见的是对象存储（S3、GCS、OSS）——存储与计算分离（第 1 课），按对象（而不是目录）组织，不支持原地修改，重命名不是原子的。列式格式（Parquet）加上表格式（Iceberg、Delta Lake）在对象存储之上提供了模式、事务与时间旅行。作业编排：调度器（YARN、Kubernetes）分配资源；工作流编排器（Airflow、Dagster）管理作业之间的依赖。
  3. MapReduce：① map——对每条输入记录调用，输出若干键值对；② shuffle——按键的哈希把键值对分配到各个 reducer，并按键排序；③ reduce——对每个键的所有值调用一次，输出结果。复杂任务由多个 MapReduce 作业串联，中间结果写入分布式存储。容错很简单：任务失败就在另一台机器上重跑，因为输入不变、输出由框架原子地提交。
  4. 数据流引擎（Spark、Flink、Tez）：把整个工作流看作一个算子图，不必把每一步的中间结果写入分布式存储；只在需要时排序；算子之间可以流水线执行，尽量利用内存与数据局部性。失败时根据血缘（lineage）重新计算丢失的分区，或从检查点恢复——这要求算子是确定性的。
  5. 连接与分组：排序—合并连接——两个输入都按连接键分区并排序，同一个键的记录到达同一个 reducer（“把相关的数据带到同一个地方”）；广播哈希连接——一个输入很小时，把它整体发给每个 map 任务放进内存哈希表，大输入不必洗牌；分区哈希连接——两个输入已按相同方式分区时，各分区独立连接。倾斜：热点键（名人）的数据集中到一个 reducer，需要对热点键特殊处理（拆分并复制另一侧）。
  6. 接口与用途：今天大部分批处理用 SQL（Spark SQL、Trino、云数据仓库）或 DataFrame（pandas、Polars、Spark）编写，由优化器选择连接算法。用途：ETL（从业务系统抽取、清洗、加载到仓库）、分析、机器学习（特征工程、训练、批量推理）、生成供线上服务读取的派生数据（搜索索引、推荐结果、键值存储）——不要从批处理作业里逐条写线上数据库，而是在作业中构建全新的数据文件，再原子地切换（批量导入），出错时切回旧版本即可。
